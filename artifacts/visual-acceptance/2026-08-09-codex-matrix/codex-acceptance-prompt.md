### 二、被验收的改版内容（一句话背景）

本次改版把对话界面从"无框裸行"改为 **OpenAI Codex 桌面应用式审美**：细边框圆角折叠卡片承载

### 三、逐项验收点（浅色/深色各查一遍；任何一项违反即记入 Findings）

**A. 对话区卡片基线（最高优先级）**
- A1 无横贯对话区的全宽水平分隔线：对话流内不得出现通栏横线把用户消息/工作组/正文切开。
- A2 Agent 工作过程（思考/工具/计划）是**细边框圆角折叠卡片**：收起时一行（状态 + 耗时），
  展开时显示明细。边框是发丝细线、低存在感；**禁止**彩色边框、大面积底色、粗描边。
- A3 活动记录是**整组一张卡片**：展开的工作组里，思考行/工具行/计划行是平级的细行，
  **禁止每条活动行各包一张重复卡片**（卡片套卡片 = FAIL）。
- A4 工作组收起态 = 终态：完成后的工作组自动折叠成一行"状态 + 耗时"（如「已完成思考 · 工作了
  N 秒」），点击可展开；正文不受卡片包裹。
- A5 用户消息：右侧紧凑中性气泡，无头像、无署名行。

**B. 状态条 / 压缩条**
- B1 运行状态是**紧凑小条**：小圆点（约 6px）+ 状态文字 + 右侧停止/重试按钮，与对话同列，
  不是全宽横条。
- B2 状态点**静态**：运行中为绿色系/accent 色、终态为灰色；**状态点不得有闪烁/脉冲动画**
  （活性动效只能存在于当前活动工作项的文字扫光上，两者不可同时出现）。
- B3 压缩条（若可见）：细边框圆角紧凑条，不是全宽分隔线；文案为「开始压缩/压缩进行中/
  已压缩完成/压缩失败」等中文短句。

**C. composer / 顶栏 / 侧栏**
- C1 composer 是**细边框圆角卡片 + 轻阴影**（浅色下白底、深色下炭灰底），与对话内容同列宽
  （居中）；不是透明长条、不是无边界输入框。
- C2 顶栏：发丝下边框（极浅细线）；顶栏按钮是图标型、默认融入背景，**不是一排常驻描边胶囊**。
- C3 侧栏项目行：紧凑行、圆角、当前项目仅以浅背景/字重区分；「新建」是行式入口，不是实心大按钮。
- C4 圆角纪律：卡片/控件圆角 ≤12px；不得出现 13–98px 的怪异圆角（99px/999px 的圆形
  pill、圆环、头像除外）。

**D. 正文神圣与文字层级**
- D1 Assistant 小说正文（段落 `<p>` 与正文文本）：**衬线**（宋体系：Source Han Serif SC /
  Noto Serif SC / Songti SC / STSong / SimSun）、15px、行高 ≥2.0、无框直出、**不包卡片**、
  不与其他 UI 元素混排。
- D1 判图注意（防误判）：正文**段落**是宋体系衬线。内容区 **H1/H2 按全局 chrome 规则使用
  无衬线**（设计事实，不是缺陷）；H3–H6 与正文同为衬线；代码块为等宽字体。判定衬线/黑体
  时请放大文字区域观察笔画末端：衬线字有三角衬线、横细竖粗特征；勿仅凭整体观感。
- D2 UI 文字无衬线（系统黑体系）；muted 辅助文字（耗时/路径/说明）清晰可读，不得淡到费眼。
- D3 标题层级：H1/H2 以深色/浅色高对比、字号、字重建立层级，**不得大面积染 accent/green**；
  H3–H6 明显低于 H1/H2。当前冻结契约（规格 §2.6，测试冻结，改字级属产品决策）：
  H1=20px/700、H2=17px/700+细分隔线、H3=15px/650、H4–H6=14px/650。若你判断层级不足，
  请以 P2 低严重级报告并建议，不要判 FAIL。
- D4 状态色边界：完成绿/失败红**只用于 icon 或短状态词**；工具名、路径、说明、整段回答
  不得整体染色。标题/正文/计划行出现大面积 accent/green/red = FAIL。
- D5 任务计划（若可见）：只有「任务计划」标题与唯一当前项（in_progress）加粗；
  已完成项无删除线、不整行变绿（仅勾选 icon 为绿）。

**E. 动效唯一性（必须交叉 t000/t400/t900 三帧判断，不能只看单张）**
- E1 顺序场景（reasoning-running / tool-after-reasoning）任何一帧：**同一时刻最多一个活性
  动效目标**——可见扫光文字数量 ≤1；不得同时看到「思考中」和工具文字都在扫光；
  展开工作组时外层状态不得同时扫光。
- E2 终态场景（conversation-completed / markdown-fixture / settings / drawer /
  plain-folder）：**不得残留任何循环动画/扫光**，可见动效数 =0。
- E3 扫光方向：reasoning-running 三帧（t000<t400<t900）与 tool-after-reasoning 三帧中，
  扫光亮带必须从左向右移动；文字本身不位移、容器不跳动。（浅色扫光带是深色 ink 带；
  深色扫光带是浅色亮带——方向判断标准一致。）
- E4 状态点、圆环、完成标记不得有循环动画。

**F. 布局与视口（浅/深各四视口逐张查）**
- F1 conversation-completed 覆盖 390x844 / 768x900 / 1280x800 / 1440x900 四个视口，
  逐张检查：无横向溢出、无遮挡、无截字、无控件碰撞、无不合理留白。
- F2 窄视口（390x844）下 composer 菜单宽度不超出视口，排队行不遮按钮，Markdown 表格在
  容器内滚动而页面不横向溢出。
- F3 顶栏/侧栏在窄视口（390/768）仍可用：抽屉/设置入口退化为图标不截字。

**G. 中文与文案契约（改版不得破坏）**
- G1 全中文界面：不得出现英文状态词（running/completed/failed 等）、不得出现
  `Worked for`、不得出现乱码/孤立 Unicode。
- G2 工作过程文案必须是中文短句：「思考中」「已完成思考」「正在调用 read_skill」
  「正在读取文件」「工作中」「工作了 N 秒」等。
- G3 完成态/折叠态不得出现签名行、时间戳、token 明细等非契约信息。

**H. 深色主题专项（本验收新增，逐张对照深色矩阵）**
- H1 深色画布为中性炭灰（近黑但非纯黑，#16181a 系），卡片表面为 #1d2023 系炭灰：
  **不得残留浅色组件**（任何大块纯白/浅灰面板、白卡片 = FAIL）；也不得是死黑一片失去层级。
- H2 文字为浅色（#eef2ef 系），正文/UI 在炭灰上清晰可读；muted 辅助文字（#a8b1ab）
  可读不费眼，对比度语义 ≥4.5:1。
- H3 发丝线边框在深色下**仍清晰可见**：卡片与背景、顶栏与内容区之间有可辨边界，
  不得糊成一体（也禁止过亮刺眼的粗白线）。
- H4 composer 深色下是**炭灰卡片**（surface 系），不得仍是白卡；轻阴影在深色下保持克制。
- H5 状态点/圆环深色下可区分：运行中 accent 绿（#8fb08f）、终态灰，语义与浅色一致。
- H6 错误红（#d0866f）/琥珀（#c8a45c）在深色下保持语义可辨，不刺眼、不浑浊。
- H7 顶栏/侧栏深色下不发白、不刺眼；「新建」「面板」等入口的 hover/active 反馈清晰。
- H8 深色下工作组展开/收起、折叠态卡片与浅色同构（细边框、一行状态+耗时），仅色彩反转。

**I. 已知覆盖边界（本次矩阵未覆盖，不得据此判 FAIL，但应在报告中列出）**
- I1 **错误/重试场景未拍**：琥珀自动重试行、红色错误卡（4xx 不重试）不在本矩阵；
  若需验收请在报告中列为建议补拍项。
- I2 截图是静态帧：动画类结论必须用 reasoning-running/tool-after-reasoning 的
  t000/t400/t900 三帧交叉对比 + audit JSON 佐证，禁止单帧臆断。
