# WWriting 小说智能体使用教程

这份教程面向本地使用者和后续开发者，说明如何启动桌面端、打开项目、配置模型、通过对话面写作、使用资料工具、运行验证和重新打包。

## 1. 安装与启动

在项目根目录执行（将 `你的项目路径` 替换为实际克隆/存放目录）：

```powershell
cd 你的项目路径
npm install
```

浏览器预览：

```powershell
npm run app:shell
```

Electron 桌面端：

```powershell
npm run desktop:electron
```

开发阶段推荐先用 `npm run desktop:electron`。它会直接读取当前源码，所以源码里的 UI、菜单和逻辑变更能立即看到。

## 2. 打开一个工作区

桌面端左侧是作品栏。

操作步骤：

1. 点击"打开本地文件夹"。
2. 选择**任意一个存在且可访问的文件夹**（空目录、普通资料目录、旧 WWriting 项目都可以）。
3. 打开后，中间区域就是对话面，可以直接发送第一条消息；不需要 `project.yaml`、不需要初始化表单。

浏览器预览没有系统文件夹选择器，可以直接在"项目路径"输入框中粘贴路径。

**文件夹就是工作区**，`project.yaml`、`WWRITING.md`、总纲和章节目录都不是聊天资格条件。长期写作项目的根目录可能会包含：

```text
WWRITING.md              # 项目记忆入口（可查看、可手工编辑）
chapters/                # 最终章节文件
drafts/                  # 草稿和规划文件
memory/                  # 章节索引与摘要
sources/                 # 资料快照
skills/                  # 项目技能
```

应用私有历史（会话、事件、检查点）写入应用数据目录的 `workspaces/<workspace-id>/`，**不会出现在你的创作文件夹里**。旧版本项目里的 `agent_state.json`、`task_queue.json` 等文件会在首次打开时被一次性只读迁移，之后不再写入；迁移只做一次，重复打开不重复处理，原文件保留不删。

## 3. 认识界面

界面分为几个主要区域。

| 区域 | 你能做什么 |
|---|---|
| 左侧作品栏 | 搜索、打开或切换自己的工作区，并管理项目下的对话。 |
| 中央对话面 | **唯一的写作入口**：聊天、写作、审核、初始化都在这里发起；当前这一轮模型在做什么（思考中、读取文件、运行命令、等待确认）以工作组条目呈现、实时可见。 |
| 设置 | 配置模型、写作参数、权限档位、联网搜索、归档等；"Agent 技能"分区可查看内置写作风格。 |
| 项目面板抽屉 | 顶部"面板"按钮打开，在需要时查看章节、模型、资料和成本；它们只展示项目事实，不打断日常写作。 |
| 章节阅读器 | 打开已定稿章节阅读，支持字号调节、翻章和沉浸模式。 |

## 4. 使用对话面写作

写作不需要点任何"开始写作"按钮：**打开项目后直接输入你想做的事**，模型会自主决定读取哪些文件、调用哪些工具、修改哪些内容。

### 4.1 打开工作区与开始写作

打开应用后，左侧作品栏提供入口：

- **打开本地文件夹**：选择任意存在且可访问的文件夹（空目录、普通资料目录、旧 WWriting 项目都可以），打开后直接恢复上次状态或开始新会话。
- **新建小说**：点击后打开创建表单，填写小说名、一句话大纲、目标章节数和每章最低字数，确认后自动创建项目并打开（适用于从零开始的完整长篇项目）。

打开后即可开始对话，不需要任何前置准备步骤。普通文件夹不需要初始化表单——想长期写下去时，可以让模型运行 `/init` 建立 `WWRITING.md` 项目记忆。

在输入框键入 `/` 会出现常用命令。继续输入可筛选，使用上下键选择，按 Enter 或 Tab 补全；也可以直接点击。补全只会把命令填入输入框，不会立刻执行。`/init`、`/write` 会像普通消息一样交给 Agent；`/model`、`/settings` 用于打开本地设置。

消息发送后会立即出现在对话中。若提交失败，原文字会恢复到输入框，并显示简短错误，方便直接重试。

### 4.2 会话（Session）与执行（Run）

- **Session（会话）**：一个工作区对应一条持续的会话。对话历史会跨重启保留，重新打开同一路径后还能接着聊。
- **Run（执行）**：每发送一条消息，就启动一次执行。模型循环、工具调用、任务计划都属于当前这次 Run；Run 结束后工作组显示结果（工作了 N 秒 / 失败 / 已停止）。

模型执行期间，当前这一轮会显示：

- **工作组**：思考、工具调用与任务计划按发生顺序合并为一个时间线组，标题显示 `工作中`。Run 结束后：**完成自动折叠**（点击可展开回看），**失败/停止/中断保持展开**。
- **思考项（已完成思考）**：每轮模型调用对应一个独立的 `已完成思考` 项，与工具动作严格按发生顺序排列。展开时的文案分三种：
  - 模型支持且本轮有内容 → 显示思考全文；
  - 模型明确不支持查看思考内容 → 显示 `当前模型不支持查看`；
  - 支持但本轮没有可查看的内容 → 显示 `本次没有可查看的思考内容`。
  思考内容只写入本地日志，**不会注入下一轮模型上下文，也不会混入正文**。
- **任务计划（Visible Plan）**：复杂任务开始时模型会给出分步计划，随执行逐项标记完成；更新时同一计划项只保留一个、内容更新并移动到最新时间点；Run 结束后折叠，可展开回看。
- **工作组工具条目**：每一次工具调用（读取文件、修改文件、运行命令、提交章节等）以工作组里的条目呈现，点击可展开查看参数、命令、退出码、耗时和输出；运行中的条目持续显示新增输出。

**耗时口径**：工作组显示的耗时是**有效工作耗时**——等待你确认授权的时间不计入。Run 结束后给出最终值（如 `工作了 12 秒`）。

### 4.3 排队、立即与停止

- 模型正在执行时发送新消息，消息进入 **FIFO 队列**：显示原文 + `排队` 标记。
- 点击 `立即`：打断当前这轮，把排队消息提升为活动输入（同一个 Run 内切换输入，**不会创建第二个项目 Agent**）。
- 点击 `停止`：取消当前 Run，已写入的文件保持完整，排队消息一并清理；临时授权（见 5.2）随之清除。

### 4.4 跨工作区并行

每个工作区有独立的会话和队列。在左侧切换工作区不会打断另一个工作区的执行——不同工作区可以并行运行，互不干扰。

### 4.5 完成与阅读

Run 结束后，工作组显示"工作了 N 秒"。已定稿的章节会出现在左侧"项目面板 → 章节"里，点击即可打开应用内阅读器：

- 显示干净正文（无标记和标题编号）。
- 支持字号调节（A− / A+，档位会记住）、翻章（箭头键或点击左右）和"沉浸"宽屏模式。

> 完成与提交的客观事实来自本地文件与工具结果（文件存在、校验和匹配、写入成功），而不是模型在对话中说"写完了"；字数是模型可选的客观参考，不是完成门禁。

### 4.6 确定性导出

在"项目面板 → 章节"点击"导出成书"：应用直接读取本地文件导出成书（txt 格式），**不经过模型、不产生额外成本**。导出完成后会提示文件位置和字数，桌面端还可一键"打开导出文件夹"。

### 4.7 安全 Markdown 渲染

Agent 的正文回复支持安全 GFM（GitHub Flavored Markdown）：表格、任务列表（勾选框）、链接、删除线、行内代码、围栏代码块、引用和标题都正常排版。为安全起见：

- 原始 HTML（如 `<script>`）一律按纯文本显示，不会执行。
- 链接只放行 `http:` / `https:`；`javascript:`、`data:`、`file:` 等危险 URL 不会生成可点击链接。
- 图片不从网络加载，只显示替代文字。

## 5. /init 与权限

### 5.1 /init 是一条普通聊天请求

- `/init` 是一条普通聊天请求，可以在写作的任何阶段使用。
- `/init` 负责创建或谨慎更新项目根的 `WWRITING.md`（项目记忆入口），**不生成固定蓝图**、不要求预先填写题材或章节数。
- 已有的 `OUTLINE.md`、`SETTING.md`、`AGENTS.md` 只作为普通权威文件被索引，不强制存在；缺少 `WWRITING.md`、总纲或章节不影响聊天、读取与普通文件编辑。
- 你可以给 `/init` 追加自然语言要求，例如"按快节奏易读的风格建立项目记忆"。

`/init` 与其他写作指令走完全相同的对话流程：你可以看到模型在读取什么、运行什么命令、修改什么文件，最后它会报告检查了什么、创建或更新了什么、哪些内容无需修改。

### 5.2 权限档位

设置 → 权限与确认，四档单选：

| 档位 | 行为 |
|---|---|
| 只读 | 模型不修改任何文件。 |
| 确认后修改（默认） | 正常模式：自动执行项目读取；写入、删除、联网、启动程序等副作用操作前先询问。 |
| 自动修改 | 可静默改稿；归档/导出仍需确认。 |
| YOLO | 跳过普通确认，并允许访问项目以外的目录。 |

要点：

- 正常模式自动执行项目读取，产生副作用前会先询问。
- 同类授权只对当前这条排队输入生效（确认卡上的"本条输入允许同类操作"）；下次输入需要重新确认，Run 结束或切换项目后临时授权自动失效。
- YOLO 跳过普通确认，并允许访问项目以外的目录。
- 极端危险操作（可能破坏磁盘、系统或大范围用户数据）始终要求输入当前给出的精确确认文字，模型与 YOLO 都不能代填；确认文字每次都会变化，不能复用上一次的。
- 归档后的项目只读；归档与解除归档在"危险区"操作。

### 5.3 写入与删除的确认

普通模式下的写入、覆盖、删除、安装、联网、启动程序等操作会弹出确认卡：

- 文件修改展示增删差异；新建展示目标与主要内容；删除展示完整目标列表；命令展示完整命令、运行目录和用途。
- 选项：`一次允许`（只放行这一次）、`本条输入允许同类操作`（放行当前这条排队输入内的同类操作）、`拒绝`。
- 极端危险操作使用红色确认卡，必须输入界面给出的精确确认文字才能执行。

## 6. 配置模型

在设置端进入「模型设置」（也可在对话模型选择器点击 `/model`，或点击聊天框「未配置」占位直达）。页面是「左供应商列表 + 右详情」的两级界面：供应商（连接信息）在上，其下的模型列表在下。

### 6.1 供应商

- 应用内置两个官方预设：**DeepSeek 官方** 与 **小米 MiMo 官方**，首次启动自动写入清单；预设可改名、可删除，删除后重启不会复活。
- 「+ 添加供应商」创建自定义供应商，必填：名称、Base URL（须以 `http://` 或 `https://` 开头）、API 密钥环境变量名（只能由字母、数字、下划线组成且不能以数字开头）。
- 供应商名失焦即保存；「禁用/启用」切换供应商状态，列表状态点随之切换；删除需二次确认，文案提示会**连带删除其下全部模型**。
- 供应商被禁用后，其全部模型都不可被选用（对话模型选择器只显示启用的供应商与模型）。

### 6.2 连接信息

- **Base URL**：失焦保存，校验 `http(s)` 前缀；OpenAI-compatible 默认请求 `Base URL + /chat/completions`。
- **API 接口协议**：下拉 4 项（OpenAI Chat Completions / Anthropic Messages / OpenAI Responses API / Gemini Native generateContent），当前仅第一项可用，后 3 项灰色不可选。
- **API 密钥**：两种填法——直接粘贴明文密钥（保存后写入本机应用级 secrets，输入框掩码，可点眼睛临时查看、切换后不再回显）；或填写环境变量名（如 `DEEPSEEK_API_KEY`，应用读取该 Windows 环境变量）。项目文件只保存环境变量名，**绝不保存密钥值**。

### 6.3 模型管理

每个供应商下列出模型，支持：

- 增删模型：改名失焦保存；删除需二次确认。
- 启停开关：停用的模型不能设为默认，也不能被项目选用。
- 「设为默认」：把某模型设为全局默认，默认模型行带「默认」角标。
- 「测试连接」：对当前供应商+模型发起连通性测试，结果行内显示在条目旁（成功绿勾 / 失败红字；超时提示「模型服务器响应超时（30 秒）」）。
- 「拉取模型」：向厂商查询可用模型名（未配置密钥时先提示、不发请求）；候选展开后可逐条添加，厂商返回的 100 个模型不会自动全部导入。

### 6.4 默认模型与停用语义

- 新建项目默认使用「默认模型」；删除默认模型后新建项目，聊天框显示「未配置」，点击会打开模型选择器。
- 项目正在使用的模型被删除或停用：打开项目时提示「已换成默认模型 XX」，项目照常能写。
- 旧项目（含此前 Mock 配置）首次打开自动升级：Mock 归零为未配置，弹「旧配置已升级」。

### 6.5 模型名标记

模型名尾部的 `[1m]` 标记（如 `deepseek-v4-pro[1m]`）表示该模型上下文窗口为 1M token：设置页显示时原样保留，实际发送请求时由应用剥离（发送给厂商的模型名不含该标记）；未带标记的模型默认按 256k 上下文窗口处理。

### 6.6 运行时参数

模型运行参数（`timeout_ms` 空闲超时，默认 300 秒；`total_deadline_ms` 总期限，默认 900 秒）是模型条目的属性，保存在应用私有清单 `model-profiles.json` 对应模型条目中（设置页暂未暴露编辑入口，可直接编辑该文件）；长章节写作建议 `total_deadline_ms: 1800000`（30 分钟）。

## 7. 使用联网搜索与网页抓取

联网默认关闭。需要使用资料工具时：

1. 在右侧设置端勾选"允许联网"。
2. 如需搜索，在"联网搜索"分区登记搜索接口地址与密钥变量名。
3. 打开"项目面板 → 资料"。
4. 输入关键词并点击"搜索"，或输入 URL 并点击"抓取"。

搜索接口可以是通用 JSON API。验证脚本中使用过的公开示例：

```powershell
$env:WWRITING_SEARCH_ENDPOINT="https://hn.algolia.com/api/v1/search"
$env:WWRITING_SEARCH_QUERY_PARAM="query"
$env:WWRITING_SEARCH_LIMIT_PARAM="hitsPerPage"
$env:WWRITING_SEARCH_RESULTS_PATH="hits"
```

网页抓取结果会进入：

```text
sources/
sources.md
source_summaries.md
```

所有外部来源都会被标记为不可信资料。网页内容不会直接变成系统指令。

## 8. 技能管理

技能用于扩展写作流程，例如风格控制、检查项或后处理。技能由一个目录里的 `SKILL.md` 文件声明，**放入目录即被发现，不需要在项目中启用**：

```text
全局技能：%USERPROFILE%\.wwriting\skills\<skill-name>\SKILL.md
项目技能：<projectRoot>\skills\<skill-name>\SKILL.md
同名覆盖：项目 > 全局 > 随应用分发 > 内置
放入目录即被发现；适用条件写在 SKILL.md，不需要在项目中启用。
```

**三个内置写作风格**（随应用分发，只读、不可删除/覆盖/直接编辑）：

| 显示名 | 技能 ID | 目标 |
|---|---|---|
| 均衡 | `balanced` | 情节、人物、描写和可读性保持均衡 |
| 快节奏易读 | `fast-readable` | 推进迅速、信息清楚、冲突直接、阅读负担低 |
| 心理文学 | `psychological-literary` | 加强人物动机、心理变化和潜台词，同时保持大众网文可读性 |

- 风格通过**自然语言指定**（"按快节奏易读的风格写"）或**由模型根据题材、目标读者、节奏和描述判断**选择；题材不与风格机械绑定。
- 确定风格后，模型把稳定技能 ID 写入 `WWRITING.md`，并在真正生成、续写、改写、润色或审核小说正文前通过 `read_skill` 读取完整技能正文（渐进加载，不常驻系统提示词）。
- 技能正文只影响小说正文，不改变普通聊天、问题澄清或工具结果汇报的语气。
- 设置 → Agent 技能 分区可以查看三个内置风格（只读详情）和管理项目/全局自定义技能；技能系统**没有启用/禁用开关**。

项目技能目录仍可发现普通 `SKILL.md`；旧的 reviewing 等 hook 元数据保留在文件中但运行时忽略，不会变成自动审稿门禁。

## 9. 章节生成的核心规则

WWriting 的核心原则是"应用负责连续完成，模型负责当前小步骤"。

章节写入的客观事实来自本地工具结果：

- 正式章节文件存在。
- 写入路径在工作区内、校验和匹配、写入原子完成。
- `run_log.jsonl` 有完成事件（旧项目兼容）。

**字数不是完成门禁**：用户有明确字数要求时，模型可以调用 `count_text` 获取真实字数，再自行判断补写、删减或结束；未调用、未达标都不会被拒绝提交。文笔、节奏、人物塑造等质量判断由模型负责，不设确定性判分。

如果模型把正文直接发到聊天回复，而不是请求工具写入文件，系统会把它视为错误输出通道。

## 10. 常用验证流程

开发或修改 UI 后：

```powershell
node --check src/app-shell/app.js
npm run verify:app-shell
npm run verify:desktop-shell
npm run verify:electron-runtime
```

修改核心引擎或项目存储后：

```powershell
npm test
npm run verify:app-shell
```

准备本地完整交付前：

```powershell
npm run verify:local
```

## 14. 常见问题

### 左上角菜单还是英文

源码已经通过 Electron 主进程接管原生菜单。如果你运行的是旧的打包 exe，需要重新执行：

```powershell
npm run package:dir
```

然后再从目录包或桌面快捷方式启动。

### 打开文件夹失败

任意存在且可访问的文件夹都可以打开。若目标目录不存在、无权限或路径为空，界面会给出简短中文提示。普通资料目录不会因为缺少 `project.yaml` 而被拒绝——任何文件夹都可以直接聊天。

### 搜索或抓取失败

检查三件事：

- 设置端是否开启"允许联网"。
- 搜索接口地址是否是 `http` 或 `https`。
- 搜索密钥是否只填环境变量名，而不是明文 key。

### 模型调用失败

检查：

- `base_url` 是否正确。
- `model_name` 是否是供应商支持的模型。
- `api_key_env` 是否对应当前本机已保存的密钥。
- 当前项目预算是否耗尽。

### 章节字数不够

这是模型自主判断的范畴。模型可以在有明确字数要求时调用 `count_text` 获取真实字数，再自行决定补写或结束；应用不会因字数不足拒绝文件写入或提交，也不会显示"未达标"警告。错误只呈现一条事实，技术细节在工作组条目的折叠详情里。

## 15. 开发注意事项

- 不要把 `node_modules/`、`.demo_runs/`、`dist-desktop/` 提交到仓库。
- 不要把真实 API key 写入项目文件。
- 不要绕过 `safeJoin` 直接拼接项目内部路径。
- 不要让网页内容进入系统提示层。
- 不要把模型聊天正文当成章节交付。
- 修改 Electron 主进程后，至少运行 `npm run verify:desktop-shell` 和 `npm run verify:electron-runtime`。
- 修改 app shell 后，至少运行 `npm run verify:app-shell`。

## 16. 技能系统（自定义扩展）

### 16.1 自定义技能

技能就是一个包含 `SKILL.md` 的目录，放入固定目录即被发现：

```text
全局技能：%USERPROFILE%\.wwriting\skills\<skill-name>\SKILL.md
项目技能：<projectRoot>\skills\<skill-name>\SKILL.md
同名覆盖：项目 > 全局 > 随应用分发 > 内置
放入目录即被发现；适用条件写在 SKILL.md，不需要在项目中启用。
```

`SKILL.md` 以 YAML frontmatter 声明名称与说明（`name` 必须与目录名一致），正文写指令：

```markdown
---
name: my-style
description: 我的写作风格
version: 1.0.0
---

正文作为 prompt 片段：写作时要求……（例如"对话多用短句与具体动作"）。
```

适用条件（如检查项、章节号范围）写在 frontmatter 的 `metadata.wwriting.hooks` 或正文小节（`## Review checklist`、`## Post-process` 等）里；运行时只读取这些内容供模型按需参考，旧的 `stage: reviewing` 元数据不会被程序化执行。同名的项目技能覆盖全局与内置版本；设置 → Agent 技能分区会列出目录里的全部技能、当前生效来源，并支持文件夹/ZIP 导入、覆盖确认与删除。

### 16.2 自定义输出风格

在 `~/.wwriting/output-styles/my-style.md` 写：

```markdown
---
name: My Style
description: 我的写作风格
---
正文作为 prompt 片段，追加到 system prompt 末尾。
```

在设置面板的"输出风格"下拉里选它。Bundled 默认提供 `creative`（创作）风格；独立审稿输出风格已随程序化审稿一并移除，审核通过普通对话的自然语言指令完成。

## 17. 对话体验速览

- **一个对话面**：写作、审核、初始化、提问都在同一个输入框发起；不存在独立的"开始写作"入口或准备卡片。
- **过程可见**：当前这一轮以工作组条目的形式实时显示模型状态（思考中 / 读取文件 / 运行命令 / 等待确认）；每个工具动作完成即出现在工作组里。
- **工作组与思考**：思考、工具、任务计划按发生顺序组成工作组（完成自动折叠、失败/停止保持展开）；每轮模型调用一个独立的 `已完成思考`，展开可看思考全文或明确的两类空文案；耗时只计有效工作，排除等待授权。
- **随时停止**：当前轮运行区有「停止」按钮，可取消本次 Run；进行中的文件写入保持完整，不会留半截。
- **排队与立即**：运行中发送的消息显示原文 + `排队`，点「立即」打断当前轮并优先执行，不创建第二个 Agent。
- **任务计划**：复杂任务显示 Visible Plan，逐项更新完成状态，结束后折叠可回看。
- **修改确认**：确认卡展示差异与用途；同类授权只对当前这条排队输入生效。
- **简洁文案**：状态与错误文案保持简短；错误只呈现一条事实，错误码、命令、退出码在工作组条目的折叠详情里。
- **阅读器**：A− / A＋ 调字号（档位会记住）、‹ › 或 ← / → 翻章、「沉浸」加宽视图。
- **快捷键**：按 `?` 查看全部快捷键。
