# ADR 0009：路径身份以真实项目根为准，且在比较点就地解析

日期：2026-09-25 ｜ 状态：已采纳（第二十一轮）

## 背景

2026-09-25 只读健壮性抽查复核发现一处不对称：`tools/index.mjs` 在每次工具调用前对**目标路径**做 `resolveFilesystemPath`（解析 junction / symlink 后的真实位置），但**项目根从未解析**——全仓 `grep realpath src/` 只命中 `fs-utils.mjs:31`（即 `resolveFilesystemPath` 自身）与 `skills/*`（那是做对了的样板）。

后果：项目根路径中任意一段是目录链接时，以根为基准的包含性/相等比较全部落空。受影响的不止一个点，而是同一批：

| 比较点 | 失效方向 |
|--------|----------|
| `runtime-helpers.mjs:228` 受保护路径（8 条规则） | fail-open：`memory/`、`.versions/`、`run_log.jsonl`、`project.yaml`、`checkpoints/`、`.wwriting/`、章节索引、草稿的直写保护整体失效 |
| `runtime-helpers.mjs:287` `safe_edit=false` 内容保护 | fail-open：章节/设定/记忆路径不再被识别 |
| `runtime-helpers.mjs:271` shell cwd 信号 | fail-open：可在日志/检查点目录内运行命令 |
| `runtime-helpers.mjs:351` 工作区文本读取 | **fail-closed**：项目内合法文件被误判「工作区外」而拒绝 |
| `risk.mjs:79` scope 判定 | 项目内写入被判「项目外」，正常写作每次弹确认 |

第四条与第五条是**这个缺陷不是有意保守**的证据：同一处不对称同时产生了「该保护没保护」和「该放行没放行」两种症状。

触发场景：Windows 下 `mklink /J`（junction）或项目位于被重定向的目录下；macOS 下 `/tmp`、`/var` 本身就是链接，临时目录下的项目必然命中。本产品当前只发 Windows 安装包（`electron-builder --win nsis`），故现实触发面是前者。

## 决定

1. **基准**：凡判断「这个文件属不属于当前项目」「这个写入要不要保护」的地方，一律以**真实项目根**（`resolveFilesystemPath(projectRoot)`）为基准。
2. **落点**：解析在**比较点就地**进行——每次工具调用在既有的路径归一化处解析一次并放进工具上下文，**不缓存、不在项目打开时改写注册表中的路径**。
3. **失败方向**：解析本身失败（权限错、目录瞬间不可访问、`ENOTDIR` 等）即**拒绝该次工具调用**（fail-closed），给可行动中文文案；绝不退回未解析的根。
4. **同源**：scope 判定（项目内 / 项目外）与受保护路径判定使用同一份真实项目根，不保留「保护失效但有确认兜底」的双口径。
5. **不在本轮**：项目身份层（打开路径、选中态、最近项目列表的比较）、路径比较的大小写口径、shell 写目标承诺的扩大（分别登记为欠账 21-2 / 21-1 / 21-4）。

## 考虑过的选项

- **在记录项目根时就归一**（进项目即把注册表写成真实路径）：拒绝。解析结果随时间可变（目录可能是事后建的链接），一次性归一让「打开时」与「使用时」的真相可能不同；且会改动注册表与界面显示的路径，波及面远超本问题本身。
- **两处都做**（记录时归一 + 比较点兜底）：拒绝。两套口径必须严丝合缝才安全，一旦不一致更难排查，收益低于成本。
- **只改受保护判定、scope 判定继续用原根**：拒绝。会长期维持两套口径，且 junction 项目的正常写入永远弹「项目外」确认；而保护判定既已正确，那道歪打正着的弹窗兜底不再必要。

## 后果

- **用户可见变化**（只在 CHANGELOG 记一条，不另做界面提示）：junction 项目的项目内写入不再弹「项目外」确认；既有授权键（形如 `write:outside:<盘符>`）失效一次、需重新确认；此前因保护失效而能写入的受保护文件，现在会被拒。
- **残留**：项目身份层未归一 → 同一物理项目经不同路径打开会出现「项目未选中」（欠账 21-2）。
- **成本**：每次工具调用多一次 `fs.realpath`；对已存在目录可忽略，写工具本就要落盘，读路径不受影响。
- **可证伪性**：本决定由「两种项目根（真实根 / 链接根）× 8 条规则」的表驱动测试钉住，该测试在旧代码下必须变红。
