# ADR 0007：连贯性供给走工具拉取而非系统注入

日期：2026-08-24 ｜ 状态：已采纳（第十六轮）

## 背景

五六月（S2a/S3 时代）的旧控制面在每次章节工作流里系统级注入前情（前章结尾摘录 +
精选事实），函数为 `chapter-memory.mjs` 的 `buildContinuityPromptContext` /
`buildRelevantFacts`。八月六日 78c313f「replace legacy agent and conversation
control planes」整体替换旧控制面时，注入随之孤儿化；新 runtime 的
`run-pipeline.mjs:353` 硬编码 `dynamicContext: []`，注释理由（Task 7 工作流退役、
模型自主读文件）并未点名连贯性注入——属拆楼的连带效应而非明示处决。

## 决定

连贯性前情以 `read_continuity` 工具按需拉取供给，不做每轮系统注入；
`dynamicContext` 槽位保持空置。

## 理由

1. **缓存命中率**：系统提示永久稳定 → 供应商前缀缓存零损失。注入式小抄每章变化
  一次，变化即作废该位置之后的全部对话缓存折扣，长会话代价随篇幅放大。
2. **不臃肿**：小抄只在模型动笔前主动拉取，一轮写作拉一次，闲聊零开销。
3. **可靠性**：纯「叮嘱模型自己读原始文件」不可靠（长期观察：经常想不起来读、
  读原始 JSON 不知重点）；一键拿精选简报保留模型自主性又消除检索负担。
4. 政策文本立硬规矩「动笔写章节前必查前情」，同会话未发生新提交可免重复调用。

## 后果

- 工具结果进入对话历史，随历史自然缓存，不重复计费。
- 防呆提醒（未查前情就动笔时工具结果夹提示）本轮不做；依据 sim 冒烟观察决定是否补。
- `chapter-memory.mjs` 成为前情简报唯一组装点（含伏笔 top5 与实体档案两种模式）。
