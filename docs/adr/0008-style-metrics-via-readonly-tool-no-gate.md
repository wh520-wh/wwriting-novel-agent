# ADR 0008：风格指标走只读工具与技能反馈环，不建审校门禁

日期：2026-08-29 ｜ 状态：已采纳（第十七轮）

## 背景

竞品调研（`docs/research/2026-08-29-competitive-research-ai-voice.md`）P0 指出：`avoid-ai-voice`
技能是静态禁用清单，模型自评「有没有 AI 腔」不可靠，缺客观验收信号。而 round14（Task 10）
已**有意删除**确定性技能钩子运行时（`src/core/skills/index.mjs:15`：`stage: reviewing` 只是
惰性元数据），`commit_chapter` 工具描述明写「不做字数/标题/技能内容门禁」——「运行时零分支」
是既有架构决策。调研要求与该决策存在张力：客观统计不能靠模型自评，但门禁运行时已被否决。

## 决定

新增纯函数风格统计模块 `src/core/style-metrics.mjs` 与只读 agent 工具 `style_stats`
（仿 `count_text`，category "read"），量化目标（模糊修饰词密度、句长变异系数、三连排比）
写在技能文本里，由模型在审校/改稿对话中调用工具、按结果改写、复测，形成反馈环。
**不建任何程序化门禁**：提交路径、权限政策、技能运行时零改动。

## 理由

1. **兑现调研 P0 的「客观工具统计」**：数字来自确定性计算（复用 `word-count.mjs` 的
   Markdown 剥离与口径），不再依赖模型自评；工具结果带测量值与阈值对比，可解释。
2. **不推翻 round14**：工具是按需调用的只读读数，不是提交前的拦截分支；「9 通用 + 6 深」
   工具数量不变量同步修订为 10 + 6（`tools/index.mjs` 仅加行与注释）。
3. **误判安全**：调研 E9 表明统计指标会误伤真人作者（非母语偏差）；门禁一旦拦提交，
   误判即阻塞创作；参考值只进对话，作者保留最终裁量。刻意修辞豁免写进技能文本。
4. **最小实现**：纯函数模块 + 一个只读工具 + 一个 SKILL.md 重写 + 一份测试，无迁移、
   无兼容性风险、无新依赖。

## 后果

- 阈值常量单一来源是 `style-metrics.mjs`（`HEDGING_CAP_PER_1000`、`SENTENCE_CV_FLOOR`），
  SKILL.md 引用同一数字；v1 值为启发值，待调研「下一验证步」的人类语料基线校准。
- 模型可能不调工具就交稿——与 read_continuity 同等风险，先靠技能文本约束，实机观察再定。
- UI 指标面板、事实可验证性自检（P1）、第三方检测 API（P2）明确不在本轮。
