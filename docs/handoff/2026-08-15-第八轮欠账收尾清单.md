## 4. 欠账③：2026-08-14-polish 视觉截图矩阵（唯一要动代码的一项）

### 4.1 背景与现场

第八轮计划（`docs/superpowers/plans/2026-08-14-第八轮restore-settings-sections.md`，B4 节）要求产出一轮视觉验收证据目录 `artifacts/visual-acceptance/2026-08-14-polish/round-01`，命令：

```powershell
node scripts/capture-visual-acceptance.cjs --output artifacts/visual-acceptance/2026-08-14-polish/round-01 --mode round7
```

2026-08-15 实测该命令**退出码 1**，卡在：

```
AssertionError [ERR_ASSERTION]: checkpoint1 fail: detail column 326px < 360px at 1280 width
    at runRound7 (D:\WWriting\scripts\capture-visual-acceptance.cjs:2161:14)
```

含义：1280×800 窗口下，设置弹窗（四分区）里「模型设置」分区的右侧详情列只有 **326px**，第八轮计划的验收线要求 **≥360px**。

现场残留：`artifacts/visual-acceptance/2026-08-14-polish/round-01/model-settings-1280x800.png`（半成品，采集脚本规定"每轮一个目录、禁止覆盖上一轮"，修复后要删掉重跑）。

### 4.2 修复方案（第八轮计划 A5 节预置的官方回退点，照做即可）

**只改 CSS，不动任何 JS 逻辑。** 在 `src/app-shell/styles.css` 的 `.model-section` 区块（第 1162 行起）内追加一条弹窗作用域规则：

```css
.model-section .model-settings-body { grid-template-columns: minmax(0, 1fr); }
```

作用：设置弹窗里的模型分区强制单列（供应商列表在上、详情在下），详情列不再被 326px 挤压。

注意：

- 文件里已有的 `@media (max-width: 880px)` 折叠规则（约第 1250–1253 行）**保持不动**，新规则是新增的、无条件作用于弹窗作用域的；
- 计划原文："回退只改 CSS，不动 A3 逻辑。若检查点 3（≤720 视口 `.sp-side` 隐藏后模型分区仍可用）不通过，记录并升级（涉及 focus 逻辑，超出本计划范围）"——即修复后若反而冒出 focus 相关失败，不要硬修，如实记录升级。

### 4.3 修复后的验证顺序（严格按序）

1. `npm run verify:app-shell` → 预期 exit 0（纯 node，任何环境可跑）。
2. `npm run verify:app-clickability` → 预期 exit 0、17/17（若你的环境受限，按 §3.2 标注 BLOCKED 并继续）。
3. 删除半成品目录（PowerShell）：

   ```powershell

   ```

4. 重新采集：

   ```powershell

   ```

   预期 exit 0。若中途再报 checkpoint 失败：读报错行号，对照第八轮计划 A5/B4 节（约 425–442、791–792 行）处理；修复后回到本小节第 1 步重走。
