## 发现 A（产品问题）：sim 真实模式"全过"但第 1 章从未交付

sim 真实模式 12/12 通过，但工作区**没有 正文/ 目录**——模型对"写一个短章节"的响应是停下来反问题材/主角（给出了正当理由：不想凭空编设定污染连续性档案），整轮只调用了 `read_skill`。原因：

1. 阶段 5 的交付断言（正文/第001章.md 存在）是 mock-only；
2. 真实模式冒烟断言只数 `run_completed >= 2` + WWRITING.md 存在——**run 完成不等于交付完成**，反问也是一次"完成"的 run。

**修法**：真实模式冒烟断言加交付校验（正文目录出现章节文件、`count_text` 被调用）。08-04 立"真实 API 是最后防线"的规矩，但防线只数 run 不验货，等于没防住交付失败。

**产品含义（冲刺首章完成率的真实风险形状）**：不是模型写不动（补一句"就按你推荐的来"后第 1 章 2.5 分钟交付），而是**礼貌确认循环**——/init 生成的 WWRITING.md 把"题材未确认"列为待办，模型忠实等待作者拍板。真实作者如果没耐心回一句"就按这个"，首章就死在确认循环里。

## 发现 B（产品问题，根因与修复见下文「发现 B 根因」）：写第 1 章的 run 以 context_window_exceeded 失败

连写第 1 章的 run 在章节落盘、count_text 核对之后，以 `run_failed: context_window_exceeded`（"上下文仍超过硬窗口上限，无法发送"）结束。随后：

- 下一条输入（"继续写第2章"）**自愈**，第 2 章正常交付；
- 之后的 usage 快照仅 `used_tokens=19076 / 256000`（compaction_threshold 204800），远低于窗口上限——**为何报溢出**需要调查（flash 海量 reasoning 输出涨上下文快于估算器预期？"仍超过"暗示压缩已尝试过一次？）；
- 待查：run_failed 时刻桌面 UI 给作者看到什么？这是"第二天继续写作率"的直接风险点（数据没丢，但作者看到的是错误）。

## 边界说明：普通文件夹流没有章节门禁

本次连写的正文是模型 `write_file` 直写 `正文/`（工具序列：write_file/edit_file/count_text），**不经过** `append_chapter_segment`/入账/非正文检测那条 novel-project 流水线。冲刺解读"无阻塞完成率"时记住：主打流程的交付防线只有 count_text（模型自选调用）+ 作者肉眼。

## 发现 B 根因（当日已查明）与修复

完整链条（journal 事件 3333–3343 可复查）：模型写完第 1 章想"入账"，推理"先看事件记录里有没有项目标识"，于是 `read_file` 读**应用私有状态目录里自己的 journal 事件文件（3.5MB JSONL）**；读取在工作区外走了权限确认（脚本自动放行）；工具结果原样进入下一轮请求，`used_tokens` 14,444 -> **388,396**（窗口 1.5 倍）；压缩触发但 `nothing_to_compact`（工具结果刚闭合）-> 仍超硬窗口 -> `run_failed`。下一输入自愈是因为大工具结果被 volatile 机制排除出历史装配。

根因：`read_file` 截断上限 1MB 按"工具流截断"设定，从未对齐 256k token 上下文窗口（1MB JSONL ≈ 39 万 token）；shell 结果同样未切片返回（只算 truncated 标记）。

## 修复（分支 `fix/real-api-stress-findings`）

1. **工具结果上限对齐窗口**（`tools.mjs`）：新增 `MAX_TOOL_RESULT_CHARS = 100_000`（按最小窗口 256k、CJK 1 字符≈1 token 的最坏口径）；`read_file` 按它截断；shell 结果按合并预算切片（stdout 优先、stderr 吃余量）；search 跳过文件的 1MiB 字节口径独立保留不变。含 `ponytail:` 注释：若接入 <256k 窗口 provider，应改在历史装配层按窗口截断。回归测试：`tests/agent/tools.test.mjs`（150k 字符文件读取截断到 100k + truncated 标记）。
2. **sim 真实模式交付断言**（`simulate-user-flow.mjs`）：run 完成不等于交付--新增"章节已交付（正文/ 或 chapters/）"+"count_text 已调用"两条冒烟断言，堵住假绿。
3. **政策文本默认值开写 + 范围约束**（`prompt.mjs`）：题材/主角未确认时给推荐默认直接开写（默认不算已确认事实、不写入 WWRITING.md）；交付范围以作者本次要求为准，未要求连写时完成一个交付单元即停。
