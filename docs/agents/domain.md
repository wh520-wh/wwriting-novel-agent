## 使用词汇表里的词

当你的输出提到某个领域概念（issue 标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 中定义的术语。不要漂移到词汇表明示 `_Avoid_` 的同义词。

- 用「**真实项目根**」，不要写「物理路径 / 规范路径 / 绝对路径」
- 用「**受保护路径**」，不要写「只读文件 / 系统文件」
- 用「**项目内 / 项目外**」，不要写「沙箱内 / 沙箱外、白名单 / 黑名单」
- 用「**权限模式**」，不要写「工作流 / 写作模式」；用「**工作流**」指 Agent 的内部执行政策，两者不可混用
- 用「**思考强度**」，不要写「推理内容 / 思维链」

若你需要的概念还不在词汇表里，这是一个信号：要么你在发明本项目不用的语言（重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 与 ADR 冲突要显式标出

若你的输出与既有 ADR 相矛盾，明确暴露出来，而不是悄悄覆盖：

## 文档时间与数字规则（本仓库强制）

`docs/` 下新增或修改任何文档，都要遵守 `AGENTS.md`「文档时间与数字规则」：可变事实加 `记录于：YYYY-MM-DD｜状态：当前有效/历史记录/待复核｜依据：…` 标注，测试数/文件规模/版本/验收结果必须注明口径与来源。
