# WWriting UI 美化建议（基于全量截图评审）

> 评审范围：历史应用截图约 90 张 + 8 张高保真原型稿，覆盖浅色/深色双主题、390×844 / 768×900 / 1280×800 / 1440×900 四种视口（原 `artifacts/now/` 截图目录已随清理归档，本建议的结论与令牌表仍可独立参考）。
> 评审方法：5 路并行逐张目检（每张均实际打开查看），按「布局间距 / 字体排印 / 色彩对比度 / 组件样式 / 信息层级 / 响应式」六维度记录，再交叉汇总去重。本文所有问题均标注截图出处，可逐条回查。
> 生成时间：2026-08-15

## 〇、总体印象

**优点（要保留的）：**

- 阅读器正文排版是全应用的品质天花板：衬线正文、首字下沉、约 1.9 行高、段落节奏专业（`04-shell-interactions/21-reader-open.png`）。
- 浅色主题中性灰白调性克制，绿色指示条/状态点使用克制；深色主题整体统一无杂色。
- 新建小说弹窗是全部弹窗中布局最均衡的：双列数字框、全宽主按钮收尾有力（`31-create-modal-empty.png`）。
- 顶栏图标风格统一（线性），抽屉 Tab 栏五等分排布整齐。
- 响应式断点基本工作正常：768px 侧栏收起、390px 弹窗近全屏，无横向溢出（机器断言也证实）。

**核心症结（一句话）：** 这不是"风格丑"的问题，而是**设计系统没有收敛**——同类组件三套语言并存、状态反馈（hover/选中/聚焦）普遍弱到不可感知、关键状态色（危险/警示/进行中）缺位、若干处两字文案被挤成竖排的布局 bug 反复出现。下面的建议按「先修系统性令牌，再修区域」组织，性价比最高的修复都在第一、二章。

## 一、设计系统层（全局令牌，改一次全App受益）

### 1.1 状态反馈体系：hover / 选中 / 聚焦全面加深一档 ⭐性价比最高

现状：全应用的交互反馈弱到"发木"。证据：

- 会话选中行底色与常态差异 <5%（`05-rail-session-active.png`、`13-dark-main.png`），扫视时无法定位当前会话；且浅色主题另有突兀的黑色实心圆点选中指示（`01-run-light/conversation-completed-1280x800.png`），两套选中语言并存。
- 发送按钮 hover 与常态像素级无差别（`10-send-hover.png` vs `09-composer-filled.png`）；黑色主按钮已是最高视觉重量，hover 无从加深。
- 抽屉未选中 Tab 的 hover 完全静默（`20-drawer-tab-hover.png` 与 `19` 几乎零差异）。
- 章节行 hover 仅一丝浅灰底，右侧 `>` 箭头无变化（`15-drawer-chapter-hover.png`）。
- composer 聚焦态仅靠边框略加深，与非聚焦几乎不可分（`08-composer-focus.png`）；阅读器工具钮、设置侧栏导航 hover 同样偏弱（`22`、`25`）。

**统一规范建议：**

| 状态 | 浅色主题 | 深色主题 |
|---|---|---|
| hover 底色 | `#ECECEC`（当前约 `#F5F5F5`，加深到肉眼可辨） | `#2E2E2E` |
| 选中底色 | `#E8E8E8` + 左侧 3px 主题色竖条（高 20px、圆角 2px）+ 文字加粗 | `#333333` + 同款左竖条 |
| focus ring | 2px 主题色 20% 透明度外发光，或边框加深至 `#999` | 同左 |
| 主按钮 hover | `#000 → #333`，active `scale(0.98)` | 白按钮 hover `#DDD` |
| 危险操作 hover | 图标/文字转 `#DC2626` | 同左 |

- 删除侧栏的黑色实心圆点选中指示，全部改为「底色 + 左竖条」方案。
- 所有 hover 加 120–150ms 过渡，避免生硬跳变。

### 1.2 对比度：系统性逼近 WCAG AA 下限

以下位置估算对比度均 ≤3.5:1，未达正文 4.5:1 标准：

- composer 底部「未配置 / 确认后修改 / 自动」三个 chip（**全部 40+ 张对话截图张张如此**，浅色约 3:1，深色 <3:1）。且「未配置」是需要用户警觉的警示状态，却用了最低对比度处理。
- 「内置」徽章（`settings-builtin-styles`）、「已计费/总览」小字（`36-dark-drawer.png`）、「还没有对话」（`40-plain-folder.png`）、「1 秒」计时灰字、引用块文字、深色「停止」按钮（约 3.5:1）。

**修复：** 辅助文字色浅色主题不低于 `#6B7280`（小字）/ `#8A8E94`（仅限占位提示），深色主题不低于 `#9AA0A6`。**「未配置」chip 必须加警示语义**：琥珀色文字 `#B45309` + 浅琥珀底 `#FEF3C7`，或前缀红点。

### 1.3 组件语言收敛：三类组件各自只有一套

**按钮（现状至少三种形态：带边框按钮 / 灰底 chip / 裸文字，外加黑实心）：**

- 主按钮：实心，高 36px，圆角 8px，用于每屏唯一主操作。
- 次按钮：1px 描边，高 32px，圆角 6px。
- 文字链：仅用于次要导航（如「返回」）。
- 危险按钮：红字 `#DC2626` + 红描边，hover 红底白字——目前「清空对话历史」与普通按钮完全同款（`29-settings-danger.png`），**误点成本是删除用户数据，属可用性安全问题**。
- ⭐「无需保存」黑色实心主按钮是系统性组件误用（`24-settings-model.png`、`13/14 settings-builtin-styles`、`settings-style-detail`、`30-settings-save-hover` 均出现）：它是状态提示而非操作，却拿走全弹窗最强视觉焦点，第一眼焦点错误。**改为灰色 12px 纯文字提示「✓ 更改即时生效」**，只在有未保存改动时才出现真正的黑色「保存」按钮（写作参数页的「保存设置」就是正确示范）。

**Tab / 分段控件（现状两套）：** 抽屉 Tab 选中=黑底白字圆角块（`14-drawer-chapters.png`），设置弹窗「全局/项目」选中=白底浅灰边（`28-settings-skills.png`），同类组件两套语言且后者选中区分度极低。**统一为一套**：浅色=黑底白字 pill；深色=**禁用白底黑字**（`36-dark-drawer.png` 里白底胶囊像浅色组件误入），改 `#2C2F33` 底 + 白字 + 底部 2px 强调条。设置侧栏导航选中态的整圈黑色粗边框（`25-settings-nav-hover.png`）像输入框 focus 框，改为浅灰底 + 左竖条 + 加粗。

**展开箭头（现状位置漂移）：** 思考块/工具行的 `^`/`∨` 箭头贴在对话区右缘，离所属内容 700px+，三枚箭头三种方向竖排互不相属（`tool-after-reasoning-*.png` 两主题同病）；用户气泡的 `^` 图标脱离气泡悬浮。**规则：箭头一律收进所属行/卡片内侧右端（padding 8px 内），跟随内容块宽度，禁止孤立在列右缘。**

### 1.4 字阶与排版

- Markdown 标题梯度塌陷：H3–H6 与正文几乎等大，靠变灰分层（`markdown-fixture-1280x800.png` 两主题）。**按字号分层而非颜色变浅**：H1 22 / H2 18 / H3 16 / H4 14.5 / H5 13.5 / H6 13，颜色统一正文色，H4 以下字重 600→500 过渡。
- 正文行宽：深色完成态行宽达 ~950px（55+ 全角字符/行），沉浸阅读器达 1100px（50+ 字/行），均超中文舒适上限。**对话正文 max-width 720–760px，阅读器（含沉浸模式）钳制 720–800px 居中**——原型 `43-mockup-polish-preview` 已定 720px 规范，直接落地。
- 垂直节奏：采用原型规范「轮内 12px / 轮间 28px」（`43`）。
- 中文孤字成行：「恢\n复。」独占一行（`conversation-completed-1280x800.png`）、说明文字孤字「件。」（`39-dark-create-modal.png`）：加 `line-break: strict` 并限制行宽。
- 已完成任务项加删除线 + 降灰；引用块文字加深至 `#6B7280`、左边线加粗 3px；代码块加 hover 复制按钮，深色代码块底色提至 `#232328`、文字 `#D4D4D4`。
- 链接：绿色是全局唯一彩色文字（`markdown-fixture`），深浅两主题下可发现性都差。**引入单一品牌色**（如靛蓝或墨绿）统一链接/强调/进行中状态，或至少深灰+下划线。路径/文件名/命令统一等宽字体 + 浅底 chip + 可点链接样式（`正文/第001章.md`、`project.yaml` 目前与正文同样式，结果入口不可发现）。
- 「任务计划 3/3」等计数用 `tabular-nums` 防抖动。

### 1.5 品牌与温度

整屏唯一强调色是黑色实心块，欢迎页中央图标是个 24px 灰边小方块，像图片加载失败占位符（`00-welcome-empty.png`）。建议：确定一个品牌色（贯穿链接、进行中状态、选中竖条、主按钮可选）；欢迎页换 64–80px 品牌插画或羽毛笔图标；深色主题主按钮用品牌色填充而非纯白（`38-dark-settings.png`）。

## 二、必须先修的布局 Bug（分布广、肉眼可见）

这些问题在截图评审中反复出现，比任何风格调整都优先：

1. **两字文案竖排事故（同一根因，至少 6 张截图中招）**：抽屉章节行的「历史」（`14/15`）、阅读器工具条「沉浸」「历史」（`21/22/23`）被挤成一列一个字。根因：容器宽度不足 + 未禁换行。修复：链接/按钮容器 `flex-shrink: 0; white-space: nowrap`，阅读器工具钮统一 32×32px、文字横排（按钮宽 56px）。
2. **模型设置报错竖排单字列（最严重排印事故）**：≤768px 时报错「× 模型服务器返回错…」被压成每列一个汉字的竖排，完全不可读，同行 5 个按钮被挤出（`model-settings-768x900.png`、`model-settings-390x844.png`）。修复：模型条目改为卡片式纵向布局——第一行模型名+状态 chip，第二行操作按钮组右对齐，第三行浅红底（`#FEF2F2`）告警条通栏、单行省略+悬停 tooltip。
3. **API 密钥框眼睛图标居中错位**（`model-settings-1280x800.png`）：应 `right: 12px`，位于安全敏感区域，肉眼可见的质量破绽。
4. **隐私 toast 遮挡 composer chips**（`12-privacy-on.png`、`13-dark-main.png` 双主题复现）：「自动」chip 被完全盖住；且 toast 宣称「正文已模糊」但对话区正文清晰——文案与实际生效范围不一致。toast 上移至对话区底部（composer 之上 16px），文案按实际范围修正。
5. **A+ 按钮折行破损**（`37-dark-reader.png`）：A−/A+ 合并为一组 segmented 控件。
6. **深色新建弹窗顶部 2px 来源不明亮条**（`39-dark-create-modal.png`）：检查 border/focus ring 溢出。
7. **抽屉遮罩范围不一致**：遮罩只压暗主区不遮侧栏，侧栏像"弹到抽屉上层"（`01-run-light/drawer-1280x800.png`）；深色下遮罩太轻（约 0.4），背景红色错误卡透出且不可读（`36-dark-drawer.png`）。统一为全屏遮罩（含侧栏）、不透明度 0.6，或改为内容区右推不用遮罩。
8. **手机端抽屉残边**：390px 下成本抽屉左缘露出 ~30px 被切断的半个汉字（`cost-panel-390x844.png`）：≤480px 时抽屉 `width: 100%`。
9. **会话行截断裁半字**：hover 浮现图标挤压文本，半个字符与省略号并存（`04-rail-hover-session.png`）：文本容器 `flex: 1` + ellipsis，图标区固定宽度。
10. **滚动区无渐隐 + footer 遮挡**：设置弹窗列表被底部按钮栏生硬裁断（`settings-builtin-styles-1280/390`）：内容区 `padding-bottom ≥ 76px` + 底部 24px 渐隐遮罩。

## 三、分区域详细建议

### 3.1 左侧栏（rail）

- 选中态按 §1.1 重做（当前过浅 + 黑圆点突兀两问题并存）。
- hover 浮现的「+ / 编辑 / 删除」图标对比度 <3:1，加深至 `#666`+；删除 hover 转红。
- 行内改名编辑器（`rename-editor-1280x800.png`）：编辑态隐藏行尾冗余图标，输入框撑满至行右缘-8px，加 2px 聚焦描边，右侧放 ✓/× 确认取消钮。
- hover 底色与栏底色差异过小（`02-rail-hover-new.png`），按 §1.1 加深。

### 3.2 顶栏

- 390px 下语义丢失严重（`conversation-completed-390x844.png`）：「面板」退化成无意义方框图标、「任务计划」丢掉 3/3 计数、标题只剩 4 字。<480px 时把次要按钮收进 ⋯ 溢出菜单，「任务计划」chip 改为「3/3」纯数字徽标，标题至少保 6 字。
- 768px 下无侧栏入口（无汉堡按钮），平板用户无法导航回小说列表（`conversation-completed-768x900.png`）：顶栏左侧加 40×40px 汉堡/返回钮。
- 深色主题月亮图标有填充底色而其他图标没有（`02-run-dark/reasoning-running-t000`），状态表达统一。
- 「面板」按钮（带边框）与「任务计划」chip（浅灰）两个并列控件样式等级不一致，统一为同款 32px 控件；chip 右侧加 `▾` 提示可展开。

### 3.3 对话区 · 运行态

- ⭐「停止」按钮是运行期唯一逃生操作，现状为纯灰裸文字、孤立悬浮在屏幕右缘中段，远离「工作中」状态行 100px+，双主题对比度都仅约 3.5:1（6 张运行态截图 + `round7` 张张如此）。**改为 32px 高描边按钮「■ 停止」，紧贴状态行右侧，与状态视觉编组。**
- 「思考中」与思考摘要同为深灰粗体，层级扁平：标题 14px/600，摘要 13px/400 灰 `#6B7280`。
- 浅色主题扫光动画几乎不可见（白高光扫白底）：改 rgba(0,0,0,0.06–0.1) 灰色扫光，或「呼吸圆点+文字渐变」双信号；摘要流式更新加 150ms 淡入位移防跳变。
- 工具调用行（`tool-after-reasoning-*`）：完成态/进行态无状态色区分、「·」指示符太隐晦、无容器。建议：步骤列表加左侧 2px 竖线 + 状态圆点（完成=灰实心、进行=脉冲强调色），行高 40px；工具名等宽字体+浅灰底 chip；进行态用三点弹跳动画。三帧静态图完全静止加深"界面像卡住"观感，计时器需真实按秒跳动。
- 「工作中 4 秒」与「思考中」之间的莫名 24px 缩进（`round7-1280x800.png`）取消，改单行「⏱ 工作中 4 秒 · 思考中」。

### 3.4 对话区 · 完成态与队列

- ⭐**已完成工作折叠态信息量不足**：成品只有「工作了 0 秒」一行；原型 `41-mockup-v4-normal` 的折叠卡（✓ 绿勾 + 「第 X 章 · 第 Y 节」定位 + 「撰写 1 段 84 字」量化元信息 + 一行内容摘要）明显更优，直接吸收。回复中的产出文件路径渲染为等宽链接，点击跳转章节。
- 「任务计划 3/3」chip 深色下存在感弱，提亮一档或加描边。
- 队列行（`round7-*`）：状态（下一条/排队）与操作（立即/取消）同为小灰字无法区分，「立即」是禁用还是弱化无法判断；优先级徽标无色彩编码。状态用 chip（下一条=强调色、排队=灰），操作用文字按钮；390px 下折行后状态 chip 跟在任务名同行尾部、操作第二行右对齐，避免两行两端大片空白。
- 宽表格状态列（已提交/草稿中/未开始）纯文字无色彩编码：改 pill 徽标（绿/黄/灰系），表头底色加深加粗。
- 对话窗顶部加「已自动保存」状态（原型 41 有，成品无任何保存反馈）。

### 3.5 对话区 · 决策卡与错误卡

- ⭐**权限决策卡**（`34-decision-card.png`）：三按钮同为浅色描边胶囊无主次，「一次允许」（推荐）与「拒绝」（破坏性）同样式并列；卡片与白底消息区无差别，第一眼焦点被右上用户气泡抢走。修复：「一次允许」改主色实心、「本条输入允许同类操作」次强调描边、「拒绝」红字/浅红描边；卡片加左侧 3px 主色竖条 + 暖灰底 `#F7F5F0`；超长路径中间截断（`D:\…\notes\大纲.md`）+ 复制图标；内边距与输入框统一 20px。
- ⭐**错误卡**（`35-error-card.png`）：裸文本块（淡红底+两行红字），无图标无圆角无边框，「重试」是无按钮样式的隐身文字。**直接照搬原型 `41-mockup-v4-apiKey` 的成熟方案**：⛔ 图标 + 「模型调用失败 · 401」分类标题 + 错误码等宽 chip（`401 Unauthorized · invalid_api_key`）+ 时间戳 + 三按钮「重试 / 打开设置 / 复制错误详情」。正文改深灰 `#444` 仅标题保红；补「打开设置」治本路径（鉴权失败靠重试无用）。
- 重试进行中要有进度态视觉（原型自身也缺）：如黄色小条「网络波动，第 2/5 次重试中」。

### 3.6 Composer

- 底部三 chips 对比度修复 + 「未配置」警示色（见 §1.2）。
- 发送钮旁「2%」小圆环（约 9–10px 字号）无标签无 tooltip，含义不明，与上下文 popover 内容重复：改细进度环 + tooltip，或删除、由点击 chip 触发 popover。
- 聚焦态加 focus ring（§1.1）；单行内容时 composer 高度收成 64px，输入增多再展开（当前单行占两行高容器，显空）。
