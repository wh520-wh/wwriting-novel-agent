# 第十轮设计规格：全应用 UI 成熟化

> 文档性质：设计规格文件（Design Spec），不是执行计划。
> 状态：需求已对齐，可据此编写实施计划。
> 日期：2026-08-15。
> 适用范围：WWriting 桌面应用的全应用视觉、排版、布局、交互反馈、响应式与无障碍表现。
> 主要输入：`docs/design/UI美化建议.md`、`docs/design/写作Agent对话样式规格书.md`、第十轮需求对齐日志。

---

## 1. 本轮目标

前九轮已经完成产品能力和核心工作流。本轮不增加业务能力，而是把当前“功能完整但仍有开发版本痕迹”的界面收敛为一个稳定、可信、可长期使用的专业桌面产品。

目标产品不是企业管理后台，而是：

> 面向个人长篇创作者、具备企业级完成度的专业写作 Agent。

“企业级”在本规格中指：

- 同类组件只有一套语言；
- 信息层级清楚，关键状态可快速识别；
- 浅色与深色主题同等完整；
- 中文长文适合长时间阅读；
- 窄窗口、系统缩放、键盘操作和异常状态稳定；
- 不出现临时感、拼装感、控件串色、文字裁切或交互反馈缺失；
- 视觉判断有明确令牌与规则，不依赖执行模型临场发挥。

本轮不是换皮，也不是重新设计业务流程。

---

## 2. 规格优先级与文档关系

发生冲突时，按以下顺序裁决：

1. 用户在第十轮需求对齐中确认的产品体验；
2. 本规格；
3. `写作Agent对话样式规格书.md` 中的行为与状态机契约；
4. `UI美化建议.md` 中的视觉问题和修复建议；
5. 现有实现与旧视觉契约测试；
6. 通用 UI 数据库或风格模板。

具体关系：

- `写作Agent对话样式规格书.md` 继续拥有 AgentSurface 的行为、状态机、事件、文案禁令和数据所有权。
- 本规格拥有全应用视觉系统，以及 AgentSurface 的视觉、布局、排版和交互反馈。
- `UI美化建议.md` 是问题清单与证据索引，不是最终行为契约。
- 旧测试若只是在固定旧视觉，应更新为本规格；涉及业务行为、安全或数据一致性的测试不得放宽。

## 3. 范围

### 3.1 本轮包含

- 全局颜色、字体、字号、行高、间距、圆角、边框、阴影和动效令牌；
- 浅色与深色双主题；
- 左侧导航、顶栏、Agent 对话区、Composer、右侧项目面板；
- 阅读器、设置、新建小说、快捷键、计划面板、版本面板和其他现有弹层；
- hover、focus-visible、pressed、selected、disabled、loading、success、warning、danger 状态；
- 390、768、1280、1440 宽度附近的响应式行为；
- Windows 100%、125%、150% 显示缩放下的稳定性；
- 为正确布局、语义和无障碍所需的 DOM 调整；
- 不准确、含糊或过度技术化的界面文案修正；
- 已有交互因定位、裁剪、层级或事件热区问题不可见、不可点时的修复。

### 3.2 本轮不包含

- Agent 推理、写作、工具调用、队列、权限和模型状态机改造；
- 新页面、新业务模块、新数据模型或新 API；
- 新附件、提示词增强、技能 pill 或营销式推荐入口；
- 重型 UI 框架或新图标依赖；
- 大面积渐变、玻璃拟态、发光、紫蓝 AI 风、装饰性动态背景；
- 为视觉效果牺牲正文阅读体验；
- 中间过程的截图矩阵、像素对比、浏览器目测或多模态视觉验收；
- 执行模型自行反复采图、调图、重跑视觉工具。

## 4. 产品气质

整体比例：

- 70% 精密生产力工具；
- 30% 文学阅读温度。

设计参考只取原则，不复刻外观：

- Linear：精确网格、克制控件、稳定状态、低噪声层级；
- Claude：舒适长文、内容优先、温和但不松散；
- 瑞士现代主义：数学化间距、清楚字阶、单一强调色；
- 原生桌面工具：键盘友好、响应直接、不过度移动端化。

禁止把“企业级”误解为：

- 大量卡片、阴影和统计面板；
- 企业蓝或紫色渐变；
- 每个操作都加边框胶囊；
- 过度解释、教学或拟人化文案；
- 为显得高级而降低对比度。

## 5. 全局设计系统

### 5.1 色彩原则

中性结构色承担绝大部分界面。墨绿只用于：

- 键盘焦点；
- 链接；
- 当前选中标记；
- 运行中状态；
- 少量需要品牌识别的局部元素。

主操作按钮保持中性黑/白，不把所有主按钮改为绿色。成功、警告、危险继续使用独立语义色，不能只用墨绿区分全部状态。

### 5.2 浅色主题令牌

以现有令牌为基线，执行时允许为对比度做小幅校准，但不得改变色彩关系。

| 角色 | 建议值 | 用途 |
|---|---:|---|
| `--bg` | `#FAFBFC` | 主画布，非纯白 |
| `--rail` | `#F4F5F7` | 左侧导航 |
| `--rail-2` | `#E9ECEE` | 较强结构层 |
| `--surface` | `#FFFFFF` | 弹窗、菜单、独立对象 |
| `--surface-2` | `#F7F8F9` | 次级表面 |
| `--surface-3` | `#EDF0F2` | 状态或分组表面 |
| `--ink` | `#202522` | 主文字 |
| `--ink-2` | `#3F4742` | 次级标题 |
| `--muted` | `#69716C` | 辅助文字，允许承载信息 |
| `--faint` | `#8B938E` | 占位、禁用，不承载关键状态 |
| `--line` | `#E4E7EA` | 普通边界 |
| `--line-2` | `#D9DDE1` | 较强边界 |
| `--hover` | `#E6E9EC` | 可感知 hover |
| `--accent` | `#3F6B4F` | 墨绿强调 |

| warning | `#8A6D2F` | 警告 |
| success | `#2C6E49` | 成功 |

浅色主题不得使用大面积奶油黄、米色或仿旧纸张背景。文学温度来自正文排版，而不是把整个应用染成暖色。

### 5.3 深色主题令牌

| `--surface` | `#1D2023` | 弹窗、菜单 |
| `--surface-2` | `#202327` | 次级表面 |
| `--surface-3` | `#2B312D` | 状态表面 |
| `--ink` | `#EEF2EF` | 主文字 |
| `--ink-2` | `#D3DAD5` | 次级标题 |
| `--muted` | `#A8B1AB` | 辅助文字 |
| `--faint` | `#858F89` | 占位、禁用 |
| `--line` | `#2A2E32` | 普通边界 |
| `--line-2` | `#33383D` | 较强边界 |
| `--hover` | `#2A302C` | hover |
| `--accent` | `#8FB08F` | 深色墨绿强调 |
| `--accent-soft` | `#263026` | 墨绿浅底 |
| `--btn` | `#E2E9E4` | 主按钮 |

深色模式中不得出现未经令牌映射的纯白胶囊、浅色卡片或刺眼边框。

### 5.4 字体体系

不依赖网络字体，不增加字体下载和加载失败风险。

UI 无衬线字体栈：

```css
-apple-system, BlinkMacSystemFont,
"Segoe UI Variable Text", "Segoe UI",
"PingFang SC", "Hiragino Sans GB",
"Microsoft YaHei UI", "Microsoft YaHei",
"Source Han Sans SC", "Noto Sans CJK SC",
system-ui, sans-serif
```

Agent 正文与阅读器衬线字体栈：

```css
"Source Han Serif SC", "Noto Serif SC", "Songti SC", "STSong",
"SimSun", Georgia, "Times New Roman", serif
```

路径、命令、错误码、模型名和数据使用现有等宽字体栈。

禁止：

- 全应用统一衬线；
- 网络加载 Inter、Noto 或其他字体；
- 中文 UI 使用负字距；
- 为“高级感”使用极细字重；
- 在尺寸固定的控件中使用不稳定的连续视口字号。

### 5.5 字号与行高

采用整数档位，减少 Windows 非整数缩放下的栅格化不稳定。

| 层级 | 字号 | 行高 | 字重 |
|---|---:|---:|---:|
| 页面主标题 | 22px | 1.35 | 650–700 |
| 区域标题 | 18px | 1.4 | 650 |
| 小节标题 | 16px | 1.45 | 600–650 |
| 强调正文 | 15px | 1.6 | 500–600 |
| UI 正文 | 14px | 1.55–1.65 | 400 |
| 控件与次级信息 | 13px | 1.45–1.55 | 400–550 |
| 辅助文字与徽章 | 12px | 1.4–1.5 | 400–550 |
| Agent 正文 | 15px | 不低于 2.0 | 400 |
| 阅读器正文 | 17px | 1.9–2.0 | 400 |

低于 12px 的文字不得承载必要信息。数字计数、耗时和金额使用 `tabular-nums`。

全局 UI 不使用 `letter-spacing` 压缩中文。比例字宽特性不得导致按钮、标签或表格列宽在不同 Windows 字体环境中变化；需要时只在正文排版局部启用。

### 5.6 阅读排版

- Agent 正文：现代文档式排版，无首行缩进、无首字下沉；
- 阅读器：保留书籍式排版、首行缩进和已有首字下沉品质；
- Agent 正文阅读宽度 720px；
- 阅读器正文宽度 720–800px；
- 中文正文目标约 30–42 个全角字符/行；
- 标题靠字号、字重和间距分层，不靠不断变浅的灰色；
- 引用、链接、代码、文件路径一眼可辨，但不与正文争抢焦点；
- 长正文优先自然换行，不为整齐随意省略；
- 必须截断的项目名称、路径和模型名提供 `title`、复制或展开能力。

### 5.7 间距体系

以 4px 为基础网格，常用档位固定为：

```text
4 / 8 / 12 / 16 / 20 / 24 / 28 / 32 / 40 / 48
```

关键节奏：

- 对话轮内：12px；
- 对话轮间：28px；
- 普通控件间距：8px；
- 卡片或独立对象内边距：16–20px；
- 页面级左右安全边距：14–24px 自适应；
- 同层级区域不得混用无规律的 13、17、19、23px 间距。

### 5.8 圆角与阴影

| 对象 | 圆角 |
|---|---:|
| 小控件、输入框、次按钮 | 6px |
| 主按钮、常规控件 | 8px |
| Composer、菜单、弹窗 | 10–12px |
| 状态徽章 | 胶囊形，仅限徽章 |

页面分区不做漂浮卡片。阴影只用于：

- Composer；
- 下拉菜单和 popover；
- 弹窗；
- 临时覆盖层。

普通列表、设置分组、工作组和正文主要依靠背景、间距和细边界组织。

### 5.9 交互状态

所有交互控件必须有稳定状态，不改变组件外部尺寸。

| 状态 | 规则 |
|---|---|
| hover | 120–150ms 背景或文字变化，肉眼可辨 |
| pressed | 80–100ms 内反馈，可轻微缩放至 0.98，但不得推动布局 |
| selected | 浅背景 + 字重，导航可加左侧 3px 墨绿竖条 |
| focus-visible | 2px 墨绿焦点环，offset 2px，只为键盘焦点显示 |
| disabled | 语义禁用、不可点击、降低强调，仍可读 |
| loading | 控件自身显示进度并防连点，不改变尺寸 |
| danger | 红色文字/边界，与普通操作保持空间分离 |

当前项目、当前会话和当前导航使用同一组选中语言。删除旧的黑色实心圆点等第二套选中标记。

### 5.10 动效

动效强度低，仅服务状态、层级和因果。

- 按压反馈：80–100ms；
- hover：120–150ms；
- 菜单、popover、弹窗：150–250ms；
- 新消息和状态替换：短促 opacity/translate；
- 退出时长约为进入的 60–70%；
- 不动画 width、height、top、left；
- 不做装饰性错峰入场、背景漂浮或弹跳；
- 真实思考、流式输出等活动源可有对应动态；
- Run 终态或用户折叠后，循环动效必须归零；
- 支持 `prefers-reduced-motion`、`prefers-reduced-transparency` 和 `prefers-contrast: more`。

### 5.11 图标

- 复用项目现有图标系统，不增加依赖；
- 同一层级保持相同线性/填充风格和笔画粗细；
- 高频、熟悉操作可使用图标按钮；
- 关键操作和低频操作使用“图标 + 文字”；
- 图标按钮必须有 `title` 与可访问名称；
- 不使用 emoji 作为导航或结构图标；
- 图标视觉尺寸稳定，点击热区大于图形本身。

## 6. 全局布局

### 6.1 桌面结构

```text
左侧紧凑导航 | 主工作区 | 可选右侧项目面板
```

- 左侧导航是主要项目和会话入口；
- 主工作区承载顶栏、AgentSurface 和 Composer；
- 右侧项目面板用于章节、模型、资料、成本和记忆；
- 设置继续使用大型设置弹窗，不改成新页面；
- 页面分区以结构层和细边界区分，不将每个区域做成卡片。

### 6.2 双层内容轴

统一采用：

- 外层交互轴：`1040px`；
- 内层阅读轴：`720px`；
- 阅读器正文：`720–800px`。

外层交互轴承载：

- Composer；
- 用户气泡；
- 队列行；
- 宽表格、代码和复杂控件；
- 对话时间流的外层容器。

内层阅读轴承载：

- Agent 正文；
- 工作组 summary 和明细；
- 引用、普通列表和短代码块。

外层与内层必须共享同一主轴关系，不能出现 Composer 任意漂宽、正文另行偏移的情况。

### 6.3 左侧导航

- 桌面使用紧凑文字侧栏，不改为纯图标栏；
- 项目和会话行保持稳定轨道，hover 后出现的操作不能挤压文本；
- 中窄窗口自动收起，通过顶栏按钮打开；
- 当前项使用背景 + 字重 + 左侧墨绿标记；
- 危险操作 hover 转红；
- 重命名态隐藏无关操作，输入框占满可用空间。

### 6.4 顶栏

顶栏只保留：

- 当前项目身份；
- 必要状态；
- 任务计划入口；
- 少量全局操作。

次要操作进入溢出菜单。顶栏不得成为一排常驻胶囊按钮。窄窗口必须保留导航入口和可识别的项目标题。

### 6.5 右侧项目面板

- 宽屏：非模态侧栏，打开后主工作区自适应，不使用阻断式遮罩；
- 中窄窗口：覆盖式抽屉，遮罩覆盖整个应用可交互区域；
- 390px 附近：占满可用宽度，不露残边；
- 宽度以 360–400px 为基线；
- 关闭后焦点返回触发入口；
- 抽屉滚动与主页面滚动互不干扰。

### 6.6 响应式分层

| 宽度 | 行为 |
|---|---|
| `>= 1280px` | 左侧导航常驻；右侧面板非模态；主内容保持双层内容轴 |
| `769–1279px` | 左侧导航可收起；右侧面板按空间决定侧栏或覆盖；主内容流式收缩 |
| `481–768px` | 左侧导航和右侧面板均为覆盖层；顶栏保留导航入口；设置接近全屏 |
| `<= 480px` | 核心流程完整可用；抽屉和设置为全宽 sheet；复杂表格改卡片或内部滚动 |

390px 是窄桌面窗口的核心可用下限，不将应用改造成手机 App。触控/点击目标以 36–40px 为主，关键操作不小于 40px；图标本体可更小，但热区必须稳定。

## 7. 区域规格

### 7.1 欢迎页与空状态

- 应用欢迎页使用与现有 WWriting 身份同源的克制品牌图形；
- 本轮精修品牌图形语言，不进行彻底换品牌；
- 欢迎页只提供明确入口，不做营销 hero；
- 项目内空对话只显示必要状态，不提供建议问题 chips；
- 普通文件夹模式明确标识当前模式；
- 空状态说明发生了什么，并在确有下一步时提供一个主操作。

### 7.2 AgentSurface

保留：

- 单一对话面；
- 无头像、无署名；
- Agent 正文无框；
- 用户消息使用紧凑中性气泡；
- 工作过程使用无框工作组；
- Composer 稳定三行；
- Run 结束后结果干净。

不得恢复旧的横贯分隔线、每项工具卡片、独立运行面板或重型章节完成卡。

### 7.3 运行态

- 状态行、思考、工具、计划按真实事件顺序出现；
- “停止”是当前 Run 的关键逃生操作，必须紧贴状态行并清楚可见；
- 停止按钮使用图标 + 文字，不做孤立灰色裸文字；
- 思考摘要与标题有明确字重差；
- 计时数字使用 tabular-nums；
- shimmer 只属于正在思考的真实活动项；
- 工具进行中、完成、失败不能只靠颜色区分；
- 运行状态变化不得推动对话布局或造成滚动跳动。

### 7.4 完成态

- 最终正文仍是结果主体；
- 工作组折叠为紧凑一行，例如 `已完成 · 42 秒`；
- 不增加重复的重型完成卡；
- 若现有事件已提供产出位置或数量，可在折叠摘要中以次级元信息呈现；
- 不为展示产出摘要新增业务字段或推导逻辑；
- 结果路径使用等宽视觉和复制能力；只有已有可靠导航能力时才可点击。

### 7.5 决策卡

- 一次只强调一个推荐主操作；
- 其他允许方式为次按钮；
- 拒绝使用危险语义，但不与推荐操作竞争；
- 长路径中间截断，并支持完整查看或复制；
- 卡片是独立决策对象，可使用细边界、左侧语义条和 16–20px 内边距；
- 极端危险确认继续遵守现有精确输入契约。

### 7.6 错误卡

主层只包含：

- 用户能理解的错误事实；
- 造成的直接后果；
- 一个明确恢复操作；
- 必要的设置入口或重试入口。

错误码、命令、退出码、堆栈和原始响应进入折叠详情，并支持复制。鉴权/配置错误不自动重试；网络重试只显示简短事实和计数。

技术详情不能占据错误卡标题层，也不能完全隐藏到用户无法提供诊断信息。

### 7.7 Composer

- 保持稳定三行，不随单行输入缩成另一种组件；
- 输入区和底部工具栏共用一个命令台外框；
- 聚焦只改变边界和焦点环，不改变尺寸；
- 模型、权限和思考强度是紧凑控件，状态文字必须达到可读对比度；
- “未配置”必须有警告语义；
- 发送按钮有发送、提交中、不可用状态，尺寸不变；
- 斜杠菜单锚定 Composer，支持完整键盘操作；
- 390px 下底部工具不与发送按钮互相挤压或遮挡。

Composer 可以有轻边界和克制阴影。模糊只用于表达浮于内容之上的命令台，不作为装饰；减少透明度偏好下改为实色表面。

### 7.8 右侧项目面板内容

- Tab 使用统一分段语言，深色模式不得出现纯白选中胶囊；
- 章节行优先展示标题、状态和必要元信息，修复两字竖排和半字截断；
- 模型 KV 信息明确区分 label 与 value；
- 资料区使用两行稳定布局，不将多个输入和按钮挤在一行；
- 成本总额是主要信息，明细是次级信息；
- 记忆区正确渲染 Markdown，不暴露 `#`、`-` 等源码符号；
- 长列表使用行和分组，不把每条记录做成浮动卡片。

### 7.9 阅读器

- 保留现有正文排印优势；
- 阅读器正文 17px、行高 1.9–2.0、宽度 720–800px；
- 工具条按钮尺寸、图标和热区统一；
- 两字操作保持横排，禁止被挤成单字列；
- A−/A+ 使用稳定分段控件；
- 沉浸模式不把正文扩展到超长行；
- 深色正文单独校准，不使用低对比灰字。

### 7.10 设置

- 保持大型设置弹窗；
- 固定左侧导航，右侧内容独立滚动；
- 左侧导航使用与主侧栏一致的选中语言；
- 设置分组优先使用标题、间距和分隔线，不默认卡片化；
- 高级选项渐进展开；
- 标签始终可见，说明文字置于第二行；
- 数字字段使用与内容相称的宽度；
- 模型错误使用通栏告警，不允许在窄屏压成单字列；
- API Key 眼睛按钮位于输入框右侧稳定热区；
- “更改即时生效”是状态文字，不伪装成主按钮；
- 删除、归档等危险操作在视觉和空间上与普通操作分离。

### 7.11 菜单、计划和版本面板

- 下拉层锚定触发器，进入时不改变底层布局；
- 点击外部、Escape 和再次点击触发器均可关闭；
- 关闭后焦点返回触发器；
- 内容过长时内部滚动，底部内容不被 footer 遮挡；
- 计划展开态与折叠态必须在真实点击路径中可见；
- 版本面板空态、列表和恢复确认使用统一弹层语言；
- 不通过截图采集脚本是否成功判断产品功能是否存在。

## 8. 文案规范

文案语气：简短、客观、直接，不拟人化。

每条状态或错误优先回答：

1. 发生了什么；
2. 用户现在能做什么。

规则：

- 正常状态以 2–6 个字为主；
- 不增加营销文案、教学长句或示例问题；
- 不使用“别担心”“我正在努力”等安慰式拟人表达；
- 不在主界面暴露内部架构名词；
- 成功通常由控件自身状态表达，不弹 Toast；
- 错误文案不说教，只陈述事实、后果和恢复路径；
- 状态不可仅靠颜色表达，配合文字、图标或形态。

现有对话规格书中的文案禁止项继续有效。

## 9. 无障碍与稳定性

### 9.1 必须满足

- 普通正文对比度至少 4.5:1；
- 大文字和必要 UI 图形至少 3:1；
- 键盘 Tab 顺序与视觉顺序一致；
- 所有核心功能可由键盘完成；
- 自定义按钮、菜单、Tab、展开项具有正确角色和状态；
- 图标按钮具有可访问名称；
- focus-visible 清楚可见，不因美化移除；
- 弹窗和菜单关闭后焦点返回合理位置；
- 错误、Toast 和异步状态使用合适的 live region，且不抢焦点；
- 支持减少动态、减少透明度和更高对比度偏好；
- Windows 100%、125%、150% 缩放下无文字裁切和控件重叠。

### 9.2 长内容稳定性

必须考虑：

- 长项目名；
- 长会话标题；
- 长模型名；
- 长文件路径；
- 长错误信息；
- 中英文、数字、标点混排；
- 字体回退后宽度变化；
- 文字放大后的多行布局。

优先使用稳定的 flex/grid 轨道、`min-width: 0`、`overflow-wrap`、`white-space: nowrap` 和明确的省略策略，不使用硬编码字符数量猜测宽度。

## 10. 实现边界

执行时允许：

- 调整 CSS 和现有语义令牌；
- 为布局、热区、键盘操作和无障碍调整 DOM；
- 提取现有重复样式为共享令牌或已有模式；
- 修正因 z-index、overflow、pointer-events、拖拽区或响应式规则造成的不可见/不可点；
- 更新与旧视觉绑定的确定性 DOM/CSS 契约测试；
- 删除被新统一组件语言取代的重复样式。

执行时禁止：

- 修改 Agent 状态机、事件语义、数据所有权或 API 契约；
- 增加新依赖以解决纯 CSS/DOM 问题；
- 新建通用组件框架或主题运行时；
- 为方便实现新增业务字段；
- 顺手重构无关模块；
- 用大面积卡片掩盖信息架构问题；
- 用 JS 测量替代 CSS 原生布局，除非现有交互确实需要；
- 为通过旧视觉测试而保留明显错误的界面。

Ponytail 原则：优先修共享令牌和共同根因，一处修复覆盖所有调用方；避免逐截图打补丁。

## 11. 执行纪律：代码优先，禁止工具试错循环

本轮计划将交给成本更低的执行模型。规格必须让其把 token 和时间优先用于代码，而不是反复探索视觉工具链。

### 11.1 开始实施前

- 一次性读取本规格、现有对话行为规格、相关 CSS/DOM 和测试；
- 先定位共享令牌、共享组件和重复根因；
- 不启动视觉伴侣；
- 不运行截图采集、浏览器自动化目测、像素对比或多模态审图；
- 不为确认颜色而反复启动应用；
- 不安装新工具或依赖。

### 11.2 实施过程中

- 优先完成整个代码批次，再统一验证；
- 不在每改一个组件后运行全量命令；
- 只在修改了非平凡交互逻辑时运行一个最小针对性检查；
- 已知是 Windows 环境，命令使用 PowerShell/npm/Node 的现有项目入口；
- 不在 PowerShell、cmd、Git Bash、WSL 之间反复切换碰运气；
- 命令因环境或 shell 差异失败时，最多进行一次有明确依据的 Windows 兼容修正；
- 第二次仍是环境问题则记录并继续完成可完成的代码，不进入试错循环；
- 不能把视觉采集脚本失败误判为产品代码失败。

### 11.3 完成代码后的确定性验证

代码整体完成后，按顺序各运行一次：

```powershell
npm test
npm run verify:app-shell
npm run verify:desktop-shell
npm run verify:app-clickability
```

规则：

- 功能、DOM、无障碍和真实点击回归仍然必须维护；
- 旧测试若固定了被本规格替换的视觉结构，应更新测试；
- 不运行 `capture-all-ui.cjs`、视觉 acceptance campaign、截图矩阵或像素检查；
- 不为了得到视觉 PASS 反复修改代码；
- 若交付范围包含重新打包并供桌面快捷方式使用，最后再运行一次 `npm run verify:local`；否则不提前运行；
- 验证失败先判断是代码失败还是环境失败，不通过重复换命令掩盖问题。

## 12. 验收方式

### 12.1 自动验收

自动验收只负责确定性事实：

- 测试通过；
- DOM 结构存在；
- 关键控件能被真实点击；
- 菜单、弹窗、抽屉和计划面板能打开与关闭；
- 键盘与焦点行为正确；
- 核心业务行为没有回归；
- 无明显横向溢出、控件重叠或不可点击遮罩。

### 12.2 视觉验收

视觉验收完全由用户在最终成品上人眼完成。

执行模型不负责：

- 截图采集；
- 截图矩阵；
- 像素差异；
- 浏览器或 Playwright 视觉检查；
- 多模态模型审图；
- 根据中间截图进行多轮视觉微调。

用户人眼验收后产生的细节反馈进入后续微调，不阻塞本轮执行模型优先完成全部代码。

执行模型不得声称“视觉验收通过”。它只能报告：代码已按规格实现、确定性验证结果，以及仍待用户人眼确认的视觉项。

## 15. 进入计划阶段的条件

本规格已完成产品方向和设计约束对齐。下一阶段只需编写实施计划，不再重新讨论视觉方向。

实施计划必须：

- 先处理全局令牌和共享根因；
- 再处理 AgentSurface 核心体验；
- 再处理侧栏、抽屉、阅读器、设置和弹层；
- 最后集中处理响应式与确定性回归；
- 将视觉验收明确留给用户；
- 将命令数量、运行时机和失败处理规则写入每个执行阶段；
- 保证便宜执行模型无需自行做产品设计判断。
