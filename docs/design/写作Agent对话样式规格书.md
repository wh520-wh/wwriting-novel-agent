# 写作 Agent 对话样式 · 设计规格书

> 用途：本文件是「小说写作 Agent」聊天界面的完整设计约束，供其他模型 / 开发者 1:1 复刻或扩展该界面时使用。
> 配套高保真原型：`docs/mockups/agent-chat-prototype-v3.html`（单文件，可直接浏览器打开，含五个可播放场景）。

---

## 1. 产品定位

一个**专门用于写小说**的 Agent 对话界面。用户用自然语言下指令（"继续写第 5 章""一口气写完 20 章"），Agent 现场创作。界面必须同时满足两个互相矛盾的需求：

- **过程可见**：用户要看得到思考、工具调用、写作的全过程（正文逐字流式在模型开启流式配置时呈现；默认配置下章节写作走非流式工具调用，正文在完成态呈现、展开全文经磁盘回填）；
- **结果干净**：写作过程不能污染聊天记录，全部完成后只留一个可随时展开的干净结果。

核心设计原则一句话：**「折叠态即终态」——历史消息长什么样，当前这轮写完就必须变成什么样。**

---

## 2. 设计原则（约束级）

| # | 原则 | 说明 |
|---|------|------|
| P1 | 过程可见但不占位 | 思考、工具调用实时可见，正文在流式配置下逐字可见；任何已完成的过程单元**立即折叠**，绝不让过程占满窗口 |
| P2 | 折叠粒度 = 创作单元 | 每写完一章，该章立刻收成一个文字标记；段落级折叠依赖流式正文（默认非流式配置不可达）；长篇任务时标记成排排列 |
| P3 | 终态只有一张卡片 | 一轮结束后，思考 + 工具 + 所有段落圆片**整体消失**，替换为一张「完成卡片」 |
| P4 | 错误显性化分级 | 可恢复错误（网络）→ 琥珀色过程态 + 自动重试；不可恢复错误（配置/鉴权）→ 红色错误态，**绝不自动重试** |
| P5 | 正文是神圣的 | 正文用衬线字体、宽松行距；任何 UI 元素（圆片、卡片、状态行）不得与正文混排 |
| P6 | 无头像、无署名行 | 写作 Agent 对话中 Agent 消息不带头像、不带署名行，直接以内容开始（2026-08-03 决定：去掉署名行）。已覆盖当前轮 / greeting / 旁路问答气泡；chat 过程占位与错误气泡、重载后历史轮旧式渲染暂仍带头像，待后续迭代迁移 |

---

## 3. 整体布局

```
┌─ 窗口（mac 三圆点 + 《书名》· 章节标题 + 右侧保存状态小字）─┐
│                                                              │
│  [历史轮 1]  用户气泡（右侧）                                  │
│              Agent 完成卡片（折叠终态，可展开）                  │
│  [历史轮 2]  用户气泡                                        │
│              Agent 完成卡片                                   │
│  [当前轮]    用户气泡                                        │
│              Agent 一轮（过程区 + 结果区，见第 4 节）            │
└──────────────────────────────────────────────────────────┘
```

- 单列对话流，最大宽度 **680px**，居中。
- 用户消息：右侧气泡，最大宽度 80%。
- Agent 消息：左侧通栏，无气泡底色，内部是垂直堆叠的元素流（间距 8px）。
- 保留 mac 风格窗口装饰（三圆点 #e07b6b / #e0c26b / #7bb27e）。

## 4. Agent 一轮的内部结构（自上而下）

```
思考块          ▶ 思考中…  /  已思考                （无框灰字，可点开）
工具卡片        ✎ 正在撰写 第 N 章             进行中  （无框小字，右侧状态）
状态行插槽      ⚡ 重试行 / ✓ 恢复提示               （仅出错时出现）
流式正文区      衬线逐字输出 + 闪烁光标
章节标记排      📖 第 N 章 · N 字 …                   （每章写完即追加）
错误插槽        ⛔ 红色错误卡片                      （仅失败时出现）
完成卡片        ✓ 标题 / 摘要标记 / 预览 / 展开全文    （终态，初始隐藏，无框）
```

**生命周期**：过程元素逐个出现 → 逐个折叠 → 全部消失 → 完成卡片淡入。一轮结束时，过程区必须为空。

## 5. 组件规格

### 5.1 ~~署名行 `.agent-tag`~~（已废弃）
- 2026-08-03 用户决定：Agent 消息不显示署名行，直接以内容开始。后续小节编号保留，不再占用。

### 5.2 思考块 `.think-block`
- **无背景、无边框、无圆角**（无框样式，跟随定稿原型），13px 灰字（`--text-dim`）。
- 思考内容**逐字流出**，期间头部显示「思考中…」（省略号跳动动画）。
- 思考结束 → 自动合拢，标题变为「已思考」；点击可手动展开/收起，三角箭头旋转 90°。

### 5.3 工具卡片 `.tool-card`
- **无背景、无边框**（无框小字，跟随定稿原型），13px 灰字，最大宽度 82%（**不得通栏**，防止过程元素压迫窗口）。
- 左侧图标（✎），中间实时文案，右侧状态小字。
- 文案格式：`正在撰写 第 N 章`（章节级；引擎 `chapter_completed` 事件仅含章节号，段落粒度「第 N 段 · 共 M 段」与总进度「x/20」无数据源，暂不提供）。
- 状态流转：`进行中` → `完成 ✓ n`（n 为已完成章节数）；失败中断时 → `已中断`（红色）。

### 5.4 流式正文 `.para`
- **衬线字体**（Noto Serif SC / STSong / SimSun），15px，行高 2.0–2.1。
- 逐字出现，末尾跟 2px 宽闪烁竖线光标（`--accent` 色，1s 周期）。
- 写完 → 0.38s 高度折叠动画（max-height → 0，opacity → 0）→ 移除，追加段落圆片。

### 5.5 段落圆片 `.p-chip`
- **无框文字标记**（无底无胶囊），12px 灰字：`📖 第 6 章 · 72 字`（段落级 `✎ 第 1 段 · 98 字` 形态仅在流式配置下可达）。
- 点击 → 在标记排下方展开该段全文预览（再次点击收起）。
- 未完成的残段：虚线边框 + 琥珀色文字 + 标注「（未完成）」。

### 5.6 完成卡片 `.done-card`（终态，核心组件）
- **无卡片、无边框**（仅 `overflow: hidden` 容器，跟随定稿原型），淡入 + 上移入场（0.45s）。
- **折叠态**只显示三行：
  1. 头部：`✓`（强调色圆形图标）+ 章节标题 + 右侧「展开 ⌄」；
  2. 摘要标记行：`🧠 已思考` `✎ 撰写 N 章` `xxx 字`；
  3. 一句衬线灰色预览（正文前 24 字 + ……）。
- **展开态**：虚线分隔后依次显示「思考过程」小节（无底色小字）+ 完整正文（衬线，pre-wrap，保留章节标题行）。默认非流式配置下展开全文经 `/api/chapters/read` 从磁盘回填。
- 字数必须由 JS 从正文实时统计（去掉空白后的字符数），**禁止写死**。
- 历史消息中的每一轮，都是该组件的折叠态（目标态；页面重载后历史轮暂走旧式 `.msg-agent` 渲染——步骤时间线 + 章节卡，折叠终态迁移为后续迭代目标）。

### 5.7 重试状态行 `.retry-line`（过程态 · 仅网络错误）
- 琥珀色系：**无底无边框**（无框样式，跟随定稿原型），文字用 `--retry-text`（`--retry-bg` / `--retry-border` 仅定义未使用）。
- 左侧 8px 脉动圆点，文案：`⚡ 网络波动，正在自动重试 n/5 …`，n 每次尝试 +1。
- 出现在状态行插槽（工具卡片与正文区之间），最大宽度 82%。

### 5.8 恢复提示 `.recover-line`
- 绿色 12px 小字：`✓ 连接已恢复（第 n 次重试成功），从断点继续写作`。
- 显示后写作从**断点**继续，已写内容不得重写。
- （前端已按此实现；引擎 `status_message` 恢复文案发送源待接入。）

### 5.9 错误卡片 `.msg-error`（错误态 · 红色）
- 红色系：低饱和红底 `--err-bg`（无边框）、标题 `--err-text`；`--err-border` 用于卡片内按钮/徽章描边。
- 结构：头部 + 正文 + （可选）提示行 + 操作按钮：
  1. 头部：`⛔` + 错误标题 + 右侧时间戳（HH:MM:SS）；
  2. 正文：人类可读的错误说明 + 等宽字体的错误码徽章 `.e-code`（如 `401 Unauthorized · invalid_api_key`）；
  3. 提示行（**可选**）：只放用户需要知道的**后果**（如"已保留当前进度"），空则整行不渲染。**禁止**出现策略性解释文案（如"不会自动重试——重试没有意义"），那是内部逻辑，对用户是噪音；
  4. 操作按钮：胶囊小按钮（如 `↻ 重试` / `↻ 继续写作` / `打开设置` / `复制错误详情`）。手动「↻ 重试」在所有错误卡上都提供。

## 6. 状态机与错误分级（最重要的行为约束）

### 6.1 正常流（正确态）

```
用户指令 → 思考流式展开 → 思考合拢
        → 循环[工具卡片报进度 → 章节写作 → 章节折叠成文字标记]
        → 全部完成 → 过程整体消失 → 完成卡片淡入（终态）
```

### 6.2 网络错误流（可恢复）

```
写作中网络中断
  → 正文暂停（保留已流出的残段）
  → 琥珀色状态行：重试中 1/5 → 2/5 → … （上限 5 次，计数实时可见；重试节奏由引擎指数退避控制）
  ├─ 第 n 次成功 → 绿色恢复提示 → 从断点继续写作（不重写）→ 回到正常流
  └─ 5 次全败 → 残段折叠为「（未完成）」文字标记（虚线边框 + 琥珀色）
              → 工具卡片状态变红「已中断」
              → 红色错误卡片：`写作任务失败 · ProviderTransportError` / 徽章 `timeout`
              → 提示「已保留当前进度」，提供「↻ 重试」「↻ 继续写作」「复制错误详情」按钮
```

### 6.3 配置/鉴权错误流（不可恢复）

```
请求发出 → 服务端立即拒绝（401/403/invalid_api_key 等）
  → 不进入任何写作过程，不显示思考块
  → 约 1s 后直接弹出红色错误卡片（正文说明问题与修正入口，不解释重试策略）
  → 卡片上提供手动「↻ 重试」按钮，用户可自行再试
```

**硬性规则**：
- R1：自动重试上限固定 **5 次**，计数必须实时可见（n/5）。
- R2：4xx 鉴权/配置类错误**一律不重试**，直接红卡。重试无意义的错误不允许出现"自动重试"文案。
- R3：任何失败都必须保留已写内容，并提供断点续写入口。
- R4：错误一律用红色卡片呈现，**禁止**用"已自动重试后继续，内容没有丢失"这类含糊的黄色提示代替明确的报错。
- R5：重试中和恢复提示属于过程态，任务最终成功时随过程区一起清理。

> 注：实现沿用既有「纸感书房」主题令牌（亮/暗自动翻转），值映射自上方色板而非逐字 hex；`--think-bg` / `--tool-bg` / `--chip-bg` / `--retry-bg` / `--retry-border` 在无框样式下仅定义未使用，保留定义供主题体系延续。

### 7.2 字体

- UI 文字：`PingFang SC / Microsoft YaHei`，无衬线。
- **小说正文/预览**：衬线 `Noto Serif SC / Source Han Serif SC / STSong / SimSun`，15px，行高 ≥ 2.0。
- 错误码：等宽 `ui-monospace / Consolas`。

### 7.3 圆角与间距

- 窗口 16px / 错误卡片 12px / 按钮 999px 胶囊。完成卡片、思考块、工具卡片、状态行、圆片均为无框样式，不适用圆角。
- Agent 一轮内部元素垂直间距 8px；轮与轮之间 18px；对话区内边距 22px 20px 20px。
- 窗口阴影：`0 10px 34px rgba(90,70,40,0.10)`（暖色调阴影）。

### 7.4 动效

| 动效 | 参数 |
|------|------|
| 正文流式 | 短篇 20ms/字，长篇批量任务 12ms/字，思考 22–26ms/字 |
| 段落折叠 | max-height 600→0 + 透明度，0.38s ease |
| 完成卡片入场 | 透明度 + 上移 8px，0.45s ease |
| 圆片出现 | 透明度 + 上移 4px，0.25s ease |
| 完成卡片展开 | max-height 过渡 0.45s ease，箭头旋转 180° |
| 光标闪烁 | 1s steps(1) |
| 重试圆点脉动 | 1s ease 无限（透明度 .25 + 缩放 .75） |
| 思考省略号 | 1.2s steps(3) 宽度动画 |

## 8. 文案规范

- **进度文案**：`正在撰写 第 N 章`（章节级；段落粒度「第 N 段 · 共 M 段」与总进度「x/20」因引擎无数据源暂不提供）。
- **重试文案**：`⚡ 网络波动，正在自动重试 n/5 …`。
- **恢复文案**：`✓ 连接已恢复（第 n 次重试成功），从断点继续写作`。
- **错误标题**：`错误类型 · 关键信息`，如鉴权/配置类 `模型调用失败 · 401`、网络/超时类 `写作任务失败 · ProviderTransportError`（徽章 `timeout`）。
- **错误正文**：先讲人话（发生了什么、用户能做什么），再给 `.e-code` 错误码徽章。
- **错误提示行**（可选）：只写用户需要知道的**后果**（如"已保留当前进度"）；空则不渲染。禁止策略性解释文案（如"不会自动重试——重试没有意义"）。
- 禁止：含糊其辞的安慰式文案；策略性说教文案；技术黑话直接怼用户（错误码只能出现在徽章里）。

## 10. 给其他模型的实现约束（Checklist）

1. 单文件 HTML，原生 HTML/CSS/JS，零依赖，浏览器直接打开可运行。
2. 所有场景共用同一套组件与 DOM 插槽，只换数据与流程，**不允许为不同场景复制不同样式**。
3. 字数、预览句一律从正文数据实时计算。
4. 播放中禁用所有场景按钮；重置按钮可随时中断播放并清空演示区。
5. 段落圆片必须可点开偷看原文；完成卡片必须可展开看全文。
6. 新增错误类型时：先按第 6 节分级（可恢复 / 不可恢复），可恢复走琥珀色过程态，不可恢复走红卡，不允许发明第三种颜色。
7. 保持配色令牌不变；新组件颜色必须从色板派生且保持低饱和。
8. 正文区域永远衬线、永远不被 UI 元素打断；UI 元素永远无衬线。
