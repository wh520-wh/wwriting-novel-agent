# WWriting 模型配置供应商两级重构规格草案（详细版）

> 状态：需求已对齐（2026-08-11），已吸收两轮独立对抗式审查结论（子代理核验）+ 用户 5 轮共 20 问拍板，作为下一轮实施计划的规格基线。本文件只记录需求、数据契约、接口契约与验收要点，不修改核心代码。
> 范围：模型配置存储层彻底重构 + 设置页面重做 + 连接测试超时误报（B3/B6）顺手修复 + 应用单实例防多开。
> 参考：外部参考设计 `docs/research/2026-08-11-model-config-provider-based-architecture-reference.md`（不要求完全复刻，本文档是采纳取舍后的正式规格）。
> 待审查：§17「待审查复议项」清单中的条目，在实施计划对抗式审查时重新权衡。

## 1. 已确认目标

现有模型配置的底层逻辑存在结构性缺陷：扁平的单层模型清单、项目内保存完整模型快照并靠 model_name 字符串匹配做写回同步、密钥/配置多轨并存、`stage_overrides` 冗余维度（经审查确认其在运行时从未真正接线）。修补无法解决，本次彻底重构存储层与设置页面。

重构后：

- **全局清单是唯一真源**；项目只存模型引用（供应商编号 + 模型编号），使用前实时解析。
- 全局修改模型设置，**引用它的所有项目自动跟着变**（保留现有产品行为，但删掉写回同步机制）。
- 供应商 → 模型两级结构；供应商可整体启停，模型可单独启停；**停用即不能用**（与删除同语义，引用项目打开时换默认 + 提示）；数量无上限。
- 用户端**任何位置不出现 mock**（含老项目迁移路径）；未配置默认模型时是明确的「未配置」状态，聊天框提供配置入口。
- 应用**单实例防多开**，双窗口并发写场景从源头消除。

## 2. 范围与边界

**本轮做**：存储层（schema v1 → v2 两级结构）、设置页面重做（供应商管理界面）、对话模型选择器联动、引用解析收进最底层、旧数据自动迁移、DeepSeek/MiMo 预设、`[1m]` 标记约定保留、mock 用户面清除、stage_overrides 删除、B3/B6 连接测试修复、应用单实例防多开。

**本轮不做**（详见 §16）：其他协议适配器实现、内置供应商目录扩展、成本面板价格显示修复（M3/M4）、网关/密钥层其余 bug（B4/B16/B5/R5-16）、参考设计进阶功能（排序/导入导出/统计/额度/高级配置/筛选）。

## 3. 目标数据模型（schema v2）

存储文件沿用 `~/.wwriting/model-profiles.json`，`schema_version: 2`。**所有写入收敛到单一写入口，加互斥**（现状 upsert 是无锁读-改-写整包覆盖，见 `src/core/local-model-profiles.mjs:16-33`）；应用层另加单实例锁（§14），双窗口并发写从源头消除，存储层互斥保留作纵深防御。

### 3.2 字段定义

#### 供应商（ModelProvider）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✓ | 内部固定编号，创建时确定，**不可改**。预设固定 `deepseek`/`mimo`；自定义创建时生成（如 `pv_<16位随机hex>`）。 |
| `name` | string | ✓ | 显示名，可改；不允许重名（迁移冲突自动加后缀 `（2）`）。 |
| `type` | `"custom" \| "builtin"` | ✓ | 本轮全部为 `custom`；`builtin` 仅预留。 |
| `status` | `"enabled" \| "disabled"` | ✓ | 启停；`disabled` 时其下模型不出现在任何选择列表，**引用它的项目打开时按悬空处理**。 |
| `base_url` | string | ✓ | API 基地址（HTTP/HTTPS，去尾斜杠）。 |
| `api_format` | string | ✓ | 协议枚举，本轮仅 `openai-chat-completions`（校验见 §8）。 |
| `api_key_env` | string | ✓ | 密钥环境变量名（密钥只落 `secrets.json` 与进程 env，绝不进项目文件/配置）。 |
| `models` | `ModelItem[]` | ✓ | 下属模型列表，可空。 |
| `created_at` / `updated_at` | ISO string | ✓ | 时间戳。 |

#### 模型（ModelItem）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✓ | 供应商内唯一，创建时确定，**不可改**（如 `m_<16位随机hex>`）。 |
| `model_name` | string | ✓ | 模型名，可改（传输名，不断引用）。**可带 `[1m]`/`[1M]` 尾部标记**：显示保留、发送剥离（沿用「统一 Journal 规格」§3.1 约定）。 |
| `enabled` | boolean | ✓ | 启停；`false` 时不出现在任何选择列表，引用它的项目按悬空处理。默认 `true`。 |
| `context_window` | number | ✗ | 有效上下文窗口 tokens（承接 `max_context_tokens` 语义；与「统一 Journal 规格」`effective_context_window` 口径对齐）。**未填或未带 `[1m]` 标记默认 256000**。 |
| `max_output_tokens` | number | ✗ | 单次最大输出。 |
| `timeout_ms` | number | ✗ | 请求空闲超时。 |
| `total_deadline_ms` | number | ✗ | 总期限。 |
| `temperature` | number | ✗ | 0–2。 |
| `stream` | boolean | ✗ | 流式开关（承接现状）。 |
| `cache_mode` | string | ✗ | 缓存模式（承接现状）。 |
| `pricing` | object | ✗ | 每百万 token 输入/输出/缓存命中价（承接现状；成本面板消费问题不在本轮）。 |

**全局默认模型**：顶层 `default_model: { provider_id, model_id }` 是唯一权威；模型行内**不存** `is_default`（UI 由顶层指针推导显示「默认」标记）。同一时刻至多一个默认。

**不设 `display_name`**（界面显示即 `model_name` 本身）；**不设 `tags`**（用户明确不做标签功能，上下文表示沿用 `[1m]` 标记约定）。

### 3.3 编号规则与身份

- 显式稳定 id：创建时分配、终身不变；改名、改地址、改密钥变量名均不变。项目引用因此永不在正常编辑路径下失效。
- 模型身份 = `provider_id + model_id`（引用键）；模型名与身份解耦。
- `provider === "mock"` 永不入清单（保留 `local-model-profiles.mjs:110` 的拒绝逻辑）。
- 清单损坏（JSON 读不了）：当空清单重建 + 启动时提示一声，不阻塞应用。

## 4. 身份、引用与解析

### 4.1 项目侧引用形态

- 项目（workspace settings / 迁移后的 project.yaml）的 `active_model` 落为：`{ provider_id, model_id }`。
- 例外（字面配置）：不在全局清单内的模型（旧项目未能匹配的模型、迁移前的快照）保留完整字段配置。**mock 除外**——旧 mock 快照迁移时显式归零为「未配置」（§6）。
- 删除 stage_overrides 后（§12），项目内只有一个有效模型引用。

### 4.2 解析（收进最底层）

- **解析收进 `loadEffectiveWorkspaceConfig`**（`src/core/config-runtime.mjs:51`）：签名新增全局模型库依赖（secretsRoot / 解析器），返回 `active_model` 前完成「引用 → 完整配置」解析。
- 全库 7 个调用点（app-server / app-dashboard / project-routes / settings-routes）拿到解析后的完整对象，**任何入口不泄漏 `{provider_id, model_id}` 到前端**。config-runtime 从纯合并模块变为依赖全局清单，耦合面纳入计划评审（§17-6）。
- **解析顺序必须先于现有兜底**：`app-server.mjs:220` 的守卫 `typeof provider !== "string"` 会把合法引用误判为「未配置」，改为「先解析引用 → 解析失败才进入未配置/降级分支」。
- **解析结果携带 `resolution_note`**：解析失败（引用悬空 / 引用被停用）时降级为全局默认模型，结果对象附 `resolution_note`（如「原模型已不存在，已换成默认模型 XX」），经 dashboard 响应透出，前端**弹一次 toast**，不常驻、不阻塞。
- **无默认模型**：保持「未配置」（`active_model: null`）；**聊天框模型指示显示「未配置」，点击弹模型选择器**（选择器即配置入口）；绝不回落到 mock。

## 6. 旧数据迁移

### 6.1 触发与透明度

- 触发路径：`POST /api/projects/open` 打开项目时，**以及启动时自动恢复的项目**（`src/core/app-server.mjs:82-89`，现状不经过 open，必须同样迁移，否则长期持有陈旧快照）。
- 迁移完成后弹一条 toast「旧配置已升级」，不事前确认、不打断。
- 迁移确定性、幂等（重复触发不重复改写）、有测试覆盖；「读路径写盘」仅此一次性迁移场景。

### 6.2 项目文件迁移（快照 → 引用）

1. 读取项目 `active_model`；
2. 旧 `provider === "mock"` → 归零为 `active_model: null`（未配置），结束；
3. 能按身份（provider + base_url + model_name）匹配到 v2 清单条目 → 写为 `{ provider_id, model_id }`；
4. 匹配不到 → 保留原字面配置；
5. `stage_overrides` 数据直接丢弃（§12）；
6. 迁移与既有 workspace 迁移逻辑的冲突处理：`src/core/workspaces/migration.mjs` 的 `legacyActiveModel`（:257-262，要求 model_name 非空）与 `verifySettingsReReadable`（:306-313，断言 model_name 一致）不识别引用形态，改为按 `provider_id/model_id` 校验或跳过。

### 6.3 全局清单迁移（v1 → v2）

1. 读 v1 存储；读不了 → 按空清单走，重建后提示；
2. 按身份（provider + 规范化 base_url）分组旧条目；
3. **匹配官方预设**（base_url 命中 DeepSeek/MiMo 官方地址）→ 并入预设供应商：预设不存在则先种子（§7）；旧模型挂进预设，**用户已有模型参数原样保留**，按 `model_name` 去重（同名的保留最新）；
4. 匹配不上 → 各自独立成新供应商：`name` 取 `provider_label`（无则 `provider`），重名自动加后缀；每个旧条目转为一个模型；
5. 旧 `provider: "openai-compatible"` → `api_format: "openai-chat-completions"`；
6. 全局默认指针：v1 `default_model_id` 映射到新模型 id；映射不到取清单第一个；
7. 分配新固定 id（预设条目保持固定 id，其余新生成）；
8. 删除 24 条上限逻辑；
9. 写锁保护下原子写入 v2。

### 6.4 预设种子

「**清单中无预设 id 才写入**」（不是「文件不存在」），否则用户删除过的预设会复活。种子写入同样走唯一写入口。

## 7. 预设（DeepSeek / MiMo）

- 预填好的普通供应商（`type: "custom"`）：**可改、可删，编号固定**（`deepseek` / `mimo`）。删除后不自动复活（§6.4）。
- DeepSeek 预设：`base_url: https://api.deepseek.com`，`api_key_env: DEEPSEEK_API_KEY`，模型 `deepseek-v4-pro`、`deepseek-v4-flash`，价格按 `OFFICIAL_PRICING` 预填。
- MiMo 预设：`base_url: https://api.xiaomimimo.com/v1`，`api_key_env: XIAOMI_MIMO_API_KEY`，模型 `mimo-v2.5-pro`、`mimo-v2.5`，价格按 `OFFICIAL_PRICING` 预填。
- 预设种子数据由代码内置目录提供（仅这两个）。价格：`deepseek-v4-pro`（3.0/6.0/0.025）、`deepseek-v4-flash`（1.0/2.0/0.02）、`mimo-v2.5-pro`（3.0/6.0/0.025）、`mimo-v2.5`（1.0/2.0/0.02），单位 CNY/百万 token（`src/shared/official-pricing.mjs:5-11`）。

## 8. API 接口协议

- 术语：**API 接口协议**（不叫「OpenAI 兼容」）。
- 表单下拉 4 项：`openai-chat-completions`（**本轮唯一可选项/可用项**）、`anthropic-messages` / `openai-responses` / `gemini-generate-content`（灰色占位，不可选）。
- **校验落点**：v2 store 归一化 + 保存路由拒绝白名单外的 `api_format`；v1 迁移补默认 `openai-chat-completions`。现状 `validateModelConfig`（`src/core/model-config-validation.mjs:13-76`）与 `normalizeModelProfile`（`local-model-profiles.mjs:105-136`）均不认识该字段，需新增。
- **地址拼接**：`base_url` 存基地址，端点路径由 `api_format` 派生——chat-completions → 追加 `/chat/completions`（沿用现有 openai-compatible 适配行为）。不得把协议写死在 base_url 拼接逻辑外；为将来协议（如 `/v1/messages`）留派生点。
- 本轮只实现 chat-completions 一个协议；其余协议值只存在于下拉占位，数据层不允许保存。

## 9. 设置页面（重做）

页面为**自动保存**（改动即存），**不设顶部刷新按钮**。总体：左侧供应商列表 + 右侧详情。

### 9.1 左侧供应商列表

- 供应商条目：图标 + 名称 + 状态点（启用绿/禁用灰）；选中高亮。
- **不设「内置/自定义」分组小标题**，全部平铺（顶部一个「我的供应商」标题；分组结构为将来预留）。
- 底部「+ 添加供应商」：新建空白供应商并选中，引导填基础连接。

### 9.2 右侧详情

- **头部**：供应商名内联改名（铅笔 → 输入框 → 失焦保存）；「已启用/已禁用」标签；启停切换按钮；删除按钮（**二次确认**，确认文案说明会连带删除其下所有模型）。
- **基础连接**：Base URL 输入框（失焦保存，校验 HTTP/HTTPS）；API 接口协议下拉（4 项，3 项灰色禁用）；密钥输入框（**掩码 + 眼睛切换**；支持直接粘贴密钥或填环境变量名；明文不回显，查看点眼睛）。
- **模型列表**：
  - 模型区顶部：「+ 添加模型」与「拉取模型」相邻。
  - 「拉取模型」：**前置检查**——未填地址/密钥先提示「请先填写接口地址和 API 密钥」，不发请求；已填则外呼厂商 `GET /models`（经应用中转端点），成功后在新建模型区**展开候选列表**，每个候选可点「添加」（逐个加，不自动全量导入）；失败行内显示具体错误（地址不通/密钥错误等）。
  - 拉取到的候选默认参数：上下文窗口 256000（除非名带 `[1m]` 标记）、价格查 `OFFICIAL_PRICING` 有则自动带、`enabled: true`。
  - 模型条目：模型名（可改，含 `[1m]` 标记）、启停开关、「设为默认」（设后全局生效，条目显示「默认」标记）、测试连接、删除（**同样二次确认**）。
  - **测试连接**：结果在条目旁**行内显示**（成功绿勾 / 失败红字错误），不弹 toast。

### 9.3 页面数据源与后端契约（端点草案）

新增/改造端点（遵循现有 `src/core/http/` 路由风格；具体形状在实施计划冻结）：

| 方法/路径 | 职责 |
|---|---|
| `GET /api/settings/providers` | 全量供应商 + 模型 + 默认指针（含密钥环境变量名，不含密钥值） |
| `POST /api/settings/providers` | 新建供应商 |
| `PATCH /api/settings/providers/:id` | 改供应商（name/status/base_url/api_format/api_key_env） |
| `DELETE /api/settings/providers/:id` | 删供应商（连带模型） |
| `POST /api/settings/providers/:id/models` | 新增模型（含拉取选中的候选） |
| `PATCH /api/settings/providers/:id/models/:modelId` | 改模型（model_name/enabled/参数/价格） |
