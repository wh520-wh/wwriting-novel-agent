# 第一部分：UI 一致性收敛（第一批）

## 1. 本轮目标

第十轮确立了全应用视觉体系，但落地后留下了**不一致**与**未兑现的承诺**两类问题。本轮只做收敛，不改产品形态、不改信息架构、不动业务流程。

目标一句话：

> 让已经存在的设计系统真正生效，删除一处已废弃的功能（隐私模式），并清理散落的实现债。

本轮明确**不是**：换皮、改版式、新增组件、重构动效框架、引入任何新依赖。（对齐决议：隐私模式为纯删除，不受"不改产品形态"约束。）

---

## 2. 范围

### 2.1 本轮包含（第一批）

按影响力排序的四项：

1. **删除废弃功能**：隐私模式整体删除（对齐决议：原"修复覆盖范围"方案废弃，见 §3.1）；暗色主题下硬编码颜色收敛；死代码/死引用清理。
2. **统一按钮基元**：收敛当前 6+ 套平行按钮实现。
3. **让设计 token 真正生效**：字阶、字重、圆角、阴影四类令牌的归并。
4. **顺手清理死代码**：零引用的 CSS 选择器与被隐藏但仍被 JS 写入的元素。

### 2.2 本轮明确不做

- 动效单轨化（CSS transition 与 `motion-runtime.js` 的双轨问题留待第二批）；
- 间距体系全面 token 化（27 个像素值的收敛留待第二批）;
- 任何新增功能、新增依赖、布局重构、文案改写；
- 浅色主题的配色体系调整（品牌色、中性色盘不动）。

## 3. 问题清单与验收标准

以下每条都给出**现状证据**与**期望结果**。解决方案给出推荐方向，但不作为唯一合法实现；实现方若有同等或更小的改动，可在评审时替换，但不得缩小问题覆盖面。

### 3.1 隐私模式整体删除（对齐决议：废弃该功能，优先级最高）

> 对齐决议：原稿方案是"补齐模糊覆盖面使文案与实际一致"；经讨论判定该功能修复价值低于维护成本，**整体删除**。

**删除理由（原现状证据）**：
- 隐私模式开启后，toast 文案声称"正文已模糊"（`src/app-shell/theme-privacy.js:56`），但 `.peek` 模糊只应用于阅读器正文（`src/app-shell/index.html:142`）与章节名等（`src/app-shell/drawer-panels.js:124,293`）；Agent 对话正文完全未覆盖——承诺与实现长期不符，无人在意即无价值。

**删除清单**（2026-08-29 全库核实）：
- `theme-privacy.js`：`setPrivacyMode` / `applyPrivacyState` / `initPrivacyMode`、localStorage 键 `ww:privacy` 与 `ww:privacy:hinted`、首启 toast；文件保留主题（日间/夜间）部分，文件名不改；
- `app.js`：`railRefs.privacyToggle` / `privacyLabel`（:39-40）、隐私切换监听（:534、:566）；
- `app.js:564-565` 的 window blur/focus 监听（写入 `data-away`）：其唯一消费方是隐私模式的失焦加深模糊规则（styles.css:1827），随之删除；
- `index.html`：`#app` 的 `data-privacy="off"`（:22）、隐私菜单项（:89-91）；
- `.peek` 体系：styles.css:1821-1827 全部规则；`index.html:142` 与 `drawer-panels.js:124,293` 的 `peek` class。

**期望结果**：全库 grep `privacy` / `data-privacy` / `peek` / `data-away` 仅剩 `theme-privacy.js` 文件名与注释级提及；应用正常启动，日间/夜间主题切换不受影响。残留的 localStorage 键无害，可顺手 removeItem 也可保留，不做要求。

### 3.2 暗色主题下的硬编码颜色漏网（缺陷）

**现状证据**：
- `rgba(24,32,27,…)` 阴影在 `src/app-shell/agent/agent.css:35,247,404,411` 写死（:35 是 `--agent-shadow` token 的定义本身；agent.css 整体无暗色块），无暗色变体；
- `rgba(28,26,22,…)` 遮罩在 `src/app-shell/styles.css:657,662,671,1025,1592` 写死，无暗色变体；
- 亮色主题的 `::selection` 用了系统蓝 `rgba(58,110,208,0.18)`（`styles.css:271`），与全绿 accent 体系不一致；暗色才换成 accent 绿（`styles.css:209`）；
- `.sw-dot` 恒白 `#fff`（`styles.css:1340`），暗色下是亮斑；
- 勘误（2026-08-29 核实）：`--shadow-xs/sm/--shadow/--shadow-pop` 四个阴影 token 明暗两套定义**已存在**（styles.css:60-63 亮色、200-203 暗色），缺的不是 token 体系，是这 9 处漏网。

**期望结果**：所有颜色都有明暗两套定义，或集中收敛进语义化 token；亮色选中色与品牌绿体系一致。

**对齐决议（2026-08-29）**：采用**色值 token 原地替换**，不新建完整阴影 token：
1. 新增逗号三元组色值 token `--ink-shadow`（阴影基色，亮色 24,32,27 / 暗色纯黑系）与 `--ink-scrim`（遮罩基色，亮色 28,26,22 / 暗色纯黑系），与既有 `--shadow-*` 明暗块放在一起定义；
2. 上述 9 处硬编码原地改为 `rgba(var(--ink-shadow), α)` / `rgba(var(--ink-scrim), α)`，几何参数（偏移/模糊/扩散）一律不动，暗色自动生效；`--agent-shadow` 定义同步改写；
3. `::selection` 亮色改为 accent 派生（`color-mix(in srgb, var(--accent) 18%, transparent)` 或等价写法），暗色已有规则可保留；
4. `.sw-dot` 恒白**刻意保留**（开关旋钮白是平台惯例，暗色下的亮斑是"开"状态的视觉语义），加注释说明，不算漏网。

**现状证据**：

**期望结果**：

**对齐决议（2026-08-29）— 字重**：全部并入既有 4 token（`--weight-regular/medium/semibold/bold` = 400/550/650/700），零新增、零重定义：

# 第二部分：去 AI 腔可度量升级（ai-voice-metrics）

## 一句话

把 `avoid-ai-voice` 从静态禁用清单升级为可度量的风格目标：新增纯函数风格统计模块与只读
`style_stats` 工具（模糊修饰词密度、句长变异系数、三连排比检测），技能改写为「量化阈值 +
审校调用工具的反馈环」，不建任何门禁（ADR 0008）。

## 背景

- 调研输入：`docs/research/2026-08-29-competitive-research-ai-voice.md` P0——禁用清单缺量化
  指标与客观验收信号；「用客观工具统计这些指标而不是让模型自评」；差异化方向是可解释反馈，
  拒绝绕过器路线。P1（事实自检）、P2（检测 API）本轮不做（用户决策 ①）。
- 现状考古：`src/skills/avoid-ai-voice/SKILL.md` 只有五条禁令，frontmatter 里的
  `stage: reviewing` check 是惰性元数据——round14 Task 10 已删钩子运行时
  （`src/core/skills/index.mjs:15`），没有任何程序化检查在跑；`count_text`

## 决策

- **D1 纯函数模块，零运行时分支**（ADR 0008）：`src/core/style-metrics.mjs` 仿
  `word-count.mjs`——纯函数、无 IO、复用其 `stripMarkdownForCount()`（import，不复制）。
  唯一消费入口是 `style_stats` 工具与测试；提交路径、技能运行时、权限政策零改动。
- **D2 三个指标**（只做能确定性算的；段尾总结句、抒情连发等语义级判断留给模型与技能文本）：
  1. **模糊修饰词密度**：词表子串计数（词表见 T1，15 词、扁平无嵌套子串），
     `per_1000 = total / effective_count * 1000`；阈值 cap `5.0`。
  2. **句长变异系数 CV**：visible 文本按 `/[。!?…;?!]+/` 切句（丢弃空段，末尾无标点的残段
     也算一句），句长 = 句内 effective count，`cv = std / mean`；句数 < 3 时 `cv = null`
     不判定；阈值 floor `0.4`。`ponytail:` 朴素切句，不处理英文缩写省略号歧义；对话引号内
     标点会把对白切碎——中文小说语境可接受，天花板待语料基线校准时一并评估。
  3. **三连排比**：句内按 `/[，,、;；:：]+/` 切短句，同一 ≥2 字 CJK 前缀连开 ≥3 个短句
     → 命中（记录 prefix、repeat、excerpt≤40 字截断）；**只列举不判定**——是否刻意修辞由
     模型/作者裁量。`ponytail:` 只抓首字重复型（「握住X，握住Y，握住Z」原型），漏后缀式
     排比与变长首语重复；升级路径是引入词级 n-gram 相似度。
- **D3 阈值单一来源**：常量导出自 `style-metrics.mjs`（`HEDGING_CAP_PER_1000 = 5.0`、
  `SENTENCE_CV_FLOOR = 0.4`），工具结果同时带测量值、阈值与 `over` / `below_floor` 布尔；
  SKILL.md 引用同一数字，改阈值只改模块常量。**v1 值是启发值不是人类基线**（调研
  Limitations 明言需本地语料校准），代码内 `ponytail:` 注释标注此天花板与升级路径。
- **D4 `style_stats` 只读工具，仿 `count_text`**：注册进 `definitions-knowledge.mjs`
  （同域第五个工具），`interruptible: false`，`category: "read"`（项目内自动放行，零新权限
  面）；入参 `path`（工作区内 .md/.txt），复用 `executeCountText` 的路径校验/大小上限/读取
  模式；工具描述明写「参考值不是门禁，不拦截提交」。结果 = D2 JSON + `path` +
  `effective_count`（与 `count_text` 同口径）。
- **D5 工具数量不变量修订**：`tools/index.mjs` 头注释「9 通用 + 6 深 = 15」改
  「10 通用 + 6 深 = 16」；`registerAll` 增 `style_stats` 一行；
  `tests/agent/tools-registry.test.mjs` 的注册数量/顺序断言同步。这是本轮唯一触碰的 core
  既有文件，全部为加行/注释，无行为分支。
- **D6 SKILL.md v2.0.0 重写**：frontmatter 删惰性 `hooks` 块（round14 F8 范围纪律：触碰
  即清，留着误导插件作者）；`description` 更新提及量化阈值与 style_stats。正文三层：
  ① 量化目标（修饰词 ≤5/千字、句长 CV ≥0.4、三连排比零容忍）；② 五条禁令保留为「怎么改」
  的工艺示例；③ 审校反馈环——改稿/审校时对草稿调 `style_stats`，超标句用具体动作与实物
  改写（不是同义词替换），复测至达标；CV 过低靠合并/拆分句子调节奏，不靠加词；**明令禁止
  堆词汇复杂度刷指标**（调研 E9 教训）；刻意修辞豁免——命中但确属刻意排比时，回复中说明
  保留理由，不强行改写。

### analyzeStyleMetrics 返回契约（冻结）

```json
{
  "effective_count": 0,
  "hedging": { "total": 0, "per_1000": 0.0, "cap_per_1000": 5.0, "over": false, "words": {} },
  "sentences": { "count": 0, "mean_length": 0.0, "cv": null, "floor": 0.4, "below_floor": false },
  "parallel": { "count": 0, "hits": [{ "prefix": "握住", "repeat": 3, "excerpt": "…" }] }
}
```

- `per_1000`、`cv` 保留 2 位小数，`mean_length` 1 位；`effective_count = 0` 时
  `per_1000 = 0`、`over = false`。
- `cv = null` 时 `below_floor` 恒为 `false`。
- `words` 为 `{词: 次数}` 直方图（按次数降序、次数同按词序）；总数 = 各词次数之和
  （词表扁平，无重复计数）。
- `parallel.hits[].excerpt` 超 40 字截断加 `…`。
