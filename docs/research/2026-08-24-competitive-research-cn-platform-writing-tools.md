# Competitive Research: 国内平台官方 AI 写作工具 vs WWriting

- 日期：2026-08-24；模式：Rapid（计划 Standard 6 家，实际可深度取证 2 家 + 官方媒体 1 条；其余 3 家官网为无正文 SPA 或连接失败，见 limits）
- 决策问题：面对中文网文平台官方 AI 写作工具（云端、平台绑定、面向签约/全勤场景），WWriting 的"本地优先 + 任意模型 + 数据自有"定位有哪些可感知差异点，哪些能力是中文网文作者的 table stakes。

## Executive Conclusion

国内平台官方工具的形态高度一致：**云端码字应用 + 按钮式 AI 辅助 + 深度绑定自家投稿/稿酬/分发体系** [E1][E3][E9]；AI 能力定位为"辅助"（查资料、续写、润色、一键成文），没有任何一家提供 agent 式自主工作流或本地文件夹模式 [E10]。阅文作家助手已覆盖桌面端并提供云端历史版本 [E1][E2]，说明"全平台 + 版本留存"是国内作者的 table stakes；WPS AI 则代表通用办公写作的模板化路线，与小说创作几乎不重叠 [E5]。WWriting 对这类用户最可感知的差异是：模型可换（平台工具锁自家大模型）、字数不被计量、创作数据在本地而非平台侧 [E9]。明确的 non-goal：WWriting 不做平台投稿、稿酬结算与内容分发集成。

## Current Product Baseline

WWriting（本地桌面，Electron）：ProjectAgent 内核（agent 自主循环 + 章节队列 + 停止恢复）、Journal 事件溯源、ModelGateway（任意 OpenAI 兼容网关，Key 存本机）、SKILL.md 技能体系、WWRITING.md 项目记忆、count_text 字数工具、章节版本快照（200 版/校验和）、可见上下文压缩、权限确认体系、确定性导出（Markdown 成书，不经模型）。

## Cross-Market Patterns

- **Table stakes（国内平台侧）**：全平台覆盖（阅文已含桌面端 [E1]）；历史版本自动留存 [E2]；读者数据/稿酬面板 [E3]；"安全/稳定"的官方背书话术 [E4]。
- **可感知差异点（WWriting）**：模型不锁定（平台工具绑定自家大模型生态）；无字数计量；创作数据物理在本地文件夹 [E9]。
- **共同缺口（平台工具侧）**：无一提供 agent 自主多步工作流、可见计划、断点恢复 [E10]——WWriting 的结构差异点。
- **Non-goal**：不做平台投稿/签约/稿酬集成，不做云端同步——本地优先定位下明确不复制阅文的平台绑定模式 [E3]。

## Prioritized Roadmap

### P0

在 README/官网明确"与平台官方工具的关系"：WWriting 不投稿、不计量、不碰你的稿酬，产出标准 Markdown 可手动发布到任何平台。面向被平台工具锁定感的作者。验收信号：文档含一节与阅文作家助手/百度作家平台的定位差异说明（含数据归属对比）。

### P1

补齐"全平台码字工具"视角下的桌面端版本留存认知：本地版本快照（200 版）已有，缺对外表述与"云端历史版本"的对齐话术 [E2]。验收信号：README 功能列表出现与"历史版本/云端留存"对齐的本地版本快照表述。

### P2

研究国内合规话术（"创作无限 安全有界" [E4]）对个人作者信任的影响，形成 WWriting 的隐私表述（应用私有目录、不联网默认、Key 本机保存）。验收信号：README 隐私小节包含三条以上可验证的本地性声明。
