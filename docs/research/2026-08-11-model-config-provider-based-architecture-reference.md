## 一、模块定位与核心价值

这是一套**自定义大模型供应商统一接入管理系统**，属于AI应用/Agent项目的「底层模型接入基础设施」。

核心目标：通过可视化配置的方式，让用户自助接入任意第三方大模型API，统一管理密钥、接口地址、协议格式、可用模型；上层业务（聊天、Agent推理、工具调用等）无需关心底层厂商差异，通过统一接口即可调用所有模型，实现**模型供应商与业务逻辑完全解耦**。

## 二、页面整体布局结构

页面采用经典的「左侧导航 + 右侧详情」左右分栏布局，整体分为3个功能区域：

### 1. 顶部标题区

- **主标题**：模型设置（页面一级功能入口，明确模块用途）
- **功能说明**：「管理自定义模型供应商，配置后可在聊天时选择使用。」
  - 明确业务闭环：配置完成 → 聊天场景可选对应模型
  - 降低用户理解成本，直述功能价值
- **刷新按钮**（右上角环形箭头）
  - 作用：重新拉取全量供应商配置，重置未保存的修改，或同步后端最新状态
  - 交互：点击后触发全量数据刷新，无感知更新页面内容

### 2. 左侧：供应商导航列表

作用：快速切换不同供应商的配置，同时全局展示所有供应商的启用状态。
采用分组管理，分为两类供应商：

#### 分组1：内置供应商（示例：智谱分类下的 Z.ai）

- 属于系统官方预置的模型服务，用户无需自行配置API地址和密钥
- 仅支持启用/禁用，不支持编辑和删除
- 每项包含：官方图标 + 供应商名称 + 状态指示器

#### 分组2：自定义供应商

用户完全自主添加、编辑、删除的第三方模型服务商，是本模块的核心。

- **列表项结构**（每个供应商条目）：
  1. 通用图标：六边形立方体图标，统一代表自定义供应商
  2. 供应商名称：用户自定义的命名（如 deepseek、MiniMax），用于识别区分不同接入方
  3. 状态指示器（右侧绿色圆点）：代表该供应商当前为「已启用」状态；禁用时变为灰色
  4. 选中态：当前选中的供应商项高亮白底，右侧同步展示其完整配置详情
- **底部操作项**：+ 添加供应商
  - 点击后触发新增流程：创建空白供应商配置，引导用户填写基础连接信息

### 3. 右侧：供应商详情配置区

展示当前选中供应商的完整配置，是核心操作区，从上到下分为「头部操作栏」「基础连接配置」「模型列表管理」三层。

## 三、右侧配置区 字段与逻辑详解

### 1. 头部操作栏

对应供应商的全局状态与生命周期管理：

| 元素 | 作用 | 交互逻辑 |
|------|------|----------|
| 供应商名称 + 铅笔编辑图标 | 展示当前供应商的自定义名称，支持内联修改 | 点击铅笔 → 名称变为输入框 → 失焦自动保存 |
| 「已启用」绿色标签 | 标识供应商当前运行状态 | 状态枚举：`enabled`（启用，绿色）/ `disabled`（禁用，灰色） |
| 「禁用」按钮 | 切换供应商启用状态 | 点击后状态切换为禁用，标签变灰，左侧状态点同步变灰；禁用后按钮文字变为「启用」<br>**业务影响**：禁用后，该供应商下所有模型在聊天/Agent选择列表中隐藏，不可调用 |
| 垃圾桶删除图标（右上角） | 删除整个供应商配置 | 点击后弹出二次确认弹窗 → 确认后删除该供应商及其下所有模型配置，左侧列表同步移除 |

### 2. 基础连接配置（核心）

这是连接第三方API的三大核心参数，决定了「往哪发、按什么格式发、用什么身份发」。

#### (1) Base URL（基础接口地址）

- **含义**：第三方模型API的根路径前缀，所有接口请求都会基于该地址拼接端点路径。
- **示例值**：`https://api.deepseek.com/anthropic`
  - 代表 DeepSeek 提供了兼容 Anthropic 协议的接口端点，前缀指向该兼容路径
- **作用**：
  - 适配不同厂商的API域名
  - 适配同一厂商的不同协议兼容路径（如 OpenAI 兼容路径、Anthropic 兼容路径）
  - 支持用户使用第三方中转/代理API地址
- **输入类型**：单行文本输入框，失焦自动持久化保存

#### (2) API 格式（协议格式选择）

- **核心地位**：这是整个多模型接入系统的灵魂设计，是「协议适配层」的可视化体现。
- **含义**：指定该供应商API遵循的请求/响应协议规范，包括请求端点、请求头、请求体结构、响应格式、流式解析规则。
- **示例选中值**：`Anthropic Messages (/v1/messages)`
- **下拉可选值（行业通用）**：
  - OpenAI Chat Completions (/v1/chat/completions)：最通用的兼容格式，绝大多数开源/商用模型都支持
  - Anthropic Messages (/v1/messages)：Anthropic 官方协议格式
  - Google Gemini 原生格式
  - 通义千问原生格式
  - 其他厂商私有协议格式
- **底层逻辑**：每一个选项对应一套「协议适配器」代码，负责把上层业务的统一请求，转译成对应厂商的请求格式，再把厂商的响应转译成内部统一格式返回。
  - 上层业务永远只调用一套统一的模型接口
  - 新增厂商/格式时，只需新增一个适配器，上层代码零修改

#### (3) API Key（接口密钥）

- **含义**：第三方模型服务商颁发的身份鉴权密钥，用于身份验证、额度计费。
- **输入类型**：密码型输入框，默认掩码显示
- **显隐开关**（右侧眼睛图标）：点击切换明文/掩码显示，兼顾安全与核对需求
- **安全设计**：
  - 前端默认掩码，防止屏幕泄露
  - 后端必须加密存储，禁止明文落库
  - 编辑时支持整体替换，截图方案为支持明文查看，也可设计为不回显完整密钥

### 3. 模型列表管理

管理该供应商下，用户希望使用的具体模型实例。一个供应商可以添加多个模型。

#### 整体结构

- 标题：模型列表
- 模型条目列表：每个条目对应一个具体模型
- 底部「+ 添加模型」按钮：新增空白模型条目

#### 单个模型条目结构（从左到右）

1. **模型名称输入框**
   - 内容：模型的官方标识名（如 `deepseek-v4-pro`），必须与API支持的模型名完全一致，否则请求会报错
   - 支持内联编辑，失焦自动保存
2. **属性标签**（示例：`1M`）
   - 作用：标注模型的核心属性，截图中代表上下文窗口大小为 1M tokens
   - 可扩展：支持标注「高速」「免费」「长文本」等业务标签
3. **操作按钮组**
   - **测试连接按钮**（插头图标）：核心校验功能
     - 点击后，系统使用当前供应商的 Base URL、API Key、该模型名，发起一次极简测试请求（如发送 "ping" 或短对话）
     - 请求成功：提示「配置有效」
     - 请求失败：返回具体错误信息（如密钥错误、模型名不存在、地址不通）
   - **编辑按钮**（铅笔图标）：编辑模型名称、标签等信息
   - **删除按钮**（垃圾桶图标）：删除该单个模型配置，不影响供应商和其他模型

## 四、底层数据模型设计（复刻必看）

### 1. 供应商配置数据结构

建议以 JSON 对象存储，每个供应商对应一条数据：

```typescript
interface ModelProvider {
  id: string;               // 供应商唯一ID
  name: string;             // 显示名称
  type: 'builtin' | 'custom'; // 类型：内置/自定义
  status: 'enabled' | 'disabled'; // 启用状态
  baseUrl: string;          // API 基地址
  apiFormat: string;        // API 协议格式枚举值，如 'openai' | 'anthropic'
  apiKey: string;           // API 密钥（加密存储）
  models: ModelItem[];      // 下属模型列表
  createdAt: number;        // 创建时间戳
  updatedAt: number;        // 更新时间戳
}
```

### 2. 模型条目数据结构

```typescript
interface ModelItem {
  id: string;               // 模型唯一ID
  modelName: string;        // 传给API的官方模型名
  displayName: string;      // 前端显示名称（可与modelName一致）
  tags: string[];           // 标签数组，如 ['1M', '高速']
  contextWindow?: number;   // 上下文窗口大小（数值型，用于业务逻辑判断）
}
```

## 五、核心业务流转逻辑

### 1. 配置保存与加载流程

1. 页面初始化：从本地存储/后端接口拉取全量供应商配置
2. 渲染左侧列表，标记每个供应商的启用状态
3. 默认选中第一个供应商，渲染右侧详情面板
4. 用户修改任意配置项 → 失焦/点击操作 → 自动持久化保存 → 更新本地状态
5. 点击刷新按钮 → 重新拉取全量数据，覆盖本地未保存修改

### 2. 模型调用全链路（上层Agent/聊天的调用逻辑）

这是整个系统的核心价值链路，复刻时必须完整实现：

1. **上层业务发起请求**：Agent/聊天模块调用统一的 `callModel()` 接口，传入统一参数：
   ```typescript
   {
     modelId: "xxx", // 模型唯一ID
     messages: [{ role: "user", content: "你好" }],
     stream: true,
     temperature: 0.7,
     max_tokens: 2048
   }
   ```
2. **路由匹配**：系统根据 modelId 找到所属供应商，拿到 baseUrl、apiFormat、apiKey
3. **协议适配**：根据 `apiFormat` 调用对应的适配器，完成：
   - 拼接最终请求URL：`baseUrl + 对应格式的端点路径`
   - 组装请求头：鉴权头、Content-Type 等
   - 转换请求体：把统一的 messages 等参数，转成对应厂商的请求格式
4. **发起HTTP请求**：同时支持普通响应和流式SSE响应
5. **响应解析**：把厂商返回的结果，解析成内部统一的响应格式
6. **返回上层**：把统一格式的结果返回给Agent/聊天模块

### 3. 协议适配器的设计模式

采用**策略模式**实现，每种格式对应一个策略类：

- 统一接口：`adaptRequest()`、`adaptResponse()`、`adaptStreamChunk()`
- 具体实现：OpenAI适配器、Anthropic适配器、Gemini适配器等
- 优势：新增格式只需新增类，无需修改原有代码，符合开闭原则

## 六、交互细节与设计考量

1. **自动保存**：所有输入框失焦自动保存，无需单独的保存按钮，降低操作成本
2. **状态联动**：供应商禁用 → 下属所有模型自动不可用，无需逐个模型禁用
3. **容错设计**：测试连接功能，让用户配置完立刻验证，避免到业务场景才发现配置错误
4. **权限分层**：内置供应商不可删除编辑，自定义供应商完全可控
5. **安全设计**：API Key默认掩码，兼顾易用性和安全性
6. **扩展性**：API格式的抽象设计，支持未来无限新增厂商协议，上层业务无感知

## 七、可扩展的进阶功能（截图未体现，建议复刻时预留）

1. **一键拉取模型列表**：调用对应厂商的模型列表接口，自动导入所有可用模型，无需手动输入
2. **高级配置项**：请求超时时间、重试次数、代理设置、自定义请求头等
3. **额度/余额查询**：集成厂商余额查询接口，展示剩余可用额度
4. **模型排序**：支持拖拽调整模型和供应商的显示顺序
5. **导入/导出配置**：支持一键导出配置JSON，方便迁移备份
6. **使用统计**：统计每个模型的调用次数、消耗token数
