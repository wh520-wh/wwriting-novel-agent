# WWriting CLI

**版本 0.1.0** —— 版本号的唯一真相源是 `package.json`，`src/version.mjs` 复述一份供运行期读取
（测试会断言两者一致）。它出现在三个地方：终端**头部面板**（每次启动的第一屏）、`wwriting --version`、`/help`。
改版本号要同时改这两个文件，漏改一处测试立刻红。

没配过模型时，首次启动会先走一次**三步引导**（厂商 → API Key → 模型）：厂商与模型用上下键选，
每一步都能跳过——没配 Key 也进得来，只是发消息时会提示「未配置」。

把长篇小说写作当作工程来管理的命令行 Agent：在创作目录里启动，可以继续或恢复本地会话，
调用 DeepSeek 官方模型写作，在写入章节前先征求你的确认；用 `-c` 重启后接着上次的会话与队列继续，
**并且把历史对话回喂给模型**——它记得你前面写过什么，不会每轮都从头开始。

- **单一对话面**：写作、`/model`、会话切换都走同一个输入框，不建第二控制面。
- **过程可见**：动态状态行与活动行只属于「当前这一轮」，轮结束只留终态状态行与可回看的正文。
- **记得住**：每轮开工时会把该会话的历史对话按预算回喂给模型；你也能看到它这一轮到底记得多少。
- **数据边界**：会话、事件日志、锁与配置一律放 `%APPDATA%\WWriting\`；创作目录只保存你确认写入的章节文件。
- **权限分级**：读取自动放行；写入 / 修改先确认（一次允许 / 本条输入允许同类操作 / 拒绝）。

## 环境要求

- **Node.js ≥ 22**（ESM）。只用标准库：`node:readline`、`node:fs/promises`、`node:crypto`、全局 `fetch`，
  没有第三方运行时依赖。已在 **v22.22.2** 与 **v25.2.1** 上跑通全部测试——声明范围与实际验证范围一致，
  不要求本项目没有验证过的版本。
- **首发平台是 Windows**，请在 **Windows Terminal 或 PowerShell** 里运行。
  Git Bash / MinTTY 不是 Windows 控制台，`readline` 的原生行为不可靠：检测到时会输出一条提示并走非交互分支，
  请改用 Windows Terminal。
- 终端需支持 ANSI 转义序列（Windows Terminal 默认支持）。设置 `NO_COLOR=1` 可关闭颜色
  ——颜色与光标控制是两回事，`NO_COLOR` 只关颜色，动态行的光标控制照常工作。
  首版是 **inline 渲染**：不占用 alternate screen，已完成的内容直接进终端 scrollback。

## 安装与本地运行

不装任何依赖，直接跑：

```powershell
node src\cli.mjs --help
```

作为全局命令安装（`package.json` 已声明 `bin.wwriting`）：

```powershell
npm install -g .
wwriting --help
```

## 快速启动：双击 `publish and run.bat`

不想记命令时，直接双击仓库根目录的 **`publish and run.bat`**：

1. **更新到最新**：如果这份代码是 Git 仓库且配了远端（`upstream`），先 `git pull --ff-only`；
   `package.json` 声明了依赖而 `node_modules` 缺失时自动 `npm install`（当前首版无第三方依赖，通常是空转）。
2. **选文件夹**：弹出目录选择框，选中哪个目录就用哪个目录当创作目录。
   **它会记住上次用的那个**：下次双击时先问一句「回车 = 就用它」，直接回车就跳过选择框
   （也可以直接粘贴一个目录路径）。记忆写在 `%APPDATA%\WWriting\launcher.json`——
   创作目录里只放作品，不放这种状态。
3. **打开命令行并启动**：在那个目录里开一个新的命令行窗口（`cmd /k`），并在其中启动本工具
   —— 窗口留在那儿，退出工具后还能看到最后一屏输出。

窗口里的第一屏就是**紧凑头部面板**（品牌行 + 工作区 / 会话 / 模型 / 记忆），可以直接确认当前版本与工作区：

```text
WWriting 0.1.0  长篇写作智能体
──────────────────────────────────────────────────────────
工作区   D:\Novels\星坠之城
会话     开始新会话 · 80a922de-22c1-43fa-95d6-001dc8807677
模型     deepseek-chat · sk-****abcd · 思考 自动
记忆     WWRITING.md 已就绪
直接输入开始写作 · /help 查看命令 · Ctrl+C 停止当前轮
──────────────────────────────────────────────────────────
❯
──────────────────────────────────────────────────────────
```

窄窗口中的路径与会话 ID 会换行，并保留完整内容。正文与输入分隔线使用同一阅读列，
宽窗口也不会把长篇正文拉满屏幕；中文换行尽量避免句末标点落在行首。

输入 `/` 后按回车可以打开方向键命令菜单，选择后只填入草稿，再按回车才执行。
也可以输入命令前缀（例如 `/mo`）后按 `Tab` 补全。运行中输入 `/` 会显示帮助，
不会打开另一个选择器与权限确认争抢按键。

记录于：2026-09-30｜状态：当前有效｜依据：本轮终端渲染与输入体验优化。
深色终端使用中性灰底、柔和陶土色强调与独立的警告/错误色；正文保持高对比，
辅助信息降低视觉权重，`NO_COLOR` 仍可关闭所有颜色。

启动器自己也会打印一行更新结果（`已是最新（a6030b3）` / `已更新：… → …` / `本地仓库（…），没有配置远端`）。

想先看看它会做什么而不真的开窗口：

```powershell
.\scripts\launcher.ps1 -DryRun                      # 演练：只显示将要执行的命令
.\scripts\launcher.ps1 -Target D:\novel             # 跳过选择框，直接用这个目录
```

两个实现细节（都是 Windows 上的老坑，踩过并写进注释了）：

- `publish and run.bat` 保持**纯 ASCII**，所有中文提示由 `scripts\launcher.ps1` 输出；
  后者必须保存为 **UTF-8 with BOM** ——否则 Windows PowerShell 5.1 会按 ANSI 解析脚本、中文直接乱码。
- 从 PowerShell 传给子 `cmd` 的启动命令只用一个环境变量占位（`%WWRITING_LAUNCH%`），
  参数里不含引号：仓库路径常含空格，这样绕开 PS 5.1 的引号转义问题。

## 启动形式

| 命令 | 行为 |
| --- | --- |
| `wwriting` | 开一个**全新会话**（什么都不写就是最小惊讶） |
| `wwriting "写第一章"` | 用这条消息开始一个**新**会话 |
| `wwriting -c` / `--continue` | 显式接着最近会话（没有历史时新建） |
| `wwriting --resume <会话ID>` | 恢复指定会话（按 ID 选，不是「选最近的」） |
| `wwriting --version` / `-v` | 打印 `WWriting <版本>` 后立即退出 |

裸启动**不会**悄悄续上最近会话——「接着上次」是一件有后果的事，得由你显式写 `-c`
（对齐 `claude`：什么都没写就是开一个新的）。会话内也可以随时 `/resume` 挑一个。

`-c` / `--continue` 接着的是**会话与历史记录**，并接着消费未跑完的队列。
**模型会拿到这段历史**：每轮开工前按预算把前面的对话（你的输入、它写出的正文、它调用过哪些工具）
重新喂进去。三条边界值得知道：

- **只回放可见内容**。历史完全从本机事件日志派生，只包含你输入过的文本、模型输出的可见正文，
  以及工具调用的名字与结果摘要（如「3210 字」）。模型的私有思考过程（reasoning）会全量落盘、
  用 `/reasoning` 按需查看，但**绝不回喂给模型**，因此也不会被回放。
- **有预算，超了就丢最早的**。默认按 24000 字符估算（中文约 1 字符 ≈ 1 token 量级，**这是估算值，不是精确 token 计数**）。
  超出时从最早的一轮开始丢；单轮超预算时保留这一轮、只截断它正文的**尾部**（最新的内容信息量最大）。
  **你的输入永不截断**——那是指令，截半句会让模型误读你的意图。
- **省了东西会说出来**。真的丢了更早的轮次时，屏幕上会有一行 `已载入前情：N 轮 · 省略更早 M 轮`。
  没省略就不占屏幕。会话列表（`/sessions`）里每一行也带该会话的真实对话轮次数。

历史读取失败（日志损坏等）不会让这一轮失败：它会降级为「不提供历史」并如实告诉你在发生什么——
失忆好过开不了工。

`--cwd <目录>` 可与上面任意形式组合，用来指定创作目录（相对路径按当前目录解析）：

```powershell
wwriting --cwd D:\novel
wwriting --cwd D:\novel "写第一章"
wwriting --cwd D:\novel --resume 80a922de-22c1-43fa-95d6-001dc8807677
```

`--help` / `-h` 打印用法后立即退出：**不启动 Agent、不写任何数据**。
`--version` / `-v` 同理，是「看完就走」：不建会话、不写私有目录、不碰创作目录
（启动器脚本正是靠它读版本，所以这条承诺有测试钉住）。

## 配置模型与 API Key

**第一次启动**（`%APPDATA%\WWriting\config.json` 还不存在）会先走一次两步引导：
粘贴 Key（**当场验证**）→ 从端点的真实列表里**上下键选**一个模型。

```text
WWriting 0.1.0  长篇写作智能体（命令行版）
──────────────────────────────────────────────────────────
首次设置   一个 API Key + 一个模型，两步就好；都能跳过。
──────────────────────────────────────────────────────────
↑/↓ 选择 · 回车确认 · Esc 跳过这步 · Ctrl+C 退出
① 填入 API Key
  在 https://platform.deepseek.com 创建后粘贴进来，回车即验证。
  直接回车 = 先跳过（发消息时会提示「未配置」）。
──────────────────────────────────────────────────────────
❯ sk-abcdefghijklmnopqrstuvwxyz012345
──────────────────────────────────────────────────────────
  API Key 有效 · 2 个可用模型
② 选择要用的模型
❯ deepseek-chat
  deepseek-reasoner
  ✎ 自己输入模型名
  ↑/↓ 选择 · 回车确认 · Esc 跳过这步
设置完成，开始吧。
```

- **① API Key**：去 `https://platform.deepseek.com` 创建后粘贴。回车就**拿它去问一次端点**：
  - 有效 → 直接进下一步，并把它记下来（`API Key 有效 · N 个可用模型`）；
  - 被拒 → 原地重问，**不保存**（不会让你在下一次发消息时才发现）；
  - 连不上 → 照常保存，但明确说「暂时没能验证」，不让网络问题冒充 Key 问题。
  这一行**照常回显**（隐藏回显那套又脆弱又难懂：屏幕上只剩一个空提示符，你根本看不出自己粘进去没有）。
- **② 模型**：候选来自端点的 `GET /models`（**真实存在的模型名**，所以模型改名 / 下架不需要改代码）。
  手里有列表时，手输一个列表外的名字会被拒收并报出可用的那几个。
- **每一步都能跳过**：Key 那一步直接回车即可；跳过之后不会再问第二遍，`/model` 随时可以补齐。

**重新配置：打一个 `/model` 就够**（不必记得模型名怎么写）：

```text
❯ /model
当前：deepseek-chat · sk-****abcd
选择要用的模型
❯ deepseek-chat            ← ↑/↓ 选择 · 回车确认 · Esc 不改动
  deepseek-reasoner
  ✎ 自己输入模型名
  ⌘ 换 API Key
设置完成：模型 deepseek-reasoner
```

- **已经有 Key 就不再问 Key**——换模型不该被逼着再确认一遍；要换 Key 选菜单里的「⌘ 换 API Key」，
  或直接用 `/model key <你的 Key>`。
- 还没有 Key 时它会先问 Key（回车跳过就干净收场，回到对话面）。
- **能自愈**：如果模型名那一格被写进了 API Key（真实事故留下的配置），向导会把里面的 Key
  **捞回来**、验一次、挪回 API Key 的位置，你一个字符都不用重新粘贴。

也可以走非交互的直达形式：

```text
/model                     打开交互式设置（非交互时的兜底是打印当前配置）
/model deepseek-chat       直接设置模型名（会对着真实列表核对）
/model key sk-xxxxxxxx     直接设置 API Key（保存前先验证）
```

两个守卫来自同一次真实事故（API Key 被当成模型名存下去，之后每轮请求都用一个不存在的模型名、
却回一句「API Key 无效」，人被指到了完全错误的方向）：

1. **只要那串里出现了 Key 的样式，它就一定是 Key**：`/model sk-…` 会被按 Key 处理，
   `/model key` 与 Key 之间少打一个空格变成 `keysk-…` 也一样；
2. **模型名位置上是 Key 一律拒收**（`saveDeepSeekConfig` 这层也拦，是最后一道防线）。

边界（铁律 8）：

- API Key 只写 `%APPDATA%\WWriting\config.json`，**绝不**进创作目录；任何展示走脱敏（如 `sk-***abcd`）。
- **没配 Key 也能用**：不因为未配置就把人挡在门外。发消息时只在对话里给**一条中文事实**（短状态 `未配置` + 下一步怎么做），不是红色故障；`/model` 始终可用。
- 配置损坏同样不阻断启动：会再走一次引导，保存时按空配置覆盖，顺手把坏文件修好。
- 环境变量 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` 可临时覆盖配置，只读、不写回文件。

## 键盘与运行控制

- **Enter** 发送输入。
- **Ctrl+C**：有正在跑的轮 → **停止当前轮**（不退出、不清队列，临时授权一并清除）；
  空闲 → 退出。
- 运行中继续输入会进 **FIFO 队列**（行尾标 `排队`），按序执行；**同一时刻只有一个模型请求**。
  轮到队列里某一条真正开跑时，屏幕上会出现它的用户行——输出从此有主，不会让你猜这段话是谁写的。
- `/now` 把**队首**那条排队输入提上来跑，并**打断当前这一轮**（队列为空时如实回一句 `队列为空`）。
  这就是规格里的「立即」。它是一条斜杠命令而不是裸词，因为「立即」在小说正文里是常见词
  （「他立即转身」），裸词触发会吞掉你的正文。
- `/stop` 停止当前轮；`/quit` 退出（退出前先停当前轮、再释放会话写锁，保证进行中的写入完整落盘）。
- 其余斜杠命令都在同一个输入框里作答：
  - `/init`：让模型建立或谨慎更新项目记忆 `WWRITING.md`（写入走确认卡，见「项目记忆」一节）。
  - `/sessions`：列出该创作目录下的会话与各自的轮次数。
  - `/resume`：切换会话——`/resume <会话 ID>` 直接切，无参时打开交互式挑选（Esc 取消）。
  - `/effort`：查看或切换思考强度（`none` / `low` / `high` / `max` / `自动`），`/effort max` 回车即生效于下一轮。
  - `/reasoning`：灰显重放**本次进程内上一轮**的思考正文（正在想的时候最近两行已经贴在框上方，
    这条命令给的是**全文**；思考正文全量落盘，但只经这条命令查看，且不回喂给模型、不跨重启重放）。
  - `/help`：列出全部命令。

## 会话锁（多进程）

- 打开会话即取得**写锁**：同一个会话同一时刻只允许一个写入者。
- 第二个进程只会拿到**一条中文事实**与非零退出码（`SESSION_BUSY`），绝不对同一份事件日志重复写入。
- 只读操作（如会话列表）不取写锁。
- 锁、事件日志与配置都在 `%APPDATA%\WWriting\workspaces\<workspace-id>\` 下，创作目录里不会出现它们。

一次完整启动长这样（第一行是头部面板）：

```text
WWriting 0.1.0  长篇写作智能体（命令行版）
──────────────────────────────────────────────────────────
工作区   D:\Novels\星坠之城
会话     开始新会话 · 80a922de-22c1-43fa-95d6-001dc8807677
模型     deepseek-chat · sk-****abcd · 思考 自动
记忆     WWRITING.md 已就绪
直接输入开始写作 · /help 查看命令 · Ctrl+C 停止当前轮
──────────────────────────────────────────────────────────
❯ 写第一章
──────────────────────────────────────────────────────────
需要确认：写入文件 第一章.md
❯ 一次允许
──────────────────────────────────────────────────────────
✓ 写入文件 第一章.md · 101 字
第一章已经写好，主角在雨夜抵达长街。
已完成 · 1.0k tokens
──────────────────────────────────────────────────────────
❯
──────────────────────────────────────────────────────────
```

重启后用 `-c` 接着上次会话时，**上一轮对话会重演到屏幕上**（用户行、正文、`思考 N 秒`、
终态行按顺序再画一遍），所以「我续上的是哪一个会话」一眼可确认。更早的轮次按同一份历史预算
省略；真的省了东西时，重演的**开头**先如实说一句 `已重演对话：更早的 N 轮未重演`（主文案
`已重演对话`，更早的轮数进详情）——屏幕重演与回喂给模型的轮次是**同一批**，不会出现
「模型记得、屏幕看不到」。

几处排版上的约定：

- **大字标识**在最上面（`src/terminal/banner.mjs`：照着上游桌面版头部的截图反推的 5 行方块字，
  8 个字形写死在代码里，没有引第三方字体）。终端够宽自动放大一档；字形、宽度、内容列宽都有纯函数测试盯着。
- **输入框是一个上下两条线的框**：上框线 / `❯ 你输入的那一行` / 下框线，所以「我现在在输入」在长输出里也一眼可见。
  线同时承担分隔，屏幕上一个空行都不用留。缩进与头部面板的横线对齐（内容列），`❯ ` 落在左侧空白里当标记。
- **实时状态**（`思考中` / 进行中的工具）贴在框的上方，框本身始终在屏幕最下方——
  流式正文、活动行、终态行都写在框上面，不会盖住你正在输入的内容。
- **用户行**永远以 `❯` 开头（提示符与用户行是同一个字符）。**模型正文**以 `▌` 开头
  （每段只有第一行带这个标记，续行缩进对齐），与用户行、工具行的标记**三族各不相同**，
  扫一眼就知道这一句是谁说的。Agent 消息不带头像与署名。
- **思考过程看得见**：模型正在想的时候，最近两行已经完成的思考贴在框的上方
  （`思考中 · 主角为什么不肯离开` + 缩进对齐的续行，压暗显示）。它**只活在这一瞬**——
  跑完就随实时区一起消失，日志里也只留一条思考全文。想看完整的思考全文用 `/reasoning`
  （只对本次进程内刚跑完的那一轮有效；`max` 档几万字符的思考不会冲掉正文，正是因为它不进滚动区）。
- **正文按终端的行宽折行**，缩进到内容列（与框线、面板同一列）。流式正文只在「攒够一整行」或遇到真实换行时
  落盘，所以屏幕上看到的折行就是终端自然折行的结果——**段落中间不会凭空多出换行**。
- **正文里的轻量 Markdown 会被渲染**：`# 标题` 去掉井号并加粗、`**强调**` 加粗、`` `行内代码` `` 压暗、
  \``` 围栏代码块整块缩进。`NO_COLOR` 下只是去掉标记、不改文字（同一份输入在任何模式下都得到同一串可见字符）。
- **工具行**用标记区分状态：`•` 进行中、`✓` 完成、`✗` 失败、`−` 已停止，并**说出结果**：
  `✓ 统计字数 第一章.md · 3210 字`、`✓ 读取文件 大纲.md · 128 行`。客观字数因此对用户可见——
  它本来就是决定「接着写还是收尾」的依据。失败时带一条原因；超过 2 秒的操作补上耗时；
  连续重复的同一行只留一行，模型反复重试不会刷屏。
- **确认提示走方向键选择器**：普通确认先印一行 `需要确认：<做什么>` 进 scrollback，紧接着选择器接管终端
  （`↑/↓` 移动 · 回车确认 · Esc/Ctrl+C 拒绝）。选完那一块收成一行 `❯ <所选项>` 留在卡片下面——
  **答了什么必须留在屏上**，这是一条权限决定，事后要能看出当时选的是哪一项；按 Esc / Ctrl+C 取消时同样
  收成一行 `❯ 拒绝`（那是一次真实的拒绝）。非交互（管道 / 非 TTY）时退回一行纯文字提示
  `回复「一次允许」「本条输入允许同类操作」或「拒绝」`。极端确认是**唯一**的例外：它必须把当次显示的那行文字
  **原样回复**——那是有意为之的抄写关卡，不是选择题（铁律 4 / 11）。
- **终态行**带上本轮用量（`已完成 · 1.2k tokens`）；连不上服务端时标题是 `连接中断`，
  与「这一轮跑失败」分开（用户能做的事不一样）。重启后**重演的终态行只有同一句状态文字与色调**
  （重演只画 `status.text` + tone，不带 live 行上的用量后缀与失败原因）——用量后缀属于当场那一轮。
- **历史事实行**只在真的省了东西时出现（`已载入前情：6 轮 · 省略更早 4 轮`），没省略就不占屏幕。
- **实时状态**（`思考中` / 工具进行中）是贴在框上方就地重绘的动态行（最多两行：思考预览会占两行）；
  Run 结束只留终态与可回看内容。

## 项目记忆 `WWRITING.md`

`WWRITING.md` 是**项目记忆**（铁律 7）：随作品走，放在**创作目录**里、与章节文件并列，
你可以直接用编辑器打开修改。

- **每轮自动生效**：这一轮开工时自动重读它，把内容作为一条独立的记忆消息注入给模型，
  不需要任何刷新命令。你在编辑器里改一行，下一轮就生效。
- **程序绝不自动生成或修改它**。它只能由**模型经确认卡写入**（走既有的 `write_file`
  / `edit_file` 权限确认，与你确认章节写入是同一套）；`/init` 是让模型建立或谨慎更新它的入口。
  创作目录里绝不会凭空冒出一个 `WWRITING.md`——冒烟脚本专门有一条断言盯着这件事。
- **超长时优先保住索引段**：内容超过 **8000 字符**时，注入的是**按预算裁过的内容**——
  其中的**权威文件索引段**（指向 `OUTLINE.md` / `SETTING.md` 等）优先完整保住，
  其余按预算从头保留尽可能多，并在屏幕上如实说一句省了什么；模型再按需
  `read_file` 去读正文。它本来就是**索引兼记忆**，不是第二份总纲。
- **分工（Q8）**：`AGENTS.md` 是**规则**——怎么写、什么不许做，相对稳定，由**你**维护；
  `WWRITING.md` 是**这部作品的当前状态**——写到哪了、哪些要求已确认、权威文件在哪，
  随写作变化，由**模型**维护。冲突时的优先级是「你当轮的明确指令 > `AGENTS.md` 的规则 >
  `WWRITING.md` 里的旧状态」。这条不做运行时防御：文字说清 + 你能直接编辑文件，
  比一个会误判的检查器强。

冒烟脚本全程使用临时工作区、临时 `APPDATA` 和本地**假 DeepSeek 服务**（真实 HTTP + 真实 SSE，不接网络），
覆盖「打开目录 → 模型调用 write_file → 确认 → 落盘 → 进程重启 → `-c` 恢复会话并读回历史记录」，
并断言**第二条请求确实带上了第一条的内容**（会话连续性的端到端证据），以及数据边界：
创作目录只出现被确认写入的文件，事件 / 投影 / 锁 / 配置只出现在临时 `APPDATA`。

（屏幕上不重演任何历史）——这条语义反转由冒烟脚本守着，不会悄悄回退。

## 首版明确不支持

- **默认只接 DeepSeek 官方端点**：开箱即用只面向 DeepSeek，不做多供应商 UI。
  但 `base_url` **事实上可配**（`config.json` 的 `base_url` 字段，或环境变量 `DEEPSEEK_BASE_URL`，
  它优先），指向别的 OpenAI 兼容网关时模型列表取自该端点的 `${base_url}/models`；
  此时思考强度要在 `config.json` 的 `model_capabilities` 里为该模型显式声明
  `reasoning_effort_levels`（ADR-0009 的第 (ii) 层）才可用，
  否则按「能力未知」如实回一句，不伪装生效。
  另有一处已知代价：每个请求都带 `max_tokens`（取该模型的输出上限——官方模型按内置表，
  网关 / 未知模型回落 **65,536**）。改动前这个字段不发、由服务端默认兜底，
  所以**真实输出上限低于 64K 的网关模型现在可能被 400 打回**。`GET /models` 不返回能力信息、
  本地判不出上限，这是「给足空间」的取舍（见 ADR-0009 未决项与
  `docs/research/06-deepseek-reasoning-effort-probe.md`）；将来的出路是给 `config.json`
  加一个 `max_output_tokens` 声明字段，与 `reasoning_effort_levels` 同一形状。
- **只做 Windows 首发验收**：Linux / macOS 终端未做回归；Git Bash / MinTTY 明确不支持。
- 不做全屏 TUI、alternate screen、桌面式悬浮面板。
- 不做与桌面端 `D:\WWriting` 的互通：不读它的 `project.yaml`，也不共用它的本地事件格式。
- 不做导出（DOCX 等）、复杂会话浏览器、向量检索；不自动创建 `OUTLINE.md` / `SETTING.md`。
- 不做多行编辑：Shift+Enter 不承诺换行。
- **不做上下文压缩 / 摘要**：历史超预算时是**丢弃更早的轮次**，不是让模型总结前情。
- **不做相关章节召回**：历史只来自本会话的对话，不检索创作目录里的其他文件（向量检索不在首版）。
