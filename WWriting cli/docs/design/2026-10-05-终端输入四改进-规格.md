## Problem Statement

用户在写长篇小说时遇到四件不顺手的事：

1. **命令靠背**：输入 `/` 之后屏幕上没有任何反馈，有哪些命令、命令名拼全没有，全靠记忆；现有 Tab 补全不可见（多命中时连按两次 Tab 会把 readline 的原始列表裸打出来），空 `/` + 回车弹窗又要求先按回车才能看到清单。
2. **忙碌时插不上话**：Agent 正在跑轮时打好了话，只能等本轮结束，或者先 `/now` 提升队首（还得先让这句话进过队列）。缺一个「这句话现在就要发出去」的按键。
3. **宽终端上输入框局促**：输入框横线封顶在阅读列宽度（78 列 + 2 格缩进），120 列终端上只占约 2/3；而实时区行与输入行折行本来就按全终端宽算——框线反而是屏上唯一不满宽的元素，观感割裂。
4. **权限模式不可见**：现在只有 YOLO 时实时区有一行警示 chip，普通模式什么都不显示，且这行 chip 会随状态行消失、忙碌时与状态文案混在一处。用户时时刻刻都该知道自己处于什么权限模式——尤其 `/resume` 换会话会把 YOLO 静默重置回普通，没有常驻指示就无从发现。

## Solution

1. 打 `/`（且只在命令位置）立刻看到命令联想菜单：↑↓ 移动高亮、Tab 一键补全、Esc 收起——与 Claude Code 的 Autocomplete 同一套按键语言；菜单底部带一行按键提示。
2. Ctrl+S = 立即发送：空闲时与回车等效；忙碌时打断当前轮、把输入框里这句话作为下一条活动输入发出——与 `/now` 共用控制器原语；停止后队列残留时也不排队、直接成为下一条活动输入。
3. 输入框横线占满终端横宽（末列留 1 格安全边），与实时区、正文折行宽度对齐。
4. 输入框上框线右端常驻权限模式标签：普通模式显示 `Normal`（中性低调色），YOLO 显示 `YOLO`（警示色、显眼）——两种状态都常驻，换模式即变色，任何时刻（空闲、忙碌、联想菜单开着）都可见。

## User Stories

1. 作为写作者，我想输入 `/` 时立刻看到全部命令的联想清单（每条带一句说明、底部有按键提示），不用背命令名、也不用先按回车开菜单。
2. 作为写作者，我想用 ↑↓ 选中命令后按 Tab 把它补全进输入框，使命令名不会拼错。
3. 作为写作者，我想让正文里的斜杠永远被当成普通字符（路径、章节名、「第一章/第二章」这类紧贴文字的斜杠），联想绝不打断正常写作。
4. 作为写作者，我想在 Agent 忙碌时按 Ctrl+S 打断当前轮并立即发出我正在输入的这句话，不用等本轮结束、也不用先排队再 `/now`。
5. 作为写作者，我想让空闲时的 Ctrl+S 与回车等效，两种状态下快捷键肌肉记忆都成立。
6. 作为写作者，我想让输入框横线占满终端宽度，宽终端上输入区与实时区的边界一致、不显局促。
7. 作为写作者，我想时时刻刻在输入框旁看到当前权限模式（Normal / YOLO 两种字样、色彩区分），所以我永远不会在不知情下让模型自动执行写入，也不会在 YOLO 被静默重置后误以为自己还开着它。
8. 作为写作者，提交了不完整的命令（如 `/mo` 直接回车）时，我要看到与今天一致的「不认识 这个命令」反馈——菜单只负责联想，不替我猜。
9. 作为写作者，在权限确认卡、`/model` 向导、`/resume` 挑选等让位界面期间，联想菜单与模式标签必须与输入区一起消失、恢复后按当前状态重建，绝不与它们抢键。

**明确排除**：多行编辑（首版不做）、`/resume <会话ID>` 等参数补全、文件路径 / @ 联想、stash（暂存草稿——参考项目 Ctrl+S 的真实语义，本轮按用户意图做「立即发送」）、确认卡与头部面板的宽度调整、运行中给 Ctrl+S 插提示行（违反文案纪律，发现面交给头部面板键位行与 README）、在实时区/滚动区另设第二处模式显示（标签是唯一显示位）。

## Implementation Decisions

**命令位置（斜杠联想的触发判据，与用户对齐的关键点）**

- 菜单打开 = 当前行处于「命令位置」：整行以 `/` 开头（斜杠是输入框里的第一个字符）、首个 token 还没结束（没打出空格）、且有前缀命中。菜单打开时高亮初始在**第一条**；无命中的前缀（如 `/zz`）视为菜单关闭，Tab 不抢。
- 菜单判据是斜杠命令解析器判据的**子集**（解析器先做 sanitize/去首尾空白——今天前导空格的「␣/model」也会被解析器执行，菜单不开，该行为保持不变）：菜单不开的行，解析器怎么判照旧；菜单开了的行，解析器必定认账。两者不会互相矛盾。
- 行中任何位置的斜杠——紧贴文字的、前面带空格的——都是普通字符，菜单不开、Tab 不抢（保持普通文本里 Tab 无操作的现状）。

**联想菜单（输入层 composer）**

- composer 面积模型新增「菜单槽」：画在实时区之下、上框线之上。忙碌时实时区（思考中/活动行）照常占自己的槽，菜单显示在它下面——与 Claude Code 布局一致；菜单不抢键、不需要让位终端（今天「忙碌时退化 /help」的分支因此删除）。
- 菜单内容与选中态由输入层自身从当前行推导并自绘，渲染器无感知；takeArea/giveArea 借用协议不变（ADR-0003）。
- **菜单擦除几何的三条硬要求**（缺陷猎捕 5/7/10 族的同款纪律，审查确立）：
  1. 菜单行数独立记账：跟踪上一帧菜单行数，菜单变矮时按**旧高**擦除（复用既有块记账原语），只按新高上移会残留旧菜单顶部行；
  2. 块顶锚定的清屏序列从输入块首行起擦，**够不到菜单所在的更高位置**——菜单重绘必须独立逐行先抹再写，不能依赖 `\x1b[0J`；
  3. 快速回显路径（逐字回显、不经过整行重绘的那条）在菜单开着时也必须触发菜单重绘/收起，否则打字时菜单残影。
- 菜单清理时序：回车提交时，菜单的收起固定发生在**拦截层拦到回车、放行给 readline 之前**——那一刻光标还在输入行上、折行几何还算得准；等到 `line` 事件触发时行缓冲已被 readline 清空，几何无从算起。
- 数据源 = 命令清单的单一权威表（14 条，连中文说明一起传入，与 `/help` 同源不分叉）；前缀筛选口径与现有 completer 相同。
- 菜单行形态沿用选择器家族：高亮行 = `❯` 标记 + accent 色；**NO_COLOR 下仅剩 `❯` 标记**（选择不依赖颜色，`❯` 就是「Tab 会补哪一行」的答案）。说明列按显示宽度截断/折行，口径与选择器条目一致。
- 菜单底部固定一行提示 `↑/↓ 选择 · Tab 补全 · Esc 收起`（选择器 DEFAULT_HINT 家族形态），**计入菜单封顶行数**。菜单「回车 = 提交原文」与全 app 五处选择器的「回车确认」相反，这行提示必须说清。菜单只在 `/` 开头时打开（即命令草稿），此态下 Ctrl+S 与回车等价，提示行不含 Ctrl+S。
- 菜单行数按终端高度封顶（与方向键选择器同款纪律）；NO_COLOR、CJK 宽度、超宽截断走度量层既有口径。
- 按键（收进既有的 readline 拦截包装，与 Shift+Tab 同一位置、同一纪律）：
  - ↑↓ = 移动高亮，循环滚动；菜单开着时接管方向键（不翻历史），关着时方向键行为不变。
  - Tab = 把高亮项补全进输入行（补全后带尾空格，菜单随之收起——进入参数输入态）。
  - Esc = 收起菜单，再打字重开。**必须显式调小建接口时的转义歧义窗口**（`escapeCodeTimeout`，默认 500ms 实测会让「Esc 后 500ms 内打的下一个字」被吞、Esc 与方向键被合并成无效序列）：设为小值（约 50ms，方向键等完整序列单次写入到达不受影响），拦截层对「meta + 单字符」的键剥掉 `\x1b` 按普通字符重注作双保险。
  - 回车 = **提交原文**（不补全、不执行高亮项）：完整命令照常执行，不完整前缀维持现状的「不认识 这个命令」反馈。
  - Ctrl+S = 立即提交（见下）。
- **completer 移除与 Tab 拦截必须同一提交落地**：单独移除 completer 而未拦 Tab 的中间态会把字面 `\t` 插进草稿，连带触发「带控制字符的半行不接」让让位前的整行草稿被丢。补一条「无 completer 时 Tab 不改行」的用例。
- 粘贴以 `/` 开头的文本（Unix 路径等）会让菜单随逐字符回显闪现：先在真机走查记录观感；若明显，单次 data 事件内的菜单重绘合并到块尾一次定夺。

**Ctrl+S 立即发送**

- 拦截位置同上（Shift+Tab 的既有包装）。今天 Ctrl+S 在 raw 模式下被 readline **静默忽略**（实测确认，不会插进行内）——拦截是实现新语义的入口，不是防污染。
- 语义（已与用户对齐，本规格为其**独立定义**，不借用「/now 会不会变」的任何未来结论）：**提交草稿并使其成为下一条活动输入；存在活动轮则先打断该轮**。细分：
  - 空闲且队列空：与回车完全相同。
  - 忙碌（有活动轮或 drain 在跑，判据 = 控制器唯一的 `isBusy()` 口径）：入队 → 提到队首 → 打断当前轮 → 同一个 drain 接手，绝不启动第二个 Agent；被取消轮的终态事件与写入完整性沿用打断式提升的既有原语，同样不可 `/retry`、终态「已中断」可见。
  - **空闲但队列非空（/stop 后的常态）**：草稿**排到队首**成为下一条活动输入，并启动消费（提升后无人接手时必须补一个启动）——按「与回车相同」处理会把它排到保留队列的队尾，违背「立即」承诺，故单列。
  - 空草稿（判据与回车丢弃闸同源：`trim() === ''`）= 无操作；空判**先于**打断发生（纯零宽字符等粘贴残留不得触发白打断）。
  - **命令位置的草稿（整行以 `/` 开头）+ Ctrl+S = 与回车完全相同**：命令就地执行、按命令自身的语义走，不走打断/提升——菜单打开态必然是命令草稿，此组合由此自然闭合。
- 提交通道：回车路径给提交回调增加第二参（如 `{ immediate }`）；Ctrl+S 拦截只负责「带标记触发既有提交簿记」（换行、擦区、重画框与回车共用同一份），不合成回车键重入。
- 控制器新增「按立即语义提交新输入」的入口，硬要求：
  1. `input_queued` 与 `input_promoted` 两个事件**同一写入任务**落 journal（单独写 promoted：对投影是空操作、对原语是抛错——草稿会无声丢失）；
  2. 打断（abort）紧随提升之后，不得拆成两步之间可被自然完成穿插的两次写入；
  3. 入口整体 catch，错误收敛成一条用户可理解的中文事实（对齐既有命令路径的错误收口）；
  4. 连按多条立即的次序：后按的先跑（每次都打断在跑的那条），与 `/now` 同语义。
- 数据面：复用既有事件（`input_queued`、`input_promoted`、被取消轮的 `run_interrupted`），无 schema 变化；实时区「排队」chip 对立即输入的短暂闪现可接受（事件流的真实中间态，随即被本轮用户行覆盖）。
- 与 `/now` 的关系：共用提升 + 打断 + 单一 drain 的控制器原语；`/now` 提升的是队首已有输入，Ctrl+S 提交的是草稿本身。两者的打断式语义都是本项目铁律 5 对上游 P3/§15（安全点切换，abort 式 promote 已退役）的**有意终端偏离**；A3（`/now` 语义裁决）落地时 Ctrl+S 是否跟随届时一并裁决，本规格不做「自动跟随」承诺。
- 误按代价留痕：Ctrl+S 在写作场景顶着「保存」的肌肉记忆，忙碌时误按 = 打断生成中的轮。**不做二次确认**（与 Ctrl+C 同一先例：确认反而挡住急用）；恢复路径 = 终态「已中断」可见 + `/retry` 重跑。
- 发现面：头部面板键位行（已列 Ctrl+C、Shift+Tab 的那行）追加「Ctrl+S 立即发送」；README「键盘与运行控制」一节加一行。不做运行中插话提示。

**满宽输入框**

- 度量层为横线增加全宽变体：缩进 0、宽 = 终端列数 − 1（守住「末列有毒、留 1 列防自动折行」的仓库口径，观感即铺满）。
- 输入框上下两条横线与单行问询（引导页 API Key 等）的框线换用全宽变体；`ruleLine` 全库仅输入层两个调用点，波及面极小。头部面板、正文阅读列、计划面板**不动**（保持阅读列）——metrics 里「所有横线对齐成一列」的设计意图就此在输入区上让位，这是用户明示要的 Claude Code 布局观感；确认卡要不要跟着拉满留作后续一轮。metrics 里「所有横线对齐」的注释随实现顺手更新。
- 输入行折行、实时区截宽本来就按全终端宽算，改完框线与它们对齐，反而消除了今天「文字超出框线」的不一致。

**权限模式常驻标签（Normal / YOLO）**

- 形态：标签**嵌在上框线右端**（右留 2 格安全边，横线字符补足剩余宽度）——不新增行、不占实时区、菜单与实时区照常各居其位。上框线是 drawArea 唯一逐帧重绘的线，标签随区重绘即天然常驻；下框线不承载标签（它的快速补线路径几何最敏感，不加变量）。
- 双态常驻：普通模式显示 `Normal`，YOLO 显示 `YOLO`——**两种状态都显示**（用户明示的「时时刻刻」；与参考项目「默认模式不显示」不同，这是有意差异）。文案就是这两个专有名词本身（极简；进 YOLO 的完整警示文案在确认卡里，标签不重复）。用词按用户指定，不译。
- 色彩区分（对齐参考项目的模式注册表形态：每个模式带自己的色彩，最高权限用警示色系）：`Normal` 用中性低调色调（与框线同族的 rule/info 系），`YOLO` 用警示色调（沿用现行 YOLO chip 的 warn 色）。NO_COLOR 下颜色全关，靠文字本身区分（两个词不同）。
- 数据流：权限模式状态已存在（会话内状态，get 返回 `normal|yolo`，翻转时同步写控制器权限层，/resume 换控制器时重置为普通）——标签是它的第三个消费面。模式变化（含进 YOLO 确认卡通过后、切回普通、`/resume` 重置）都必须即时反映到标签；输入层新增一个「设置框线标签」的 composer 钩子（文本 + 色调），由模式状态持有方调用。
- **现行实时区 YOLO chip 退役**（renderer 的 liveMode 行 + `YOLO_CHIP` 文案）：标签成为权限模式唯一的显示位，不留两处。ADR-0020 的显示条款由本规格取代，实现时在该 ADR 补一段修订注。
- 运行中不可切模式是既有纪律（「权限模式等这一轮结束后再切换」）——标签始终显示的是**已生效**的模式，不显示「正在切换」的中间态。
- 让位期间（确认卡/向导/挑选）标签随输入区一起消失，恢复后随区重绘——模态界面在场时它是焦点；非交互/管道路径无输入区，无标签。

## Testing Decisions

- 只测外部行为：按键序列 → 屏幕画面与提交事实，不测内部状态字段。
- 度量层：全宽横线的宽度口径（列数、末列留白、`columns` 缺失兜底）；带标签横线的拼接（标签右对齐、右留 2 格、线宽补足、标签窄于最小线宽时的下限行为）。
- 输入层（fake TTY 地基 + 画面解释器，现有用例同款）：
  - 菜单出现/消失：行首 `/` 出清单且高亮在第一条、行中斜杠（紧贴文字/前带空格）不出、删掉行首斜杠即消失、无命中前缀不开、token 打完空格收起；
  - 按键：↑↓ 循环移动、Tab 补全带尾空格、Esc 收起重开、**Esc 后紧跟字符不丢字**（小歧义窗口下）、菜单开着时 ↑↓ 不翻历史、菜单关着时 Tab 吞掉且**不插入字面 `\t`**、回车提交原文；
  - Ctrl+S：空闲提交、忙碌带「立即」标记、**命令草稿（`/` 开头）与回车完全相同**、空行与纯空白无操作、提交 `/` → 无操作且输入框原样重画；
  - 模式标签：启动即显示 `Normal`、YOLO 确认卡通过后变 `YOLO`、切回普通即恢复、NO_COLOR 下文字仍可辨、标签随区重绘无残影；
  - 擦除几何：菜单 + 实时区 + 折行输入共存时无残留；菜单变矮时按旧高擦除无顶部残行；快速回显（逐字打字）路径菜单不残影（画面断言整屏还原）。
- 控制器：立即提交 = 草稿成为**下一条活动输入**（忙碌时该输入被提升 + 当前轮被打断 + 同一 drain 接手；空闲但队列非空时插到队首并启动消费）+ 两事件同一写入任务 + 入口错误收敛成一条中文事实 + 连按次序（沿用队列/停止/立即的既有用例形态）。
- 画面级断言：忙碌中 Ctrl+S 后屏幕出现「已中断」终态 + 新输入立即开跑的用户行。
- 回归：斜杠解析判例不变——行中斜杠永不误判为命令。
- 真机走查（ADR-0018 纪律，ConPTY 抓包）：Ctrl+S 在 raw 模式下的行为；**Esc 收起菜单后立即打字**；**IME 组合态下 `/` 菜单过滤与 Ctrl+S**；**粘贴 `/` 开头文本（含 `\t` 的粘贴块）**；菜单擦除无残留；满宽横线 + 换行的 ConPTY 行为；**YOLO 标签在确认卡通过/`/resume` 重置两个路径上的即时变色**。

## Out of Scope

- stash（暂存草稿，提交后自动恢复）——参考项目 Ctrl+S 的真实语义；本轮 Ctrl+S 按用户意图做「立即发送」。
- 参数补全（`/resume <会话ID>`）、文件 / @ 联想、多行编辑、运行中给 Ctrl+S 的插话提示。
- 确认卡、头部面板、计划面板的宽度调整（保持阅读列）。
- 权限模式的持久化（跨重启记忆 YOLO）——模式仍是会话内状态（跟 ADR-0020），标签只负责显示。
- A3（`/now` 语义裁决）本身——本规格已把 Ctrl+S 定义为独立语义，A3 落地时一并考虑两者是否统一。
- 相邻既有缺陷（审查发现、**另立缺陷单**）：`/compact` 模型请求期间 `isBusy()` 为假——该窗口内提交（回车今天即可触发）会开跑一轮且该轮会被摘要过滤排除、对模型静默失忆。修复 = 压缩期间计入忙碌口径或拒绝提交，不属本轮。
- 非交互 / 管道路径：无输入框，全部维持现状（含模式标签）。

## Further Notes

- 已与用户对齐的交互口径（2026-10-05）：① Ctrl+S 忙碌时 = 打断并立即发送；② 菜单开着回车 = 提交原文；③ 空 `/` + 回车弹窗退役、**无操作**——落点收进输入层，与空行同一个丢弃闸；④ 权限模式标签双态常驻（Normal / YOLO 字样 + 色彩区分），上框线右端。对抗审查中两位审查员倾向 bare `/` 落「不认识反馈」更诚实，因与用户拍板的「无操作」不符未采纳，留此备查可翻转。
- 参考行为出处（Claude Code 2.1.88 cli.js 提取）：Chat 上下文 `enter=chat:submit`、`ctrl+s=chat:stash`；Autocomplete 上下文 `tab=accept`、`esc=dismiss`、`up=previous`、`down=next`；`enter` 不在 Autocomplete 上下文（落到 Chat 层原样提交）；模式注册表 `{shortTitle, symbol, color}`，`bypassPermissions`（最高权限）用 `color:"error"` 警示色系——本规格的 YOLO 标签取同构做法。
- 与上游 §4.7 的偏差记录（按 ADR-0009 先例，随实现成文）：上游契约是「前缀筛选、上下键、**Enter**、Tab、Esc 和鼠标选择；选择命令只把完整命令填入输入框，**不自动执行**」——本规格的 Tab=填入与上游一致，**回车=提交原文是有意偏差**（与 Claude Code 一致；避免「菜单高亮着 /model、回车却只是填入」的双重确认），鼠标项终端无对应物。
- 铁律 10 与标签用词：全部 UI 文案简体中文是铁律，`Normal` / `YOLO` 是用户明示的专有名词（现行 chip「YOLO · 自动执行写入」已是混排先例），按用户指令优先保留英文原词。
- 铁律 11 满足：菜单是方向键选择器家族的输入态变体（↑↓+Tab+Esc），无数字答法；实现后需同步更新 AGENTS.md 的三处——铁律 11 的「现状注」、**验证要求一节的铁律 11 条目**（该节现要求「回车确认」用例，需改写为输入态变体的用例形态：↑↓ 移动 → Tab 补全 → Esc 收起 → 回车提交原文）、README 的交互描述（弹窗退役 + Ctrl+S + 满宽框 + 模式标签）。
- 建议动手顺序：满宽横线（最小，也是标签的地基）→ 权限模式标签 → Ctrl+S → 联想菜单（最大，动同一个拦截点与面积模型）；completer 移除与 Tab 拦截必须同一提交，逐条提交、逐条带测试。
