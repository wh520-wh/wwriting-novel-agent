# 会话辨认与输入面五项补齐：标题归档 / @引用 / 撤回排队 / 导出 / 输入历史 — 规格

> 来源：对照 Claude Code 2.1.88（`C:\Users\32694\Desktop\claudecode2.1.88`，sourcemap 未混淆源）
> 的能力盘点，由用户圈定五项。上游桌面版仍是能力与文案的规格权威；本文只在不与上游
> 冲突的空白处（会话辨认、输入辅助）立规矩。交互细节凡属本文单方拍板的，见文末「待回填」。

## Problem Statement

四件小事叠加，伤害的是「几十个会话、几十万字」的长篇使用形态：

1. **会话不可辨认**：`title` 永远是空串，`/sessions` 与 `/resume` 列表只有
   `UUID · 时间 · 状态 · N 轮`——挑不出哪本是哪本书；写完的一段也没法收起来
   （`session_archived` 事件有 fold 无生产者，`-c` 与挑选列表都不会藏它）。
2. **排队输入只能干等**：队列行挂在实时区，用户想撤回其中一条没有任何入口
   （`input_withdrawn` 事件与事件桥的「排队已取消」反馈都在，只缺用户面）。
3. **对话出不去**：讨论出来的大纲、设定只在会话里；没有导出命令。
4. **输入历史不跨进程**：readline 历史只在内存，重启即空；↑ 翻不到昨天的输入，
   更没有搜索。

## Solution

五张小票，全部走既有接缝（无新事件类型除 `session_renamed` 外、无新权限层级、
无第二控制面）：

- **T1 会话标题与归档**：首条输入自动起标题（`session_renamed`）；`/rename` 手工改名；
  `/archive` 归档当前会话并开新会话接续；列表与挑选列表带上标题、隐藏已归档。
- **T2 `/cancel` 撤回队首**：撤回队首排队输入（与 `/now` 的队首提升对称）。
- **T3 `/export` 导出对话**：全部轮次导出为 markdown，写进创作目录根。
- **T4 输入历史持久化 + Ctrl+R**：每工作区一份 JSONL 历史；Ctrl+R 打开历史搜索菜单
  （联想菜单家族的第二个输入态变体）。
- **T5 @文件引用**：输入中 `@` 触发文件联想，Tab 补全路径进草稿——纯文本引用，
  内容由模型经 read_file 自取。

## User Stories

1. 作为同时写两本书的作者，`/resume` 的挑选列表让我一眼认出「昨天那本」。
2. 作为写完一卷的作者，`/archive` 把它收起来，`-c` 与挑选列表不再被它占位。
3. 作为排队了三条输入又改了主意的用户，`/cancel` 把队首那条撤回来，屏幕上的排队行同步消失。
4. 作为想把大纲落盘的作者，`/export` 给我一份能直接进创作目录的 markdown。
5. 作为回头改稿的作者，Ctrl+R 搜「第3章」就能把上周那条输入原文调回草稿里改两个字重发。
6. 作为引用设定的作者，`@设定` 两下就把 `设定/人物.md` 补进草稿，不用拼路径。

## Implementation Decisions

### T1 · 会话标题与归档

- **D1 · `session_renamed` 事件**：`data.title` 非空字符串；fold 写入
  `projection.title`（畸形不更新，只推进 seq，与 `digest_compacted` 同纪律）。
  封面（state.json）的 `title` 字段本就存在，封面形状与锚点校验不变。
- **D2 · 自动标题**：会话句柄 `submit`/`enqueue` 时，若 `title === '' && turns === 0`
  且输入首行不以 `/` 开头（斜杠命令不是对话内容），在**同一批次**里先追加
  `session_renamed` 再追加输入事件（appendBatch 单批原子）。标题 = 首行 trim、
  内部空白压一、按码点截 24 字符。绝不覆盖已有标题；`/retry` 不触发（复用 inputId，
  能重试就说明已有轮）。
- **D3 · `/rename <标题>`**：追加 `session_renamed`（截 64 字符），允许运行中改
  （只动封面字段，serializeWrite 串行）。无参 = 回显当前标题 + 用法提示。
  主文案「已重命名」。
- **D4 · `/archive`**：忙碌拒绝。动作 = 当前会话追加 `session_archived`（控制器新
  API `archive()`）→ 创建并切换到全新会话（组合根注入 `archiveCurrent`，复用
  `switchSession`）。主文案「已归档」，detail「已开新会话接续」。
- **D5 · 归档的可见性**：`openLatest`（-c）跳过已归档（已有）；`/resume` 挑选列表
  过滤 `status === 'archived'`（0 轮空壳过滤照旧）；`/sessions` 仍列出（状态列已有
  「已归档」）。`--resume <ID>` 仍可打开归档会话——再次开跑（`run_started`）后
  status 自然回 active，「用它就是在写它」，不设独立的取消归档命令。
- **D6 · 行标签带标题**：`sessionRowLabel` 在标题非空时行首加标题段（两个空格分隔
  同旧）；标题为空的行与旧实现**逐字一致**（测试钉）。

### T2 · `/cancel` 撤回队首排队输入

- **D7**：控制器新 API `withdrawQueued()`：队列空返回 null；否则对队首调
  `session.withdraw`（既有事件 `input_withdrawn`，serializeWrite 串行），返回
  `{ input_id, text }`。命令层：队列空回「队列为空」（与 `/now` 同句）；成功回
  「已撤回」+ detail 原文首行（截 40 字符，多行加省略号）。运行中可用（这正是
  排队场景）；屏幕反馈零新增——事件桥对 `input_withdrawn` 的「排队已取消」
  终态行与实时区整表替换**已经存在**。

### T3 · `/export` 导出对话

- **D8 · 取舍层复用**：内容项来自 `buildReplay(events, { budgetChars: Number.MAX_SAFE_INTEGER })`
  ——全部轮次、零省略（导出是显式动作，不受屏幕预算约束；轮次取舍逻辑只有一份，
  不另写第二套）。工具过程行 / 确认卡 / 排队行同样**不导出**（P24 同判据）。
- **D9 · markdown 形态**：头部 meta（会话 ID、标题、导出时间本地时区、轮数）+
  每轮 `## 用户` → 思考耗时（斜体）→ 正文原样 → 终态状态行（斜体，文案用
  `terminalStatusText`——R5 同源，导出与屏幕说的是同一句话）→ 末尾附当前计划。
- **D10 · 落盘**：写**创作目录根**（用户显式命令即授权；应用私有历史照旧不进创作
  目录，导出物是用户要的作品资料）。文件名 `对话导出-<yyyyMMdd-HHmmss>.md`，
  重名自动追加 `-2`…`-99`（`wx` 探测），99 次仍冲突如实报「导出失败」。0 轮会话
  不写文件，回「还没有可导出的对话」。忙碌拒绝（导出半轮是假账）。
  成功主文案「已导出」，detail = 文件名。

### T4 · 输入历史持久化 + Ctrl+R 搜索

- **D11 · 存储**：`<workspaceDir>/input-history.jsonl`（应用私有区，铁律 8），每行
  `{ at, text }`。记录点 = 提交入口（onSubmit，含 Ctrl+S 与位置参数；空行与裸 `/`
  本就不提交）。相邻去重（与上一条相同跳过，由调用方传 `previous`）。上限 500 条：
  加载时截尾；加载发现超限即重写压缩。读 / 写失败静默降级（历史是增强，不值得
  打扰对话面）。
- **D12 · readline 播种**：`createInputReader` 接受 `history`（**最新在前**），
  `start()` 时灌进 readline 原生 `history`（`historySize` 提到 100）——↑ 在菜单关着时
  照旧翻历史，且跨进程成立。
- **D13 · Ctrl+R 历史搜索菜单**：联想菜单家族的**第二个输入态变体**（铁律 11 同族）。
  Ctrl+R 打开：查询 = 当前草稿整行（空 = 列最近），匹配 = 子串包含（ASCII 大小写
  不敏感），**最新在前**；↑/↓ 移动高亮；**Tab 或回车 = 补全进草稿，不提交**（与
  斜杠菜单的「回车提交原文」有意不同——误回车重发一整段旧输入比多按一次回车危险
  得多）；Esc = 收起并**退出**搜索模式（不带回）。搜索模式期间斜杠菜单与 @ 菜单
  抑制；再按 Ctrl+R = 选中下一条（经典 reverse-search 肌肉记忆）。提示行
  `HISTORY_MENU_HINT = '↑/↓ 选择 · Tab/回车 补全 · Esc 收起'`。Ctrl+R 必须拦在
  readline 自己的 reverse-i-search 之前。
- **D14 · 多行条目**：显示名 = 首行 + （多行时）`…`；补全进草稿的是**全文原文**。

### T5 · @文件引用

- **D15 · 触发与补全**：光标所在 token（光标前最近一段空白之后）以 `@` 开头即触发
  （行首斜杠命令位优先归斜杠菜单）。匹配 = 文件相对路径（`/` 分隔）含 `@` 后查询
  子串（大小写不敏感），路径短者在前；Tab 补全 = 用路径 + 尾空格替换该 token，
  菜单随之收起；回车 = 提交原文（与斜杠菜单同判，ADR-0022 家族）；Esc 收起、
  行变重开（与斜杠菜单同纪律）。
- **D16 · 文件清单**：组合根注入 `menuFiles`（返回 `[{ path }]`），来源 = 递归列
  创作目录的普通文件：跳过点开头目录/文件与 `node_modules`，上限 500，路径字典序。
  刷新时机 = 启动 + 每次提交后 fire-and-forget；失败降级空数组（菜单不开，打字照常）。
- **D17 · 语义 = 纯文本**：`@` 只把路径写进草稿——不注入文件内容、不经权限层
  （模型需要内容时经 `read_file` 自取，读取本就自动放行）。系统提示词补一行说明，
  让模型知道这个约定。
- **D18 · 共存**：三种菜单共用同一渲染槽与擦除簿记，优先级 = 历史搜索（显式进入）
  > 斜杠命令位 > @ 文件。`menuOpen()` 语义不变（屏幕上有菜单帧）。

## Testing Decisions

只测外部行为（铁律同前），按切片：

- **T1**：`session_renamed` fold（生效/畸形不更新）；自动标题——首条输入触发、
  第二条不覆盖、斜杠命令首输入不触发、create 时已有标题不覆盖、同一批次原子

  成功后旧会话归档且当前切到新会话；挑选列表过滤已归档；行标签带标题且无标题逐字
  一致。
- **T2**：`withdrawQueued` 队列空 null / 队首撤出且其余不动；`/cancel` 三态
  （空 / 成功 / 控制器抛错）；事件桥 `input_withdrawn` 屏幕反馈（已存在，回归确认）。
- **T3**：`buildExportMarkdown` 纯函数——meta 顺序、用户/思考/正文/状态四类项、
  plan 附加；落盘——重名后缀链、0 轮不写、忙碌拒绝、失败如实报。
- **T4**：存储——空/缺失/坏行跳过、500 截尾、相邻去重、写失败不抛；readline 播种
  （↑ 能翻到历史）；`historyMenu`——空查询全列、大小写不敏感子串、最新在前、
  补全为全文原文、多行显示名；输入层——Ctrl+R 开/收、Tab 与回车补全不提交、
  搜索模式抑制斜杠菜单、Esc 退出模式。
- **T5**：`fileMenu`——@ 触发、斜杠位不触发、光标中途的 token 判定、补全替换段、
  大小写不敏感、路径短者在前；`listRelativeFiles`——递归、跳点目录与 node_modules、
  上限、`/` 分隔；输入层——@ 菜单与斜杠菜单互斥、Tab 补全收起。

## 待回填（本文单方拍板、实现后可再议的交互细节）

1. **标题来源**选了「首条输入截 24 字」而非模型起名：零成本零延迟、客观（铁律 6
   的精神）；不满意可 `/rename`。若日后想要模型起名，`session_renamed` 事件不变，
   只换生产者。
2. **`@` 不注入内容**只补路径：权限面零新增、上下文零突变；Claude Code 的内容注入
   在「read 自动放行」的本项目里是多余的写法。若实测发现模型经常漏读，再议注入。
3. **历史菜单回车 = 补全不提交**：与斜杠菜单（回车提交原文）不同，提示行写明。
   理由见 D13。
4. **`/archive` 归档当前会话并自动开新会话**：把「收起来」和「继续写」合成一次动作；
   不做归档列表挑选（`/sessions` 可见 + `--resume <ID>` 兜底）。

## Out of Scope

- 多行输入编辑器与 `$EDITOR` 草稿（第一梯队另一项，单独走访谈）；
- `@` 的内容注入与 @目录；
- 历史搜索的模糊匹配 / 全文搜会话（Claude Code 的 agenticSessionSearch）；
- 模型自动起会话标题、`/tag` 标签体系；
- 取消归档命令、会话删除命令；
- 导出格式选项（仅 markdown）、导出到指定路径。
