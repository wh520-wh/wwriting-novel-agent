# 章节收尾两工具与 Run 级重试 规格

> 日期：2026-10-02 ｜ 来源：`docs/research/07-cli-vs-upstream-gap.md` 的 B1 收尾 + A2 选题，
> 契约依据：`D:/WWriting/docs/design/统一行为规格书.md` §4.1/§4.3、round8 规格 D1–D4、round9 规格 §2.2。
> 上游是规格权威；本文件记录 CLI 的适配决策与偏差。

## Problem Statement

1. **修订无处入账**：模型用通用修改工具改完一个已提交章节后，没有「重新入账」的合法通道——重复提交会在账本上伪装成新的一次定稿，不提交则账本与正文脱节；回滚也只会回到最初提交，修订成果没有版本保护。
2. **设定无受管存储**：事实、时间线、角色状态只能散写进正文或 WWRITING.md，长篇一致性没有唯一真相源；模型也可能顺手改坏它们。
3. **失败只能重打**：Run 失败或崩溃中断后，用户必须把原文重新打一遍才能再跑；崩溃恢复规则明确「需用户手动重发」，但没有便捷的重发入口。

## Solution

- 新深工具 **`finalize_revision`（入账章节）**：把已提交章节的修订状态重新入账——存版本快照（账本 `revision` 条目）+ 记前情口径字数；回滚目标同步扩为「最近一次生效版本」（提交或入账），安全网快照仍不作回滚目标。
- 新深工具 **`update_memory`（更新设定）**：项目 `memory/` 目录下的结构化设定档案（continuity.json + 渲染打印件 continuity.md）的唯一合法写通道；系统做参数校验、幂等合并、原子落盘与重渲染；通用文件工具对 `memory/` 只读并在拒绝时指路；提交/入账/回滚结果附记忆维护提醒行；提示词加纪律两行。
- 新斜杠命令 **`/retry`**：把最近一次失败（或非用户停止的中断）的轮次用原输入重跑，恢复同一 run，不新建会话轮次；已完成与用户主动停止的轮次不可重试。

## User Stories

1. As a 写作用户, I want 模型改完已提交章节后把它重新入账, so that 版本账本与前情如实反映修订而不撒谎。
2. As a 写作用户, I want 回滚恢复最近一次生效版本（含修订入账后的版本）, so that 回滚不会跳回修订前丢掉成果。
3. As a 写作用户, I want 设定档案由专用工具受管更新（校验、合并、幂等）, so that 长篇设定一致且有唯一真相源。
4. As a 写作用户, I want 通用文件工具碰不了设定档案, so that 误操作改不坏它们，且被拦时知道合法通道是什么。
5. As a 写作用户, I want 一条命令重试刚才失败或中断的输入, so that 不用重新打字。
6. As a 写作用户, I want 用户主动停止的轮次不会被重试, so that 「停止」的语义保持干净。

## Implementation Decisions

**共同适配原则**：语义、门禁方向、中文标签照上游（标签表：`入账章节`、`更新设定`）；参数与存储按 CLI 的「相对路径 + 应用私有账本」体系适配，偏差逐条记录。

1. **路径体系**：两工具都以章节文件的相对路径为引用键，替代上游的 `project_id`/`chapter_no`；不带 `expected_checksum`——CLI 无章节索引与校验和体系，终端单会话串行无多写者覆盖风险。
2. **入账门禁**：路径从未提交过 → 一行中文事实拒绝（对齐上游 `chapter_not_committed`），不写任何东西；已提交则放行。
3. **回滚目标扩展**：回滚目标从「最近一次提交」扩为「最近一次提交或入账」（上游 round8 D4：回滚恢复最近生效版本）；回滚前的安全网快照仍不作回滚目标。提交/回滚/入账三个工具的 description 同步改写。
4. **设定档案存储**：`<项目根>/memory/continuity.json` + `memory/continuity.md`。不变量照上游：md 恒等于 json 的渲染打印件（只有工具触发重印）；档案内容**永不注入**系统提示词或上下文（缓存友好），模型按需用读取工具看。与 WWRITING.md 分工：WWRITING.md 每轮注入（项目记忆入口），设定档案不注入。属创作项目数据，不违反数据边界铁律。
5. **参数与阈值照上游**：facts / timeline / characters 三组；quote ≤ 80 字、三组各 ≤ 50 条、单条事件串 ≤ 10、traits ≤ 10、单实体 facts ≤ 20。
6. **合并语义照上游**：facts 按 实体+属性+值 去重，同属性不同值标冲突（照实记、不调和）；timeline 按章+事件串去重；characters 按名合并特征与最新状态；整体幂等（重复调用安全）。
7. **轻量门禁**：只校验引用的章节文件在磁盘上存在，不比指纹、不强制先入账；不存在时错误文案点名该文件。
8. **时间线冲突检测第一版不搬**：返回的 violations 如实为空数组，代码注释记录「上游检测未实现，空 ≠ 检测通过」——与「检测失败≠检测通过」的既有纪律同源。
9. **返回契约**：`{ ok, path, facts_added, timeline_added, characters_added, timeline_violations }`。
10. **文件保护（新机制：目录级保护）**：写入/修改/追加/回滚落盘/删除类工具命中 `memory/` 一律拒绝，拒绝文案指路 update_memory（「记忆档案为系统文件，只读；设定档案请用 update_memory 工具更新。」）；读取放行。
11. **权限分级**：`finalize_revision` 只写应用私有存储 → 与提交同级自动放行；`update_memory` 写创作目录 → 写级确认，确认卡说「更新设定」。
12. **记忆维护纪律（上游三件套的 CLI 两件化）**：提示词加两行——「memory/ 记忆档案只读；设定档案请用 update_memory 工具更新」「提交/入账/回滚后必须依次：update_memory → 更新 WWRITING.md，两件缺一不得声称完成」。CLI 无 book_summary.md / WORKLOG.md，其职能由 WWRITING.md 承担（偏差记录）。
13. **固定提醒行**：提交/入账/回滚三个工具的成功结果附一行写死的提醒（内容不随状态变化）：`记忆维护：请依次 update_memory → 更新 WWRITING.md`。
14. **/retry 的可重试判定**：从事件日志取最近一条 `run_failed`，或 `run_interrupted` 且原因不是用户停止的轮次；原文取自该输入的提交事件。最近终态是已完成或用户停止 → 一行事实「没有可重试的失败轮次。」
15. **同 run 恢复**：复用原输入的 input_id 与原文重跑——历史装配的「排除当前输入」逻辑因此天然把失败尝试排除出上下文；run_id 优先复用原 id（忠实「同一 run id 恢复」），若实现验证与恢复逻辑的唯一性假设冲突，则改用新 id + `retry_of` 字段记录原 id（偏差记录）。
16. **忙碌语义**：运行中调用 `/retry` → 一行拒绝（与 /compact 同法）；终端天然串行，无需上游的按钮防连点等价物。

## Testing Decisions

- **只测外部行为**：服务级测试（临时目录 + 可注入 fs，章节服务既有测试为先例）验证账本条目、快照文件、合并幂等、渲染恒等；工具工厂装配级测试（真临时创作目录 + 临时私有数据根）验证端到端行为与拒绝文案；重试测试在事件存储层验证判定与恢复语义，不 mock 内部调用次序。
- **先例**：章节服务测试（临时目录注入）、技能服务测试（真实临时目录）、终端命令测试（命令表分发）。
- 关键用例随各工单验收标准列出；全部「测试先行，全量回归绿」。

## Out of Scope

- 上游 `checkTimeline` 时间线冲突检测（violations 恒空，如实记录）。
- 记忆维护传感器（Run 收尾比对 mtime、`memory_maintenance_lag` 审计事件、prompt 注记注入）——CLI 靠提醒行与提示词纪律，传感器是后续可选件。
- `book_summary.md` / `WORKLOG.md` 两文件的引入（用 WWRITING.md 承担）。
- 自动压缩（已裁决：手动 /compact，见 ADR-0015）、自动记忆提取/后台提取器。
- 多会话防覆盖 checksum、web_search、shell 工具、分片 journal、会话注册表（各自选题，见 07 差距文档）。
- 铁律 4 极端操作确认流不变；`/retry` 非选择题，不受铁律 11 约束。

## Further Notes

- 偏差清单（相对上游）：无章节索引/校验和体系（`expected_checksum` 不做）；两件套替代三件套。
- **偏差定稿（2026-10-02 实现期）**：`/retry` 的 run_id **不复用**——思考重放按 run_id 归堆（`src/agent/replay.mjs` 的 `reasoningByRun`），复用会让失败尝试的思考并进重试轮；「同一 run 恢复」由 `run_started.data.retry_of`（指向原 run id）+ 复用原 `input_id` 承载。已回填 `docs/research/07-cli-vs-upstream-gap.md`。
- 实现期补充裁定：`/retry` 在队列非空时也拒绝（排到队尾不是「重试刚才那次」的语义）；`memory/` 保护的别名路径（junction/symlink 指向 memory/）按真实路径判定，不能绕过。
- `update_memory` 落地后，CONTEXT.md 术语表可增补「设定档案」条目（随术语敲定逐条增补的惯例）。
