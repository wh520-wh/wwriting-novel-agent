# 会话存储有界化：state.json 封面化 + 读侧有界 + 打开锚点 — 规格

> 日期：2026-10-06 ｜ 状态：**ready-for-agent**（方案先经两路调查核实——上游桌面实现与
> Claude Code 2.1.88 原始源码（`<LOCAL_PATH>`，证据取自包内
> sourcemap 的未混淆 TS 源），再按本仓库消费面逐点核对；偏差裁决见 ADR-0024）

## Problem Statement

会话存储的**读路径全是全量读**，而写路径无界增长，四个事实叠加：

1. **每轮开工全量读日志**：`loadHistory`（`src/agent/run-controller.mjs` 的 `readAll()`）在
   每一轮开始时把整个 `events.jsonl` 读盘、逐行 parse、seq 连续校验、`projectTurns` 折算。
   思考正文全量落盘（ADR-0012），单轮成本 O(日志总量)，整场长篇会话 O(N²)。
2. **裸启动与 /resume 全量扫**：`session-manager.list()` 对**每个**会话目录全量读日志 +
   `projectTurns` 再扫一遍，只为拿标题、时间、轮次；`openLatest`（裸启动与 `-c`）每次都走。
3. **`state.json` 只写不读**：每条 append 都原子重写一次投影，但全 src 没有任何读方——
   它本可以是「打开会话不全量重放」的锚点、`list()` 的数据源，现在是纯落盘仪式。
4. **无退出机制**：日志只增不减（与上游一致）；空壳会话随裸启动逐日累积。

本机实测（2026-10-06）：单工作区 3.1 MB / 14 会话，最大 984 KB / 1666 行。今天痛感为零，
成本乘在「每轮」上且随小说长度线性涨——这是**便宜的奠基**，不是救火。

## Solution

**不分片、不建注册表**（裁决见 ADR-0024：与上游 §19/§24 的分片方案有意偏差，与
Claude Code 的 append-only 实践同向）。布局不变、零迁移，做三件事：

1. **T1 封面化**：投影加 `turns` 计数，`state.json` 成为每会话的「封面卡」——
   `list()` 改读它，缺/坏回退全量折算（只读，不自愈写）。
2. **T2 读侧有界**：event-store 新增**从尾部按字节块回读**的原语；
   `loadHistory` 与 `/retry` 判定改为有界读，每轮成本从 O(日志总量) 降到 O(预算)。
3. **T3 打开锚点**：写者打开会话时校验 `state.json.last_seq` 后只增量重放尾部，
   大会话打开不再全量折算。

## User Stories

1. 作为写到几百轮的长篇作者，我每轮开工的等待不再随日志变长而变长。
2. 作为带着几十个历史会话回来的用户，裸启动与 /resume 的列表不再把每个会话的日志读一遍。
3. 作为用户，屏幕上「省略更早 N 轮」必须不说谎——窗口截断看不到的轮数不冒充精确数。
4. 作为老用户，我存量会话不做任何迁移，升级后第一次打开照常工作。

## Implementation Decisions

### D1 · 投影加 `turns`（T1）

- `blankProjection()` 增加 `turns: 0`；`applyEvent` 的 `run_started` 分支 `+1`。
- 语义与 `projectTurns(events).length` 逐字一致（每个 `run_started` 一轮，含 open/重试轮）——
  两者必须同值，`/resume` 列表的数字不许因数据源切换而变。
- `turns` 字段的在位性兼作 state.json 的**版本标记**：旧缓存没有它 → 回退折算。

### D2 · `list()` 读封面，回退不写（T1）

- 每会话先读 `state.json`：JSON 可解析、`session_id` 与目录名一致、`last_seq` 为非负整数、
  `turns` 为数字、`updated_at`/`status` 在场 → 直接出摘要，**零日志 I/O**。
- 任一条件不满足 → 回退现行为（全量读 + fold + projectTurns），**保持 `list()` 只读不取锁的
  纪律**：不把折算结果写回 state.json（自愈交给打开写者时的 `repair()`，它本来就重写）。
  理由：list 无锁写 state.json 会与并发写者的原子重写竞争，为一个便宜的兜底引入新竞态不值。

### D3 · 有界读原语（T2）

event-store 新增 `readTail({ maxBytes, untilSeq })`：从 EOF 按字节块（256 KiB）**向前回读**，

- 只收**完整行**（文件起点前的半个首行不算事件，与 `readRaw` 尾行语义对偶）；
- EOF 尾行不完整 → 如实报 `truncatedTail`（与 `readRaw` 同判据）；
- 回读收集到 **seq ≤ untilSeq** 的事件即停（该事件不含）；
- 回读字节累计 ≥ maxBytes 或到达文件起点即停；
- 返回按 seq 升序的完整事件数组 + 停止原因（`fileStart | seqBoundary | byteLimit`）。

不做 seq 全程连续校验（那是全量读的仪式）；逐行仍走既有 parse 校验，坏行照抛不静默。

### D4 · `loadHistory` 有界化（T2）

- **有摘要**：回读 `untilSeq = digest.throughSeq`——摘要文本就在 `digest_compacted` 事件的
  data 里，`latestDigest` 语义改为「回读路上遇到的第一条」（即最新一条）；
  `coveredTurns` 精确值 = 回读路上累加所有 `digest_compacted.covered_turns`
  （多次压缩的情形：较晚摘要的覆盖轮不含较早摘要已覆盖的轮，求和恰为总数）。
- **无摘要**：回读直到窗口内**完整轮**的可见字符合计 ≥ `historyBudget` 再多一个完整轮
  （对齐 `buildHistoryMessages` 从新到旧装到预算为止的语义——预算装满后更早的轮必被丢，
  不读它们不改变结果），或到文件起点。当前输入排除（`/retry` 重跑同一条输入）后若不足
  预算，继续补读一个块。
- **诚实计数**：`truncatedTurns` 在窗口到达文件起点时精确；被 `byteLimit` 截断时只知
  下界——`historyMeta` 新增 `truncatedExact: false`，事件桥文案随之变
  「省略更早 N+ 轮」（铁律 3：宁可少说，不可编数）。摘要覆盖数永远精确（见上），不加号。
- 等价性要求：窗口未截断（到达文件起点或 seq 边界）时，产出的 messages 与全量读**逐字节一致**；
  该等价性是测试钉住的契约，不是愿景。

### D5 · `/retry` 判定有界化（T2）

`findRetryableTurn` 只看最近一条终态：回读直到收集到至少一个 `run_started`
（最新一轮完整在窗口内）即停；回读失败或畸形时回退全量读。语义与全量读严格一致
（它本来就只用最后一轮）。

### D6 · 打开锚点（T3）

- `loadForWrite` 先试锚点：读 `state.json`（校验同 D2，另加 `turns` 必须在场）→
  `readTail` 回读，窗口内必须存在 **seq == state.last_seq** 的事件（且 session_id 一致）
  → 锚点成立：以 state.json 为投影初值，只把 seq > last_seq 的增量事件（通常为零条）
  依序 fold，`rememberedSessionId` 取自封面。
- 锚点不成立（文件缺/坏/形状不对/last_seq 不在尾部窗口）→ 整体回退现全量折算路径。
  回退永远可用，锚点只是快路。
- 尾行截断语义不变：回读检测到 EOF 半行 → `tailInfo` 照旧记 `truncated`，
  `repair()` 照旧截断并补 `log_tail_truncated`。
- **fold 的 `inputs` Map 不进封面**（那等于把全对话文本再存一份）。`applyEvent` 的
  `run_started` 取输入文本改为三级回退：队列项（刚 splice 出的那条自带 text）→
  `active_input`（当场提交的）→ `inputs` Map（跨锚点丢失时的兜底为 null——
  排队跨锚点开的轮由队列项兜住，孤立文本丢失只影响投影展示字段，不影响历史装配，
  `loadHistory` 的轮次文本来自 `run_started.data.text` 事件本体）。

### D7 · 维持全量读的两处（明确的非目标）

`/compact`（空闲手动，需要全量未覆盖账）与 `/replay`（显式重演，readEvents）
继续 `readAll()`。它们是低频显式动作，不在本轮 bounded 化范围。

## Testing Decisions

只测外部行为（铁律同前），按切片：

- **T1**：`run_started` 计数进投影；`list()` 走封面（封面齐全时不再触发日志读——
  以「封面存在且正确时摘要字段逐项等于全量折算值」钉）；封面缺失/损坏/session_id 不符/
  旧形状（无 turns）各一条回退用例；回退后 `list()` 输出与旧实现一致。
- **T2**：`readTail` 的停止三态与半行/尾行语义；`loadHistory` 等价性矩阵——
  （无摘要/有摘要）×（窗口未截断/被截断）下 messages 与全量读一致；多轮多次压缩的
  coveredTurns 累加；`/retry` 重跑同一条输入的排除语义；`truncatedExact: false` →
  屏幕文案「省略更早 N+ 轮」；`findRetryableTurn` 有界 == 全量。
- **T3**：锚点命中（重开零增量）；state.json 滞后一批的增量 fold；锚点各失效形态
  （坏 JSON / 无 turns / last_seq 不在尾部）回退全量；排队输入跨锚点开轮文本不丢；
  EOF 半行 + 锚点并存时的截断修复。

## Out of Scope

- 分片 journal、稀疏索引、manifest、会话注册表（sessions/index.json）——ADR-0024 有意不做；
- `/replay` 流式化与 `/compact` 的读取范围裁剪；
- 空壳会话清理（裸启动留壳是 ADR-0010 的既定语义，封面化后它们的 list 成本已趋近于零）；
- 投影里除 `turns` 外的任何新字段。
