# 技能分区（skills）规格

状态：ready-for-agent · 2026-10-01
决策记录：CONTEXT.md（术语）、ADR-0013（发现根裁剪）、ADR-0014（摘要注入 + 渐进读取）
上游权威：`D:\WWriting\src\core\skills\*`、`core\agent\prompt.mjs`、`core\agent\tools\definitions-knowledge.mjs`（只读）

## Problem Statement

CLI 的写作 Agent 手里只有文件工具和字数统计：写悬疑章没有类型公约可依，定文风没有基座可循，更没有「展示而非陈述」这类技法约束。上游桌面版已有一套「Agent 技能」机制（12 个内置写作规则包 + 完整的发现/读取契约），CLI 缺这一分区——同一个用户在两边得到的写作纪律不一样，自己写的技能包也没法在 CLI 里生效。

## Solution

开箱即有：12 个内置技能随 CLI 自动被发现。用户把技能文件夹放进 `~/.wwriting/skills`（与桌面版共用）或项目的 `skills/` 目录即生效，项目级同名可覆盖全局/内置。Agent 写作前按 基座/修饰/流派 分层选型：摘要（每技能一行）常驻 system 消息，全文经 read_skill 工具渐进读取；选型结果写进 WWRITING.md 写作风格区，跨会话延续。`/skills` 命令让用户一眼看到哪些技能生效、哪些被覆盖。

## User Stories

1. 作为小说作者，我想 CLI 自动发现内置的 12 个技能包，以便不做任何配置就有风格纪律。
2. 作为小说作者，我想把技能文件夹放进 `~/.wwriting/skills` 或项目 `skills/` 就生效（项目同名覆盖全局/内置），以便自定义规则与桌面版资产互通、且能在单个项目里做覆盖。
3. 作为小说作者，我想 Agent 动笔前按题材/风格自动选技能并读取全文，以便章节受类型公约与技法约束而无需我每次手工提示。
4. 作为小说作者，我想选型结果（技能/修饰/流派三行）写进 WWRITING.md 写作风格区，以便下一章与下次会话延续同一套风格，且我能手工修改。
5. 作为小说作者，我想 `/skills` 列出生效技能（标签/名称/来源/描述）与被覆盖项，以便确认放进去的技能被识别、没被同名高优先级副本盖掉。
6. 作为小说作者，我想技能正文不占常驻上下文（只注入一行摘要，read_skill 按需读），以便长会话的上下文预算不被用不上的规则文本吃掉。
7. 作为小说作者，放了一个坏技能目录（frontmatter 缺失、name 与目录名不符、超大小）时，我想它只被跳过并在 `/skills` 里报告，以便一个坏包不拖垮其余技能。
8. 作为小说作者，read_skill 要一个不存在的技能名时，我想得到一条可理解的错误事实（错误码只进详情），以便知道是名字错了而不是能力坏了。

**明确排除**：不提供技能导入/删除命令（装删 = 直接操作目录）；不做 legacy 迁移；不改 12 包内容。

## Implementation Decisions

1. **发现契约照抄上游冻结契约**（ADR-0013）：三个发现根——内置（仓库自带）、全局 `~/.wwriting/skills`、项目 `<项目根>/skills`；生效优先级 项目 > 全局 > 内置，同名低优先级进被覆盖（shadowed）；每根只扫直接子目录，含合法 SKILL.md 才算技能；单目录解析失败进 errors 不拖垮整层；根缺失/不可读 = 该层无技能。
2. **frontmatter 契约照抄**：`name` 必填且必须等于目录名（Windows 大小写归一），`description` 必填，SKILL.md ≤512KiB；`metadata.wwriting` 的 category/display_name/scope/priority/hooks 保留但 hooks 不解释不执行。分类映射：writing-style→基座、style-modifier→修饰、genre→流派，无分类不带标签。
3. **12 个内置包整包拷贝**进仓库（上游冻结文本，逐字节不改动，含 3 个无分类的旧式包）。
4. **服务面只做 catalog + read**：catalog 返回 生效/被覆盖/失败 三组；read 只按生效清单解析名字，未命中报「未发现技能：名字」；路径安全照抄（资源 realpath 不可逃逸技能目录；SKILL.md ≤512KiB、其他资源 ≤1MiB；前 8KiB 含 NUL 判二进制，二进制只报路径与字节数不进上下文）；错误为 SkillError + 小写下划线码，文案逐字对齐上游。
5. **目录块注入**（ADR-0014）：agent-loop 新收可选 skillCatalog 参数，块拼在 system 消息里项目记忆段之后（system 末尾）；格式与政策文案逐字对齐上游——`[Available Skills]` 头 + 目录 intro + 每技能一行 `- [标签] name: description` + 分层选型规则（基座恰选一、修饰 0–3、流派按题材可叠加，选型结果写入 WWRITING.md 写作风格区，全文分层读取）；无技能时整块省略，不造占位。
6. **清单按 runId 缓存、失败返空数组不阻塞**（照抄上游 runtime 语义）：会话中途增删技能目录，下一轮输入生效。
7. **read_skill 工具**：参数 schema 照上游（name 必填，resource 可选默认 SKILL.md，可读 references/…、assets/…）；工具描述照上游「读取已发现 Agent Skill 的 SKILL.md 或其安全资源。」；实现合并进默认工具工厂（文件工具之外多一个 readSkill 方法，按名字映射解析）；权限归类**只读自动放行**，动作展示「读取技能」。
8. **WWRITING.md 骨架新增「## 写作风格」空区**（选型规则负责填写三行；设计草案同步补记）；已有项目的旧 WWRITING.md 不动，Agent 按选型规则自行写该区。
9. **`/skills` 命令只读**：列出生效技能（标签/名称/来源/描述）、被覆盖项（文案对齐桌面版「被更高优先级同名技能覆盖，不生效。」）、解析失败项；零选择交互；来源标签照桌面版映射（项目/全局/内置）。
10. **铁律对齐**：/skills 纯信息输出，不建第二控制面（铁律 1）；read_skill 只读自动放行（铁律 4）；全部新文案简体中文（铁律 10）；无数字答法（铁律 11）。

## Testing Decisions

- 好测试只测外部行为：服务层用真实临时目录 + 注入 userHome/内置根（沿用现有 makeTempRoot 惯例），断言 catalog/read 的返回与错误形态，不 mock fs。
- **接缝**：唯一新接缝是「技能服务可注入」——组合根创建真服务，测试注入临时根服务；其余全部复用现有接缝：agent-loop 参数（fake model 捕获 messages/tools 的既有模式）断言目录块位置与 read_skill 往返；命令依赖注入（renderer.calls 记录模式）断言 /skills 输出；项目记忆骨架断言（现有 project-memory 测试）覆盖写作风格区。
- 移植类用例对齐上游 tests/skills 的语义：同名覆盖、单包失败隔离、name 与目录名不符、frontmatter 缺失、路径穿越拒绝、大小上限、二进制判定、空目录返空。
- 每个家族测试先行（红→绿→提交），沿用现有「顶层平铺 test + 文件头覆盖面注释」风格。

## Out of Scope

- importSkill / removeSkill / ZIP 导入 / legacy 迁移（ADR-0013 Consequences：等出现第二个技能来源再移植）。
- bundled 发现根（CLI 无打包形态）。
- 桌面版式技能管理面板；CLI 只有只读 /skills。
- hooks 字段的运行时执行（上游也不执行，纯惰性数据）。
- 12 包内容的任何改动（上游是规格权威）。

## Further Notes

- **文案权威**：目录块两段政策文案、分类标签映射、错误文案在访谈期间已从上游逐字抄录核对，实现时以 `core\agent\prompt.mjs` 与 `core\skills\*` 原文为准再核一遍。
- 12 包中 3 个无分类（旧式包），目录块里不带标签出现——照上游行为，不补分类。
