# 裸启动开一个全新会话，「接着上次」由 -c 显式表达

`wwriting`（不带任何参数）开一个**全新会话**。接着最近会话要显式写 `-c` / `--continue`；
恢复指定会话用 `--resume <ID>`，会话内用 `/resume`（无参时打开交互式挑选）。

**Context**：此前裸启动等于 `--continue`
（`args.mjs` 里 `continueLatest = continueExplicit || (prompt === null && resume === null)`）。
双击 `publish and run.bat` 出来的窗口因此会**默默续上最近的那个会话**——
可能是一个几个月前的、写在另一个题材上的会话。用户看不到这个选择被做过，
只会在模型张口就叫出一个陌生主角名字时才发现。

**Considered Options**

- **保持裸启动 = 接着上次，只让启动脚本显式带「新建」参数**：改动最小。
  但命令行用户（不走启动脚本的那批）仍然会踩同一个坑，而「什么都没写」
  被解释成「续上最近会话」本身就是一次静默的、有后果的推断。
- **裸启动 = 全新会话（选中，对齐 `claude`）**：什么都不写就是最小惊讶——
  开一个新的。「接着上次」是一个**有后果的选择**，该由用户显式做。

**Consequences**

- **这是破坏性变更**。`tests/acceptance/main-path.test.mjs` 里「进程 B 不带参数即 --continue」
  那条用例、`scripts/smoke-windows.ps1` 的相关断言、README 的「启动形式」一节都随之改动。
- 启动脚本 `scripts/launcher.ps1` **不需要改**：它拼的命令行本来就不带会话参数，
  语义反转后自然变成「全新对话」，正好是想要的默认。
- 老用户找回旧会话的路径变长了：`wwriting -c`，或 `wwriting` 之后 `/resume` 挑选。
  换来的是「不会在不知情的情况下续上一个陌生会话」。
- **会产生 0 轮的空会话**。裸启动即刻建会话（沿用原先「带一条消息启动」那条分支的做法：
  `create` → `close` → `openController`），所以每次双击启动又立刻退出，都会在私有目录里
  留下一个空壳。它不进 `/resume` 的挑选列表（Task 13 Step 9 按 `turns > 0` 过滤），
  但仍在 `/sessions` 里可见、仍能用 `--resume <ID>` 打开——所以这不是丢数据，
  只是私有目录会慢慢堆空壳。真要清，正确做法是给 `/sessions` 加一条「归档空会话」的动作
  （`session_archived` 事件已经存在），**不是**推迟建会话——推迟建会话会让
  「启动即取写锁」这条既有不变量出现一个没有锁的窗口。
- 屏幕重演（ADR-0011）让 `-c` 这条路可用：接着上次会话时，上一轮对话会重新显示出来，
  用户因此能立刻确认「我续上的是哪一个会话」。这两条决策是配套的。
