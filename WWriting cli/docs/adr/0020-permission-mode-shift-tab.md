# 权限模式切换：Shift+Tab 二态环（普通 ↔ YOLO），开启需确认卡，仅空闲可切

`permissions.mjs` 的 `setYolo/isYolo` 从第一版就在，但没有任何生产入口能打开 YOLO——
它只活在测试里。本决定补上终端入口：**Shift+Tab 在普通 ↔ YOLO 之间翻转**，权限分级
（铁律 4）的语义一个字节不动。

上游规格对 Shift+Tab 是**空白项**（两份规格书均无此交互，2026-10-04 已核查）；但既有
条款划定了边界，本决定在边界内落位：

- YOLO 的定义（统一行为规格书 §16）：跳过普通确认、放开项目外目录；**extreme 与
  受保护路径的精确文字确认绝不放行**——permissions.mjs 的既有实现已是如此，本功能
  只是接通开关，不改判定。
- YOLO 的开启确认文案（§16 / 设置页条目）：`YOLO 会自动执行写入和控制操作。确认开启？`——
  确认卡标题逐字用它。

## 决定

1. **二态环**：普通 ↔ YOLO，没有第三态。上游桌面版有「权限模式」下拉（§4.7），终端
   对应物是这一个键；项目没有 plan/auto 概念，二态就是全部。
2. **进 YOLO 要确认卡，退出不要**：变弱的一侧（解除全部写确认）必须有关把——误按一次
   Shift+Tab 不该直接放行所有写入。确认卡走 `pick`（让位 + 方向键选择器，铁律 11：
   只有 ↑/↓ + 回车，不提供数字答法），Esc / 「先不开」= 不开启且**留一行取消痕迹**；
   退出是收权，即时生效、无卡、无成功状态行（铁律 3：chip 消失就是全部反馈）。
3. **仅空闲可切**：`controller.isBusy()` 时按键只回一行「运行中」（与 /retry 同款）。
   翻转时必然没有运行轮，「对哪一轮生效」因此没有歧义；也避开确认卡与运行中的工具
   确认卡抢键。规格 §4.7 的「正在执行的 Run 不变，从下一条输入生效」语义不需要——
   空闲判据让生效时机天然无歧义。
4. **警示 chip 常驻实时区**：YOLO 期间输入框上方一行 `YOLO · 自动执行写入`（warn 色，
   `renderer.setLiveMode`，合成链末尾贴输入框）。P8 权限警告必须保留——它就是要常驻的
   那条；合成进既有实时区（动态行 → 排队 → 计划 → chip），不新开 UI 区域（P15）。
5. **不持久化，/resume 重置**：跟会话走（与思考强度同款，P16）；切换会话时
   `permissionMode.set('normal')`——权限弱化状态绝不静默跨会话，新会话的用户不该被
   上一会话的 YOLO 罩着。
6. **按键捕获在 readline 之前**：`input.mjs` 包 `rl._ttyWrite`（与 `attachAreaHooks`
   包 `_refreshLine` 同一纪律）。必须抢在 readline 内部消费之前：配了 completer 时
   Node 把 `\x1b[Z` 归一为 `{name:'tab', shift:true}` 并**与 Tab 一样触发命令补全**
   （实测），不拦就是误触补全。非 TTY 无此路径；`_ttyWrite` 不可用时退化为既有行为。

**Considered Options**

- **免确认直切（grokbuild 的做法：横幅警示）**：更快，但误按一次就解除全部写确认；
  本项目铁律 4 的分量比少按一次键重，且规格已有现成的确认文案。
- **运行中也可切（§4.7 语义）**：chip 立即变化、正在跑的轮保持原模式。语义可行，
  但确认卡会浮在运行轮上方、与工具确认卡抢让位；收益（省一次等待）配不上复杂度。
- **三态环（普通 → 只读 → YOLO）**：项目没有「只读模式」概念，为环的形状造一个状态
  是本末倒置。
- **/yolo 斜杠命令**：与 Shift+Tab 不互斥，但敲四个键做的事不该比按两个键更常用；
  且命令面板会多一条高风险常驻项。未做——键位先行，命令待真实需求。

**有意不做**：不改 permissions.mjs 的任何判定；不持久化到配置文件；不在启动面板加
常显模式行（启动必为普通，常显是噪音）；不提供「输入数字 1 = 确认」的答法（铁律 11）。
