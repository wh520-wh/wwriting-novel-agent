# 屏幕重演与模型记忆共用同一份预算

重启后重演到屏幕上的轮次，与回喂给模型的轮次，是**同一批**——
`buildReplay` 直接问 `buildHistoryMessages` 保留了几个尾部轮次，绝不自己再算一遍预算。

**Context**：这个 CLI 原来没有屏幕回放这件事。`--continue` 只把历史回喂给模型
（`src/agent/history.mjs`），屏幕上从不重演过去的轮次：重启后用户面对的是
一个启动面板加一个空输入框。于是会出现「模型记得、屏幕看不到」——
模型张口就叫出主角的名字，用户却完全不记得自己写过。这是明确要堵的洞。

**Considered Options**

- **全保真重演**（工具行、确认卡、排队行、终态行全按当时的样子重画）：最忠实，
  但一个几十轮的会话重启后要刷好几屏，而用户要找回的是「我们写到哪了」，不是过程。
- **重演最近 N 轮**（按轮数）：好预测，但与模型记忆的口径不一致——
  模型那边是按**字符预算**截的，两套口径迟早分歧。
- **不设上限、全部重演**：一个写了三个月的会话重启时可能要刷上百屏。
- **共用模型记忆的预算与取舍（选中）**：屏幕与模型对得上，且只有一套取舍逻辑。

**Consequences**

- **不变量：屏幕 ⊇ 模型（限于对话内容）**。屏幕上看得见的绝不少于模型记得的。
  唯一的边界情形是「最新一轮单独就超过整个预算」，此时模型拿到的是被截尾的正文、
  屏幕重演全文——方向是安全的。
- **一个如实记录的残余缺口**：`history.mjs:153-160` 会把工具摘要
  （`· count_text 第一章.md · 3210 字`）折进喂给模型的 assistant 消息，
  而重演不画工具行。所以「模型记得某次统计得到 3210 字、屏幕上没有」仍然成立，
  P26 因此**只在「对话内容」这一层完全成立**。
  这个缺口被 `tests/agent/replay.test.mjs` 里那条 `P26 的已知残余缺口` 用例钉住——
  它断言的就是「缺口存在」，谁想声称 P26 无条件成立，会先撞红它。
  补它的正确做法是重演一行极简的工具摘要（如 `· 用了 3 个工具`），
  而不是把全部工具行重演回来（那就退回了被否决的「全保真」方案）。
- 重演**不含**工具过程行、确认卡、排队行：它们是过程不是内容。
  代价是重启后看不到「上一轮改了哪个文件」，收益是屏幕不会被几十行 `✓ 读取文件` 冲掉。
- **状态文案与事件桥共用 `terminalStatusText` 一份定义**。重演出来的历史轮与刚跑完的
  当前轮因此**共用同一句状态文字与色调**：`已停止` 与 `已中断` 分得开，`连接中断` 不会被糊成
  `操作失败`，`未配置` 也不会变成 `操作失败`。agent 层只带判据（terminal / interruptReason / failCode），
  文案由终端层查表——分层不破，文案不重复。
  注意重演行只画 `status.text` + tone：live 终态行上的用量后缀 `· 1.2k tokens（思考 800）`
  与失败原因 detail **不会**跟着重演——那些属于当场那一轮（`replay.mjs:46`）。
- 思考项重演为 `思考 N 秒` 终态行，**不重演全文**。全文只经 `/reasoning` 查看，
  且只有本次进程内的上一轮——思考正文虽然全文落了盘，跨重启的全文重放
  需要先把整个会话展开，那与「默认折叠」的语义相反（见 ADR-0012）。
- 重演发生在启动面板之后、常驻 readline 之前：此时屏幕上还没有输入框，
  内容按顺序直写，不必和行缓冲打交道。
- 判据是**日志里有什么**，不是「用户敲了哪个参数」：全新会话的日志里没有
  `run_started`，`buildReplay` 自然返回空，一个字节都不写。
  这与 ADR-0006「判据是内容不是事件」是同一种思路。
- 思考正文全文落盘会让 `events.jsonl` 明显变大，而 `loadHistory` 每轮都 `readAll()`
  整个日志。这是**明确接受的代价**（对齐 grokbuild：思考文本原样进日志），
  换来的是日志作为唯一真相源的完整性。若将来成为瓶颈，正确的做法是给
  `readAll` 加一个「只读尾部 N 字节」的入口，而不是把思考正文截断后落盘。
- **补记（2026-09-29）**：本 ADR 的重演只装在**启动路径**上。会话内用 `/resume` 中途切换
  会话走的是 `switchSession`（另开一个控制器），**不重演**：切换后新会话的历史照样
  `loadHistory` 喂给模型，屏幕上却没有对应内容——「模型记得、屏幕看不到」在**这条路上**
  仍然成立，与上面 P26 的缺口同型，是刻意留下的范围边界而非 bug。
  不能照抄启动路径那一套：旧对话还在 scrollback 上、擦不掉，直接在其后追加新会话历史
  会变成两段对话首尾相接、中间没有分隔，比什么都不显示更难读。要补它得先定一条
  分隔 / 标题行的设计，作为独立任务做。
