# 会话存储保持 append-only 单文件：读侧有界化，不分片、不建注册表

差距盘点 C1/C3 把「事件日志无界增长」与「list 全量扫」列为下一步，初版方案是照搬上游
桌面版的分片 journal + 稀疏索引 + `sessions/index.json` 注册表（§19/§24，实现于
`journal-segments.mjs` / `session-registry.mjs`）。经 2026-10-06 两路核实后改判：
**布局不变（每会话一个 `events.jsonl`），成本问题全部在读侧解决**（规格：
`docs/design/2026-10-06-会话存储有界化-规格.md`）。与上游构成有意偏差（同 ADR-0009/0023
先例），与 Claude Code 2.1.88 的实践同向。

## 决定

1. **不分片**：`events.jsonl` 一直追加到底。上游分片为双流（events/transcript）+
   HTTP 多会话并行而生；本 CLI 单流单写者，16 MiB 段文件与稀疏索引解决的问题
   （句柄过大、随机定位）在「每轮只读预算尾部」的读侧纪律下不存在。
2. **不建注册表**：`list()` 改读每会话的 `state.json` 封面（投影缓存升级为真读缓存，
   补 `turns` 计数），缺/坏回退全量折算。不引入 `index.json`——它是一份会漂移的
   第二真相源，需要 touch 时机纪律与损坏恢复规则；封面随每次 append 原子重写，
   永远新鲜，坏了自己会说话（回退路径），无需重建仪式。
3. **读侧有界**：新增从尾部按字节块回读的原语；`loadHistory` 只读到预算装满、
   `/retry` 只读最后一轮、打开会话锚点校验后只增量重放。日志大不再是成本，
   预算（ADR-0005）才是唯一的量。
4. **真相源纪律不变**（ADR-0001）：每一轮的历史仍从磁盘日志重新折算，内存不养
   第二份对话账；锚点与封面都是**可回退的快路**，不是信任的替代品。

## Considered Options

- **照搬上游分片 + 注册表**：机制最全，但为零迁移收益引入三个新文件形态（段/索引/manifest）
  与一套 touch/重建纪律；Claude Code 2.1.88 实证单文件 append-only 可用到 GB 级
  （其会话文件无轮转无分块，靠读侧流式裁剪兜底），CLI 场景用不着更重的机器。
- **内存轮次缓存（fold 增量维护 turns，loadHistory 零盘读）**：每轮 O(1) 更快，
  但把对话账从磁盘搬进内存常驻，违背 ADR-0001 的「日志是唯一真相源」精神；
  摘要覆盖数、省略数也会因缓存起点而难保精确。读侧有界化把每轮成本压到
  O(预算)（几百 KB 封顶）后，这点收益不值得换掉纪律。

**后果**：三个小切片（封面化 / 读侧有界 / 打开锚点，合计约三百行）替代原估 600–900 行的
分片改造；存量会话零迁移。若未来出现「单会话日志大到读预算尾部也疼」的真实场景
（数百 MB），再评估分片——那是数据说话的决定，不是提前背的复杂度。
