# `/now` 保留打断式提升：打断当前轮，被提升输入由同一个 drain 接手（裁决 A3）

差距盘点 A3（`docs/research/07-cli-vs-upstream-gap.md`）记了两头规格打架：上游统一行为
规格书 P3 已**退役 abort 式 promote**——「立即」= 安全点优先调度，不打断正在执行的轮次
（§6.2、§15：同一 run id 内切换 active_input_id，旧轮自然收敛后新输入接棒）；本项目
铁律 5 写的却是打断式，实现（`src/agent/run-controller.mjs` 的 `requestPriority`）也是。
ADR-0021 给 Ctrl+S 立「立即提交」时把跟随与否显式挂给了本次裁决（其决定 2）。本条裁决：
**保留打断式**——与上游 P3 构成有意偏差（同 ADR-0009 的先例），不是漏改。

## 决定

1. **`/now` 打断式照旧**：把队首输入提升为活动输入；有活动轮则先打断。打断不是停止：
   队列保留（`stopped` 复位）、临时授权照清（`clearInput`），被打断轮与 /stop 同一条
   abort 路径收敛（`run_interrupted`，现行实现记 `user_stop`——不可 `/retry`，可重试
   判据见 `history.findRetryableTurn`），随后由**同一个 drain** 接手跑被提升的输入，
   绝不启动第二个 Agent。
2. **Ctrl+S 随本条闭合**：ADR-0021 挂起的「届时一并裁决」就此关闭——Ctrl+S 与 `/now`
   共用「提升 + 打断 + 单一 drain」原语（`submitNow`），裁定同语义，不出现两个「立即」。
3. **理由一（画面诚实）**：终端是单一对话面 + 打字机式输出，当前轮的产出正铺在滚动区里。
   「切到新输入、旧轮在后台继续写完」在终端上无处安放——用户看到的画面必须与正在发生的
   事实一致（铁律 2 的精神）；打断让「立即」字面兑现。
4. **理由二（没有对应对物）**：安全点调度依赖上游的 checkpoint 机器与并发轮次模型，
   终端范式是单一 Run 循环（一个 drain + FIFO 队列）。搬安全点要引入整套「旧轮悬置 /
   收敛对账」复杂度，而它保护的东西（不打断长工具调用）在打断式下由用户按键自行承担——
   选择权在用户手里，正合「立即」的本意。
5. **裁决范围**：只裁语义，不裁实现；若未来引入安全点 / 并发轮次机制，本条与铁律 5
   一起重审。

## Considered Options

- **跟上游改安全点切换**：与统一规格书逐字一致，但「后台继续跑完的旧轮」会在滚动区里
  以「终态已出的轮又长出新内容」的面目出现（与铁律 2 冲突），且需整套 checkpoint 复杂度。
- **两态可配（打断 / 安全点切换）**：多一个没人需要的开关。交互面上的模式切换是产品
  语义（权限模式，ADR-0020），不给调度细节留旋钮。

**后果**：A3 的「两头规格打架」就此关掉。上游 P3 的「立即」与 CLI 的「立即」从此是
同名不同义的两个词——读上游规格时以铁律 5 与本条为准。
