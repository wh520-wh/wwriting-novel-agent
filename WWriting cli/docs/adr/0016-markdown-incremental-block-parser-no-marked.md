# 正文 Markdown 用自写的增量块级解析，不引 marked

规格书 §4.10 要求助手正文按 GFM 语义渲染（表格、任务列表、删除线、行内/围栏代码、引用、
标题）；上游的桌面实现用 marked 单一解析器。CLI 的决定相反：在 `src/terminal/markdown.mjs`
自写一个**增量**解析器——能定的立刻吐出去，定不了的（表格候选行、半行）先攒着：
表格按显示宽度自适应（自然宽 → 按列折行 → 行高超过 4 行退化为纵向「表头: 值」），
块级（标题/列表/引用/分隔线/围栏代码/表格）与行内样式都由这一个模块负责。

**Considered Options**

- **引 marked（与上游、Claude Code 同栈）**：被否——正文是**流式写进 scrollback** 的
  （渲染器的既定契约：一行一行落盘、不重排已写出的内容）；marked 面向「拿到整篇
  再渲染」，要么把整条消息攒完再画（丢掉逐行流式感），要么自建重渲染层（与 scrollback
  架构直接冲突）。
- **保持行内样式、块级按原文出**（旧的「轻量 Markdown」）：表格/列表/引用全以裸标记漏出——
  正是本次要修的缺口。
- **自写增量解析器（选中）**：流式契约不动，块级语义按 GFM 子集实现；表格变宽时借
  Claude Code `MarkdownTable` 的三档策略（自然宽/折行/纵向退化），中文按 2 列宽计算。
  已知代价：表格要等分隔行才确认（首行延迟一行）、表格单元格不解析嵌套块、行内样式
  跨折行不自动续（与旧口径一致）。

边界：不支持的（图片、原始 HTML、脚注）按原文降级；`~` 单击不视为删除线（GFM 语义如此），
`~~删~~` 才生效。

后续实施中的三条加固（2026-10-02 评审后）：**先上色、后折行**——折行器认识自己发出的
SGR（宽度按纯文本算、续行重开生效样式），强调跨折行不再把 `**` 漏到屏幕上；行内标记
遵循 flanking 规则（`3 * 4 * 5`、`src/*` 的星号是字面量，未闭合的标记按字面输出，
绝不吞字）；表格单元格按**词**折行（中文逐字断、拉丁词整词搬），且算完列宽做总宽复核，
下限顶穿终端时退纵向——绝不画出会被终端自行折行的超宽行。半行（流式未完成的行）只在
不含任何标记字符时才软折行：带标记的半行等换行再排，宁可晚一拍也不劈开一对标记。
