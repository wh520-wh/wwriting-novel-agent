# 历史回放按字符预算，不引 tokenizer

记录于：2026-10-08｜状态：历史记录｜依据：用户要求充分使用长上下文；现行契约见上游 `docs/design/统一行为规格书.md` §34。字符估算继续使用，但固定 24000 字符上限已取消；窗口内完整保留，接近模型窗口才自动压缩。

以下为原决策：

会话历史回喂模型时，预算按**字符数**算（`DEFAULT_HISTORY_BUDGET_CHARS = 24000`），
从最新一轮往前收，用户输入永不截断，只有单轮就超预算时才裁该轮正文尾部。

**Considered Options**

- **引 tokenizer 做精确计数**（如 tiktoken）：准确，但本项目坚持零第三方运行时依赖
  （只用标准库），且精确计数会与模型自报的 `run_completed.usage` 形成**两个数字**，
  用户不知道该信哪个。
- **字符数估算**（选中）：中文正文约 1 字符 ≈ 1 token 量级，这个量级够用。
  明确记为**估算值**，不与模型自报的 token 数混用。

**Consequences**

- README 里必须写明「这是估算值，不是精确 token 计数」，不许含糊。
- 截断事实对用户可见（`已载入前情：N 轮 · 省略更早 M 轮`），且**只在真的省了东西时才占一行**。
  客观事实必须让人看见——同一条铁律的另一处应用是字数统计：篇幅由 `count_text` 统计后再决定
  补写还是收尾，不靠模型自报。
- 「自报的数」与「本地算的数」在展示层必须可区分，不许混成一个。
