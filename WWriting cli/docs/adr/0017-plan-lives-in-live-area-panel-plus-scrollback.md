# 任务计划在终端 = 实时区常驻面板 / chip + 滚动区全表

上游 §4.2 的形态是「顶栏常驻 chip（任务计划 N/M ▾）+ 折叠下拉」，生命周期是：
plan_updated 到达 → 显示；Run 结束 → 保留供回看；新 Run 的 run_started → 清空（口径 A）。
终端没有顶栏，形态落成两处并存：

1. **滚动区全表**：每次 plan_updated 落一份完整计划表（含三态标记与删除线），
   与 /plan、重演共用同一份排版——这是「回看」的真相面；
2. **实时区（输入框上方）**：运行中展开面板（标题 + 条目窗口，最多 5 条，超出收
   「… 还有 N 步」、完成项收一行汇总）；空闲收成一行 chip `任务计划 N/M · 当前步骤`。
   Run 结束保留 chip（§4.2 的「保留供回看」），新 Run 清空。

三态标记与条目形态与上游 §4.2 同源：实心勾 ✓ / 箭头圆 ▶ / 虚线圆 ◌；完成 = 压暗 + 删除线，
进行中 = 强调色 + 加粗。

**Considered Options**

- **只留滚动区（A1 的现状）**：Run 结束后计划滚出视野，「我们写到哪了」得敲 /plan——
  与「顶栏常驻」的规格差一截，也不满足长篇写作「过程可见」的定位。
- **只做一行状态行**：步骤一多就看不到结构，退化成进度条。
- **独立固定区域（状态栏）**：终端不切 alternate screen（inline 渲染的既定契约），
  没有安全的「固定区域」控制手段；输入区上方（composer 协议）是唯一的常驻面。
- **实时区面板 + chip（选中）**：复用 composer 的多行实时区（它自己量高度、自己擦除），
  与活动行、思考预览共用同一块位置；让位写 scrollback 会把实时区一起擦掉，所以渲染器在
  每次写回后重挂「剩下的实时内容」——面板的持久性靠这一步，不是靠一次 setLive。

已知边界：管道（非 TTY）模式不合成多行实时区（直写流里擦不干净），计划仍落滚动区与 /plan；
退出时输入区连同实时区被拆掉，终止画面只剩滚动区全表——chip 是「在场时」的常驻形态。
