# 技能发现裁剪为三根：内置 / 全局 / 项目，项目可覆盖内置

CLI 需要技能发现机制。上游冻结契约有四层来源（builtin / bundled / global /
project，生效优先级 项目 > 全局 > 随应用分发 > 内置，同名低优先级副本进
shadowed）。CLI 没有 Electron 打包形态，`bundled`（resourcesPath）无从谈起，
裁掉；其余三根照抄，全局根沿用上游的 `~/.wwriting/skills`，项目根为
`<项目根>/skills`。

**Considered Options**

- **只做 内置 + 项目 两根**：更省事，但断掉与上游桌面版的资产互通——用户在
  桌面版装的全局技能在 CLI 里看不见。发现代码本来就按根数组写，两根和三根
  成本几乎一样，没有理由砍。
- **三根照抄（选中）**，含两个有意继承的上游事实：
  - 全局根在 `~/.wwriting/skills` 而**不是** CLI 自己的应用数据根
    （`%APPDATA%/WWriting`，见 workspace-store）：技能是用户资产，跟随上游
    约定才能两边共用；不要因为 CLI 有自己的数据目录就另起炉灶。
  - 项目级优先级最高：用户可以在自己项目里放同名技能覆盖内置/全局版本，
    这是上游「项目 > 全局 > 随应用分发 > 内置」契约的一部分。

**Consequences**

- 用户文件会落进 `~/.wwriting/skills` 与 `<项目根>/skills`，这两条路径从此是
  契约，改动等于迁移用户资产。
- 项目根下的 `skills/` 在创作文件夹里，这**不违反** ADR-0002（私有数据不进
  创作文件夹）：技能是用户主动放置的项目资产，不是应用私有历史。
- v1 不移植 importer / removeSkill / legacy 迁移：装删靠用户直接操作目录；
  ZIP 导入的安全校验链路等出现第二个技能来源时再移植。
