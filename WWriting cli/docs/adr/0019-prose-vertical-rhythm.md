# 正文垂直节奏：致密块矩阵 + 正文→UI 单空行，模型原文空行照旧透传

上游「正文神圣」（衬线、行高 ≥2.0）在终端没有直接等价物——终端没有行距、没有字体，
**垂直节奏就是终端的全部排版**。此前唯一的节奏规则是「模型原文空行 → 一个空行」1:1 透传，
标题、表格、围栏、引用紧贴前文，长文档读起来是一堵密不透风的墙。

落地为两条规则，全部无重绘（正文流纯追加的既定契约不动）：

1. **块间距矩阵**（`markdown.mjs`，决策键 `prevBlock`）：围栏代码、表格、引用、分隔线是
   **致密块**——与相邻块之间自动补一个空行；标题只在**上方**要空行（向下绑定，标题与它
   引出的内容之间不留缝）；段落与列表是 flow，互相之间不补（段落节奏仍由模型原文决定）。
   引用续行（`> a` 换行 `> b`）是同一块的延续，不算边界。判据收口在 `needAir` 一处；
   原文空行透传后 `prevBlock='blank'`，边界空行自然哑火——**绝不与模型自己的排版叠加成双空行**。
2. **正文→UI 单空行**（`renderer.mjs` `sealProseGap`）：上一批落进 scrollback 的是正文时，
   下一条 UI 行（工具行/状态行/决策卡/用户行/重演行）落盘前补一个空行。判据是
   「屏幕上最后一行是谁」的标志位，不是「markdown 缓冲里还剩什么」——正文是边到边写的，
   等 flush 时缓冲多半已空，按缓冲判永远不会触发（第一版就栽在这里）。

**Considered Options**

- **只按模型排版（原状）**：模型输出风格不可控，块贴块的墙靠模型自觉拆——不可验收。
- **段落间也强制空行**：双倍行距，模型自己排的版会出现忽宽忽窄，且与 1:1 透传叠加
  需要一套「吃掉原文空行」的规则，复杂度换不来可读性。
- **CSS 式 margin 折叠（块间取 max 而非各补一行）**：矩阵翻倍，收益为零——终端一行
  空白已经很宽，两个相邻致密块各补一行也只是两行，可接受。
- **致密块矩阵 + sealProseGap（选中）**：一个决策变量、一个判据函数、一个标志位，
  三处收口，测试钉得住。

**有意不做**：不动宽度口径（metrics.mjs）、段首标记 `▌`、用户底色带、h1 样式、表格三档；
不引入任何重绘或行内样式变化。空行永远不超宽、不携带 SGR，对折行器与 NO_COLOR 透明。

已知边界：思考全文（printReasoning）与重演走同一条 sealProseGap 路线，节奏与正文一致；
会话收尾（close）与 clearLive 不补尾空行——终态行之后就是输入框的上框线，那是既有的分隔。
