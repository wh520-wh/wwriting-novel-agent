# Ctrl+S 立即提交：草稿成为下一条活动输入，有活动轮则先打断（终端侧有意偏离上游 P3）

输入层的按键拦截包装（ADR-0020 的 `_ttyWrite` 包法）已经拦下 Shift+Tab；本决定给同一个
包装补上 **Ctrl+S（\x13）= 立即提交当前草稿**。raw 模式下 readline 对 \x13 是静默忽略
（Node v25 实测），所以这个键今天是空闲的——拦截是实现新语义的入口，不是防污染。

## 决定

1. **语义独立定义，不借用「/now 会不会变」的任何未来结论**：Ctrl+S = 提交草稿并使其成为
   **下一条活动输入**；存在活动轮则先打断该轮。细分三态：
   - 空闲且队列空：与回车完全相同（走 `submit` 同一条路）。
   - 忙碌（活动轮或 drain 在跑，判据 = 控制器唯一的 `isBusy()`）：入队 → 提到队首 → 打断
     当前轮 → 同一个 drain 接手，绝不启动第二个 Agent；被取消轮终态「已中断」、不可
     `/retry`，与 `/now` 打断完全同一条 AbortController 路径。
   - **空闲但队列非空（/stop 后残留的常态）**：插到队首并**补启动消费**——按「与回车相同」
     处理会排到保留队列的队尾，违背「立即」的承诺（对抗审查确立的第三态，A2/C2）。
2. **对上游 P3/§15 是有意的终端偏离**：上游已把「立即」退役为安全点优先调度
   （requestPriority 优先切换 active_input_id，abort 式 promote 停用、`interrupt_requested`
   只由停止产生）；本项目铁律 5 的「立即」就是打断语义，`/now` 如此，Ctrl+S 亦然。这是
   终端单 Agent 范式的取舍（见 A3 差距盘点），**不是漏改**。A3（/now 语义裁决）落地时
   Ctrl+S 是否跟随届时一并裁决，本决定不做「自动跟随」承诺。
3. **命令草稿不走立即**：整行以 `/` 开头的草稿按 Ctrl+S 与回车完全相同——命令就地执行、
   按命令自身语义走。菜单（联想菜单开着时必然是命令草稿）与 Ctrl+S 的组合由此自然闭合。
4. **空判先于一切**：`trim()` 后为空的草稿（与回车丢弃闸同源）无操作且不动屏幕——
   纯零宽字符等粘贴残留不得触发一次白打断。
5. **数据面硬要求**：入队（`input_queued`）与提升（`input_promoted`）必须**同一写入任务**
   落 journal——单独写 promoted：对投影的 fold 是空操作、对 promote 原语是抛错（输入不在
   队列），草稿会无声丢失。abort 紧随提升之后，两步之间不得插入可被「当前轮自然完成」
   穿插的等待；错误由命令层既有收口收敛成「提交失败」一条中文事实。
6. **屏幕簿记与回车共用**：输入层把「擦框、越过框沿、回调、重画」收成一份（emitSubmission），
   Ctrl+S 与 line 事件共用；差别只有两处——换行回显自己补（readline 没走 accept 路径）、
   `onSubmit` 带 `immediate` 标记原样上交。不合成回车键重入。
7. **误按代价的取舍**：写作场景里 Ctrl+S 顶着「保存」的肌肉记忆，忙碌时误按 = 打断生成中的
   轮。**不做二次确认**（与 Ctrl+C 同一先例：确认反而挡住急用）；恢复路径 = 终态「已中断」
   可见 + `/retry` 重跑。

## Considered Options

- **跟随上游安全点语义（不打断、仅优先调度）**：与上游对齐，但本项目铁律 5 与 `/now`
  都是打断式，单给 Ctrl+S 一套不打断语义会造出两个「立即」；留待 A3 一起裁。
- **忙碌时只排队**：与回车无差别，快捷键失去存在意义。
- **复用 /now（先入队再提升队首）**：行为等价但把两步暴露给竞态——提升与入队拆开后，
  当前轮可能在两步之间自然完成，promote 落在空队列上抛错。合并为同一写入任务后此路
  与本决定等价，取后者（单一入口、单一事务）。

**有意不做**：不做二次确认；不做运行中的插话提示（发现面 = 头部面板键位行 + README 键盘
一节）；不改 permissions 判定；不持久化任何状态。
