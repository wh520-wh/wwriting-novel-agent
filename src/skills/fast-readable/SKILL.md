# 快节奏易读

只在生成、续写、改写、润色或审核中文小说正文时使用本技能。讨论需求、解释修改、提出问题和汇报工具结果时，保持普通清楚的交流语气。

## 目标

写出信息进入快、冲突到达早、因果关系清楚、段落易扫读的中文网文正文。读者应随时知道人物要什么、眼前阻力是什么、局面为什么改变，并愿意继续读下一段。

## 写法

- 场景尽快进入异常、目标、威胁、机会或冲突，删除不影响局面的寒暄和准备动作。
- 每一段至少完成一件事：增加新信息、推进动作、改变关系、升级代价或制造新问题。
- 优先使用明确动词和具体名词。句子通常偏短，但要穿插必要的中长句，避免整章像电报。
- 对白短而有目的，配合动作、停顿和反应推进攻防；不要让角色轮流朗读设定。
- 爽点来自“压迫或期待建立 → 主角作出有效选择 → 局面发生清楚反转 → 他人和环境给出可信反馈”，不能只靠旁白宣布厉害。
- 解释设定时先让设定影响现场，再补足读者理解当前选择所需的最少信息。
- 章节结尾留下正在发生的新变化、未解决的危险或明确的新目标，不使用与正文无关的强行断句。
- 遵守 `WWRITING.md`、总纲、设定和既有正文；不为了追求速度跳过必要因果。

## 避免

- 同一震惊让多人依次重复；
- 反复使用感叹号、打脸围观和“全场死寂”代替真实反馈；
- 每段只有一句、每句都同样短；
- 用设问句、预告句或作者旁白虚构悬念；
- 为凑字数增加无效路人反应、同义改写和循环争论；
- 在正文中提及节奏、爽点、技能或提示词。

## 交付前静默检查

检查开场是否及时进入事件、每段是否带来变化、冲突升级是否有因果、对白是否可以删短、爽点是否由行动和反馈兑现、结尾是否产生真实后续动力。直接修正文，不输出检查清单，除非用户要求说明。
